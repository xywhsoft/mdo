# 会话列表、详情与已确认操作的读取恢复

隔离构建基线为 `4306f3d`，加本阶段会话前端改动。先用五个失败检查复现：列表 503 立即报错、已确认的保存等待侧栏、详情缺少取消信号、临时详情失败提前报错，以及错误归属的详情被接受。

## 修复

- 列表及选中详情采用统一的六次有界指数退避、抖动、单次八秒超时和共同一分钟期限。临时失败保留已读内容，普通列表刷新合并进行中的请求；耗尽才出现准确提示。列表后台探测保留最终提示，正式重试可立即读取。
- 确认后的模型保存、创建、重命名、分叉、回收/恢复、清空与历史截断立即返回；新侧栏读取取消保存之前的旧快照，不重复写入。已确认导入也直接打开任务，不依赖侧栏当时可用。
- 返回原任务时，队列等待实际详情恢复结束；后台元数据检查不再与该读取并行。已读到远端恢复后，队列恢复不等待侧栏。
- 新选择清除前一任务的详情；响应必须匹配项目和任务。永久拒绝或畸形响应丢弃不可用控件。冷载入输入框不再误提示“恢复到进行中”。
- 侧栏最终提示保留原列表、菜单及焦点；正式重试完成且可见行改变时，焦点回到选中任务。已有历史也能显示最终详情错误，其按钮重试详情而非错误地只重读历史。新增提示覆盖中英俄文。

## 实际打包页面

`manual_session_read_recovery_qa.py` 只在隔离副本加入有界 GET 故障，不模拟模型保存、草稿、队列或模型事件。模型通过标准设置 API 配置为回环测试服务。三次实例总共九次模型请求、四次 profile PUT、零最终模型错误，见 `native-initial.json`、`native-final.json` 和 `native-input-trace.json`。

验证了两次列表失败自动恢复、六次耗尽保留列表、正式立即重试，以及模型已保存时读不到侧栏仍能输入和继续。第一次实例揭示后台详情检查会额外消费故障；补上并发合并后，第二次实例实际达到选中详情六次耗尽，仅出现一处准确提示，缓存历史和输入仍在，正式重试后可续聊。新任务详情的两次失败恢复及正确载入文案、选中范围隔离亦通过。侧栏重试成功后读取 DOM，确认焦点为 `.session-item` 且最终提示已移除。过程见 `browser-observations.json`；各 arm 重置对应故障计数，因此结束快照并不代表全部阶段累计次数。

第三次实例增加仅用于隔离测试的输入事件记录；英文、中文草稿往返没有追加内容，中文消息实际只提交一次。模型切换后请求的 `wire_model` 从 `ornith-1.5-35b` 变为 `session-read-alternate`，回复正常，见 `input-trace.json`、`native-input-trace.json` 及 `continued.png`。这两个模型均由本地测试服务回答，没有访问 ornith 或其他线上模型。

前两次未记录输入事件的自动化中，少量文本出现重复，另有一次非预期短草稿。带记录的复测未复现，尚不能确定来自前端同步、输入法还是浏览器输入工具；不能把输入完整性全场景标记为通过。该现象继续列为最高优先级的后续排查，不加入猜测性的去重补丁。

## 检查与候选

54 项相关 Node 检查通过，含九项会话资源检查、五项元数据并发检查、两项实际提示组件检查，以及任务、审核/询问、草稿、运行序列和焦点回归。三个干净前端合约通过：模块闭包、模型配置的空闲/排队路径、会话版本化写入。

独立 Windows 候选为 `.build/conversation-acceptance/mdo-session-read-final.exe`。复用收据匹配的 `0b7e041` 宿主；八个生产前端文件的实际 HTTP 返回与隔离源码逐字节一致，候选不存在 QA 故障端点，见 `build.json`。输入记录代码也只存在于测试副本，不在生产候选中。其他未提交工作及后续独立平台提交未纳入此隔离候选。

复现：在生成 unity 的干净副本运行夹具，打开打印 URL。通过 `/api/v1/qa-session-arm/list/{2|6}` 后在模型面板切换模型；通过 `/api/v1/qa-session-arm/detail/{2|6}` 后选择另一任务或从设置返回当前任务。耗尽后使用正式“重试读取”。`--trace-input` 可记录隔离页面的合成输入事件与程序恢复赋值；只可用于没有真实私人数据的测试 Home。创建打印的 stop 文件清理，最长十分钟。

没有压力或高负载测试。本阶段没有更新日常程序、手机或官网；安卓真机、系统剪贴板和导出实际落盘仍需继续验证。后台元数据单独读取的挂起取消也需进一步核查。
