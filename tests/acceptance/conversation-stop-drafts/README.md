# 断网停止与首次草稿读取恢复验收

2026-10-08，在独立便携目录中使用 Windows 正式打包工作台实测。
模型只连接本机回环服务，输入均为固定测试文字，没有调用线上或付费模型。

发现并修复两个实际问题：

- 流式回复期间断网后点击停止，原实现丢弃了取消意图。现在记录具体运行的停止意图，
  显示“连接恢复后停止任务”；重连先确认原运行，再按需取消。已确认停止不重复提交，
  服务重启或写入权限改变时停止自动操作，不会取消其他会话的新运行。
- 首次进入新任务时读取草稿失败，输入虽然留在页面，重连也无法保存，刷新后丢失。
  现在恢复读取原版本，保留本地输入及待发送记录，然后保存；读取错误以退避方式恢复，
  不因持续输入变成快速轮询。永久权限错误和另一窗口的版本冲突仍保留明确提示。

实际界面验证：

1. 开始流式输出，断网，点击停止；重连后原运行确实停止。
   完整捕获的请求中，重连取消操作为一次 DELETE。
2. 点击继续任务，回复完成，原草稿保留，没有复制用户消息。
3. 另一轮流式回复期间使用 Ctrl+Enter，原运行停止，优先消息完成。
4. 断网停止后切到新任务，重连仍取消原运行，新任务草稿保持独立。
5. 使用修复草稿读取后的新副本，首次断网进入新任务并输入，重连后刷新。
   `COLD_NEW_TASK_DRAFT` 正确恢复；切回原会话仍显示 `SAVED_SESSION_DRAFT`。
   原生接口确认两个草稿分别保存到项目和会话，均没有未确认提交。

停止验证共 5 次模型请求、23 条事件，其中主动取消 3 次，成功完成 2 次，最终错误事件为零。
首次草稿读取验证没有启动任何模型请求。相关 Node 检查 62 项和前端契约检查 20 项通过，
覆盖停止确认丢失、退避上限、写入权限变化、旧响应、保存版本、待发送记录及迁移。
