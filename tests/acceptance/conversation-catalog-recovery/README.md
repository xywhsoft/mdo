# 冷启动清单读取恢复验收

2026-10-08，Windows 正式打包工作台、独立便携目录及本机回环模型服务。
没有调用线上或付费模型。

基线：首次进入明确的会话 URL 时，用浏览器调试协议丢弃模型与 Agent
清单的成功响应。解除拦截后，本地连接恢复，会话可见，但模型面板仍只有
不可选择的 `conversation-fixture` ID；清单不再读取。截图
`catalog-missing-before.jpg` 保存了该状态，基线没有启动模型请求。

修复后：

1. 同时暂挂两个清单响应，触发客户端请求超时。解除拦截后，无需刷新，
   模型名和可选清单自动恢复，编辑中的 `COLD_CATALOG_RECOVERY` 留在输入框。
2. 另一次刷新中，实际丢弃 Agent 清单的一条 200 响应，立即清除拦截。
   清单自动恢复，模型面板可操作；`catalog-restored.jpg` 显示恢复结果。
3. 关闭面板，按 Enter 发送草稿。只有一次模型请求、一条用户消息，运行
   成功且最终错误事件为零。见 `catalog-conversation-completed.jpg`。

模型、Agent、项目的只读清单使用明确启用的恢复策略：保留旧数据，后台
指数退避加抖动；最多六次请求、共用一分钟期限，每次请求最多八秒。
初次失败即释放启动等待，不用整个恢复过程挡住工作台。清单首次未确认时
输入仍可编辑，发送等待清单恢复；只有重试耗尽或永久拒绝才显示错误。
新的刷新、重置或权威数据更新会取消旧恢复，过期响应不能覆盖新清单。
切回前台或重连时只重新读取已耗尽的暂时失败，不扰动正常清单或永久权限错误。
普通资源存储和包含写入的设置操作没有启用这个重试策略。

40 项相关 Node 回归和 20 项前端契约检查通过；138 个前端模块解析和
引用可达检查通过。新检查覆盖首次加载、保留旧清单、六次退避、实际请求
取消及共用期限、永久拒绝、旧响应、重置、显式刷新和真实 API 的选择性恢复。

独立测试宿主已停止，网络拦截已清除。没有压力或高负载测试，也没有官网
发布。Android 的真机应用切换、休眠及软键盘行为仍需单独验证。
