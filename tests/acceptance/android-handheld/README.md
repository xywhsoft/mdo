2026-10-10。使用独立 `org.xleaves.mdo.qa.stability` 包，保留手机日用版及其数据。应用源码为 `630556a0dcb180ead6a2323ddc489aae8073c0ff`，安装后的 APK SHA-256 与既有构建候选一致。此验收不覆盖工作区后续未提交的改动。

设备为 RMX5090、Android 16 / API 36、arm64-v8a，系统 WebView 为 `com.google.android.webview` 138.0.7204.179。模型对端使用有界本地模拟服务；运行的是手机实际 APK、ARM64 C/TCC 宿主及正式设置、会话和恢复接口，不是电脑浏览器模拟移动端。

## 对话恢复

运行 [原生对话夹具](../../test_android_conversation_runtime.py)，模型响应错误属于主动注入的测试条件，没有访问生产账号或模型服务。结果见 [接口及请求记录](runtime.json)：

| 场景 | 结果 |
| --- | --- |
| 临时 429，两次失败 | 第三次成功，等待约 1.06 秒、2.33 秒，没有中途错误事件 |
| 响应前断线 | 第二次成功，没有中途错误事件 |
| 流中途断线 | 第二次完成，成功会话没有错误事件 |
| 每日额度用尽 | 仅一次请求、一次最终错误，分类为 `daily_token_limit` |
| 退避期间取消 | 约 112 ms 进入 cancelled，取消后没有继续重试 |
| 明确恢复和继续 | 原输入恢复成功，恢复标志清除，可继续下一轮 |
| 结束进程后启动 | 草稿和安全存储中的测试凭据保留，可继续对话 |

## 手机原生 WebView 操作

通过 ADB 截取实际屏幕，并按观察到的控件执行 Android 触摸/按键操作，未使用 DOM 注入、虚拟剪贴板或代理保存接口。

- 点击回复复制，再在主输入框通过系统“全选、粘贴”菜单粘贴，原文 `ANDROID_OK: after-restart` 完整一致，见 [系统粘贴](clipboard-pasted.png)。点击手机发送按钮后模型只收到一次相同输入，回复正常。
- 在当前中文九键输入法实际点击按键、选择“你”候选。候选选择没有误发，见 [候选确认](ime-committed.png)；随后按软键盘 Enter 按现有规则发送“你”，模型只收到一次输入。此测试没有验证三语言剪贴板或软键盘多行换行；现有规则仍为 Enter 发送、Shift+Enter 换行。
- 点击会话导出，经过手机系统保存界面进入专用 `Download/mdo-stability-qa-20261010` 目录并保存 Markdown，见 [保存位置](markdown-save-picker.png)。实际文件为 993 字节，读回包含所有完成的合成用户输入和回答，没有失败流草稿。
- 从会话菜单导出 JSON 备份，经过同一系统保存流程，见 [备份保存](backup-save-ready.png)。实际文件为 49,147 字节；逐项 Base64 解码验证 7 个文件的长度、SHA-256，均一致，合成会话 45 条 UI 事件没有 error。原样文件在 [exports](exports)，摘要见 [原生验收结果](native-ui.json)。

系统文件管理器将默认备份文件名截为 50 字符，保留 `.json` 后缀；内容完整，不据此声称已完成导入恢复。备份 `restore_ready=false` 是导出格式中的状态，本轮只完成实际保存和字节校验，未通过手机导入器验证可恢复性。保存时文件曾短暂为 0 字节，随后后台写入完成；最终读回的是完整 JSON。

夹具按预设 30 分钟时限正常结束，并清理自身的端口转发和模型对端。运行后补充的 HTTP 读取遇到连接拒绝，是夹具已结束，不是产品故障。运行及手机 UI 共 14 次有界模型请求，没有压力或高负载测试。
