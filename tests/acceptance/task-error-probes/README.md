# 耗尽读取后的安静后台探测

基线 `6e015b9`。普通轮询在任务读取六次耗尽后再次调用 `load()`，重新清除最终提示并启动完整退避周期；持续故障会让载入状态和最终错误反复切换。新的可控时钟检查先复现了重复开启读取、后台探测清除错误、再次六次重试等问题。

## 改动

- 纯读取增加后台模式。首次载入仍使用原有六次尝试、共同一分钟期限、单次最多八秒的退避；耗尽之后，每 30 秒最多做一次探测，期间保留最终提示及已有数据，不开始新的完整退避周期。成功读取后才清除提示。
- 正在探测或退避的读取由实际待处理标记合并，不再仅根据可见状态判断。页面隐藏取消请求，页面缓存返回继续原来的安静读取；切换上下文或收到权威数据会取消旧请求和等待。
- 任务列表和详情的轮询/实时刷新使用后台模式。正式“重试读取”、打开面板、选择任务以及已接受回答后的确认使用立即读取；不会重放工具、回答或停止写入。
- 任务回答已经被接受后，详情/列表读失败由各自面板显示准确的最终提示，不再另弹“回答刷新失败”错误。回答锁定状态继续保留。
- 权限拒绝等永久原因仍不进入指数重试；周期性复查保留准确提示，并受到同样的频率限制。普通设置写入和其他默认资源存储策略不变。

## 完整打包页面

使用 `manual_task_read_recovery_qa.py` 的隔离原生实例、正常模型和 `spawn`，启动实际等待输入的 Python 子进程。接缝只令询问 GET 返回 503，不改变写入、原生任务或会话事件。

自动恢复实例故障上限为 12，实际消耗八次：首次六次，随后两次独立后台探测。`native-exhausted*.json` 记录七次失败，`native-later*.json` 记录八次失败；两次页面观察间隔约 55 秒，始终为同一条准确最终提示，输入保留，无错误 toast。关闭故障后未点击重试，正式页面自动恢复真实输出，再发送保留输入得到正常回复。`automatic-runs.json` 记录一次 DELETE、三次回环模型请求、零最终模型错误。没有为了恢复再创建任务。

独立手动实例仅令六次询问读取失败。`manual-before.json` 记录正式“重试读取”按钮，约 17 秒后点击该按钮；这个时间仍处于 30 秒后台等待内，页面立即恢复真实输出，输入保留。`manual-runs.json` 记录一次 DELETE、两次回环模型请求、零最终模型错误。两个实例合计五次模型请求，均为有界功能验证。
