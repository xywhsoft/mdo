# 中断结束确认的运行锁取消

基线 `7a0bccd`。`runRecoveryAction` 的默认结束确认适配器把 AbortSignal 传给 HTTP 请求，却没有传给 `withSessionRuntime`。外层有界等待虽已超时或因页面退出取消，内层仍可能占住运行锁；如果确认原先排在另一个操作之后，取消后仍可能在前驱结束时发出多余的读取。

修复只补齐该适配器的运行锁选项传递，沿用既有取消机制：正在读取时释放当前等待，排队时取消该等待但保留前驱的顺序。结束写入仍只提交一次，确认只读，不重放模型或工具调用。

新增三项检查调用真实的默认适配器和 API 客户端，模拟传输不响应取消。第一项让首次确认挂起，八秒超时后新的读取在 500 ms 退避后成功，原会话运行锁可继续使用；第二项验证页面退出立即释放锁且迟到数据不会应用；第三项验证排队确认取消后不在前驱结束时产生多余 GET。

修复前已有八项通过，新增三项全部失败：完整确认耗尽、退出后后继进不去、取消后仍发出一次 GET。修复后相关恢复动作、运行序列、恢复读取和决策共 45 项 Node 检查通过。

```powershell
node --test tests/test_recovery_action.mjs tests/test_frontend_session_runtime.mjs tests/test_runtime_read_recovery.mjs tests/test_recovery_decisions.mjs
```
