# 搜索恢复的真实打包页面验收

2026-10-09。实现提交 `f1077208`（恢复卡片和提示）、`89077509`（Markdown
产物读取），锁定 xs `9a0f5f6f` / xwork `90e4dc0f`。使用干净源码构建隔离
Windows 候选，并用真实浏览器操作正式页面。未做压力或高负载测试。

本次实际发现并修复：

- 程序重启后继续同一次未完成搜索，页面显示一张“已停止”和另一张“完成”
  卡片，另有空的停止回复。现在显式恢复时沿用原卡片，只移除这类没有内容的
  停止占位；部分回复和实际失败仍保留。匹配需要保留的原用户输入、轮次、
  工具名、调用编号及完整且相同的参数。缺失/截断历史、子 Agent、新用户
  回合、已完成或已失败调用均不冒认同一次调用。显示修改不改变原生事件账本。
- xwork 的固定恢复说明以英文内部文字显示。现在跟随中文、英文和俄文
  界面，保留自定义说明原文。
- 搜索产物已经写入 `.md` 文件，但会话产物接口只接受 `.txt`，导致预览
  返回 404。现在接受 xwork 实际生成的两种后缀，继续核对运行编号、产物
  编号和文件名，把路径绑定到当前 Home；Markdown 返回正确媒体类型。

`manual_search_recovery_qa.py` 复制正式 app 到独立目录后打包，只在测试生成
入口中指定回环账号服务并注入一次性的本地 JWT。模型以真实 HTTP 协议返回
固定工具调用；mdo 实际运行模型管理、xwork、工具、会话、HTTP/WS 和页面。
搜索经过故障代理进入 home 仓库的统一网站插件、JWT 和 SQLite 额度事务。
平台 HTTP 响应为本地夹具，不访问公网搜索或真实付费模型。日额度拒绝由
代理注入 `daily_limit`，用于验证客户端分类，不能冒称再次验证真实线上额度。

跨进程操作。页面最终没有错误卡及未结束的工具卡。

打开打印的 `url`，依次输入 `search-retry`、`search-lost`、`search-quota`、
`continue`；打开 `restart_url` 发送 `search-restart`，等 `proof.json` 的
`holding` 为 true 后创建打印的 `restart_marker`，再用页面入口重新连接并
继续任务。核对结果、预览和续聊后创建 `stop_marker`，夹具会保存事件并关闭
自己拥有的两个服务；最长十分钟，处于一次性 JWT 的有效期内。
`node tests/acceptance/search-ui-recovery/check.mjs` 可重核本次保存的证据，
不是重新调用线上平台或运行一次新的浏览器验收。
