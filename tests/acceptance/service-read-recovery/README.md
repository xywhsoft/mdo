# 服务状态读取恢复与准确提示

基线 `78dec578`。两个隔离 Windows 候选仅包含本阶段的四个前端生产模块及三种语言各四条文案，使用锁定的 `7e4eb8a090ca` 宿主；未混入主工作区的分发、通知及 Android 修改。构建摘要、八个实际包内文件的逐字节校验见 `read-build.json`、`final-build.json` 和两个 served-source 记录。

## 修复

原服务状态读取失败一次就暂停所有写入，连输入框也禁用，并误显示“项目清除请求需要核对”。冷启动还等待这个读取，失去确认后不会自行恢复，保存会话位置则再弹一次无关错误。仅有 AbortController 的超时不能结束忽略 abort 的请求。

现在状态读取使用统一安静退避：每次最多八秒，最多六次尝试，共享一分钟期限；最终短暂失败后间隔三十秒继续只读核对，连接恢复和返回页面也可恢复。忽略取消的请求或正文仍有期限，页面离开取消旧读取，迟到回复不能解锁。返回先等待旧取消完成，再启用新的读取。

界面区分普通连接检查和已经证实的清除/重启。连接检查期间保留对话和输入，允许编辑，保存与发送等待确认；临时失败不弹逐次错误，耗尽后才出现准确连接提示。冷启动的只读界面不再等待整段退避。最后选中的会话在状态确认后保存，期间切换只保存最新目的地。

真正的清除请求和已验证的重启围栏仍需原有确认。所有清除/取消/确认写入保持单次提交；响应丢失只读核对原请求，不自动重放。挂起的取消写入最多等待八秒，仍保留原请求编号。原有清除执行、丢失确认、草稿保护及重启检查全部通过。

## 真实打包页

`manual_service_read_qa.py` 使用隔离 Home、回环模型和真实 HTTP/WebSocket 转发。暂扣或有限次失败只作用于服务状态 GET，写入和模型运行仍由实际打包程序处理。外层 HTML 只观察 DOM；focus 和 pagehide/pageshow 是明确标注的合成事件。

- 基线：首次 200 的正文暂扣十二秒；八秒后输入框禁用，显示无关的清除核对提示，又弹出无法保存上次会话。见 `baseline.png` 和基线只读请求记录。
- 冷启动：修复版在正文未返回时已经打开会话，能把输入改为“网络恢复后继续这段输入”；发送仍禁用。八秒请求截止后自动重读成功，输入不变，没有错误 toast。
- 两次 503：实际读取为 `503, 503, 200`，约 1.7 秒恢复，全程无错误 toast。
- 六次 503：前六次读取安静退避；耗尽才显示“暂时无法核对服务状态”，输入仍可编辑。第一次通过打开连接面板触发新的只读核对恢复；第二次不点击，最后一次失败后 30.015 秒自动读成功并恢复发送。之后两轮模型各执行一次，队列正常清空。
- 最终候选：慢读时实际可见面板只有“检查服务连接”的说明和检查状态，没有清除确认控件；核对成功自动关闭。模拟挂起读取中立刻离开/返回，旧读取消、新读成功、草稿保留，随后正常发送。
- 直接工作台：服务在线时刷新，恢复历史并再发送一轮。刷新前启用异常监听，所测刷新与续聊期间没有未捕获异常，没有错误 toast。两种候选共四次模型请求，零最终模型错误。

最终夹具的合成非 persisted pagehide 会触发设备传输的停止逻辑，随后使用 HTTP 回退；不能据此声明原生窗口返回或 WebSocket 重连验证通过。真实 BFCache 返回在设备传输模块中触发重新载入，可信生命周期和输入法仍待进一步检查。

直接工作台后续观察到了未在本轮操作中输入的文字，其来源没有证实。未发送、未清除，原草稿保留在隔离 Home；仓库证据只记录长度和哈希，并省略包含该输入的截图。没有凭此做去重或覆盖输入。首次语言初始化在状态围栏关闭时仍有控制台保存警告，也保留为后续排查项；本轮没有把它算作解决。

## 复现与范围

```powershell
python -X utf8 tests/manual_service_read_qa.py --packed <候选 mdo.exe> --directory <全新隔离目录>
```

打开打印的 QA URL，按钮分别暂扣冷启动状态正文、失败两次或六次、模拟页面返回。创建打印的 stop 文件收集请求/模型/草稿证据并关闭自己的程序，夹具最长十分钟。Node 检查不等待实际退避时间，使用可控时钟验证期限及取消。
