# 明确拒绝后的队列恢复

2026-10-11。原生 xs/TCC 的干净 Windows 打包版、正式草稿/附件/队列/运行 API，
通过实际浏览器页面点击发送、队列重试和续聊。模型对端是有界本地模拟服务；
没有浏览器 fetch 替换、响应代理、生产账号或压力/高负载测试。

## 发现与修复

模型配置允许附件，但漏配 media-input 时，真实运行入口返回
`422 image_model_unsupported`。旧页面把发送前的队列状态保留为 sending，显示
“发送状态待确认”“可能已被服务端接收”，尽管没有运行、模型调用和对话事件。
模型列表刷新还会依据附件开关清掉准确的图片拒绝提示。
见 [旧页面](baseline.png)、[原生记录](baseline.json)。

436311ea 在启动返回后识别已审查的运行前校验拒绝，保留原错误代码；只接受明确的
422 与已知代码组合。页面重读队列，确认原编号没有 run_id、start_claimed 后，
通过已有的有界写入确认入口退回 pending。队列、图片和发送时固定的配置都保留，
自动派发仍被阻止，等待用户明确重试。未知错误、响应丢失和已经认领的任务仍按
原规则核查结果，不能据 HTTP 状态猜测可重复执行。

ec91433f 保留这类队列图片拒绝的准确提示，避免模型列表刷新误清除。
图片能力校验及模型配置规则本身没有改变。
