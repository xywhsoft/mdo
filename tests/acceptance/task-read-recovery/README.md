# 后台任务读取的安静恢复

本阶段在完整打包页面、真实 WebSocket 和实际原生任务上验证，使用普通设置 API 添加回环模型。模型通过 `spawn` 启动一个等待标准输入的 Python 进程；测试没有伪造任务 DTO、工具执行或会话事件。

## 复现与修复

旧源码在停止已经成功后，首次任务列表 GET 返回 503，立即用内部错误文本替换整个列表。`baseline.jpg` 和 `baseline.json` 同时记录了页面错误和原生任务已取消的事实。

任务列表与详情现在采用有界纯读取恢复：最多六次尝试、共同一分钟期限、每次最多八秒，等待从 500 ms 指数增长并带少量随机抖动。恢复中保留最后的列表、输出和输入，不产生中途读取错误。详情四个并行 GET 共用同一次尝试的取消信号；一个失败后，其余未完成读取被取消，输出仅在整批成功后追加。

轮询和 WebSocket 刷新共用正在进行的任务读取，避免频繁刷新重置退避。离开页面取消请求和等待；浏览器从页面缓存返回时恢复未完成的读取。永久权限拒绝不重试，也不以旧数据遮盖拒绝。

恢复耗尽且已有数据时，只显示“暂时无法更新，以下显示上次读取的任务信息。”，保留任务卡并提供“重试读取”。详情也保留输出并提供同样的明确重试入口。任务创建、工具执行和其他写操作不因此重放。

## 完整页面结果

- 两次 503：停止请求一次；恢复中显示真实的“正在停止…”，随后显示“已停止”，列表未被错误替换。切换到另一会话再切回，未发送输入仍在。真正重启测试实例后，通过正式重连/重新载入入口保留草稿与历史，继续对话成功。
- 六次 503：停止请求一次；退避期间没有读取错误。耗尽后仅一条最终提示，任务卡和输入保留。随后常规刷新恢复终态。
- 六次 503 后手动读取：点击正式“重试读取”按钮恢复“已停止”，提示消失，输入保留，没有再发送停止请求。

`recovered-native.json`、`exhausted-native.json` 和 `manual-native.json` 记录失败次数及 DELETE 次数；各 `*-browser.json` 和截图记录真实页面内容。三个验收实例的普通模型请求分别为 3、2、2 次，零最终模型错误；只有第一个实例重启并继续了一次。

## 有界检查

45 项任务、读取恢复、页面生命周期及停止确认 Node 检查通过；33 项设置/草稿恢复检查通过。详情恢复验证输出 `A` 后读取失败、重试后仅追加 `B` 一次，以及同批挂起请求取消、清除选择取消重试、403 不重试。通用恢复检查包含六次耗尽只发布一次错误、共享一分钟截止时间和页面缓存返回。

干净基线的模块图、任务详情及设置保存三个前端合约通过。另一个旧静态合约仍要求 `renderMarkdown(item.text)`，当前源码使用 `body.append(renderMarkdown(text))`，因此该断言失败；根工作区另有修正，本阶段未纳入其未提交修改。

候选程序和七个实际 HTTP 返回的前端文件哈希见 `build.json`。仅前端与测试变更，宿主按现有版本/裁剪配置收据复用。没有压力或高负载测试，没有安卓真机检查，也没有替换日常程序或官网安装包。

## 重现方法

从本阶段源码生成 unity，并使用匹配依赖/裁剪配置的 xsw：

```powershell
python tools/build_mdo.py --xserver-root <匹配的-xs-源码> --prepare-only
python tests/manual_task_read_recovery_qa.py --host <匹配的-xsw.exe> --directory <新的隔离目录>
# 耗尽检查加 --failures 6。
```

打开脚本打印的 URL，保留输入并打开任务详情；GET 打印端口的 `/api/v1/qa-task-arm`，再点击任务停止。该测试专用服务端接缝仅令接下来的任务列表 GET 返回 503，普通写入和 WebSocket 不经过代理。GET `/api/v1/qa-task-proof` 查看次数。创建打印的 `restart_file` 重启一次，创建 `stop_file` 结束并清理进程；整个实例最长六分钟。

这两个测试端点只注入隔离 app 副本，不进入产品候选程序。
