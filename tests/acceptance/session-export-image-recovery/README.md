# 图片 Markdown 导出的安静恢复与等待期限

基线为 `f58bf2f2`，独立候选仅修改图片导出模块，兼容宿主仍锁定 `3232f7b8efb0`。实际包中两个生产模块与干净验收工作树逐字节一致；见 `build.json` 和 `served-source.json`。

## 问题及修复

原实现遇到一次 503 就丢弃图片；定时器只通知 abort，没有结束自己的等待，忽略取消的 fetch、响应流或取消回调能让导出一直挂起。现在元数据、图片正文和退避等待共用原有 30 秒总期限，短暂故障最多六次尝试，失败正文及时释放。预算按每张图片预留一次；错误身份、文件名、MIME、大小或短读仍不接受。离开页面取消操作，迟到响应不能补入已经结束的导出。

七项新增检查在原源全部失败、修复后全部通过。27 项相关 Node 检查及干净工作树的两个前端合约通过。测试覆盖 503、fetch/正文断连、不响应 abort 的请求及 reader、挂起 cancel、页面离开、迟到响应和图片预算。

## 实际打包页验证

独立 Home、回环模型和 68 字节公开测试 PNG，实际 HTTP/TCC 生成图片会话。使用工作台正式 Markdown 导出按钮；外层只观察其 Blob，保留原下载动作。

- 图片信息连续两次 503：三次元数据 GET、一次正文 GET，安静恢复，导出包含一张原图。
- 图片正文连续两次 503：一次元数据 GET、三次正文 GET，安静恢复，原图 SHA-256 与上传原件一致。
- 正文暂扣 35 秒：导出约 30.01 秒结束，保留文字和图片 ID，并明确标注图片未包含；五秒后到达的正文不能改变已交接的 Blob。
- 导出超时后正常续聊：第二轮用户输入准确，无图片重复，两个回环模型请求均成功，零最终模型错误。

`browser.json` 记录三个实际导出 Blob 的摘要和图片哈希；`proof.json` 为服务器请求、原始模型输入及会话事件。耗时使用验收结束后采样的 Unix/单调时钟偏移进行对齐，因此为近似值。slow 阶段后两次 GET 属于异常来源排查时刷新 iframe 的缩略图读取，不是第三次导出的重试。

外层 iframe 页面出现一条 MutationObserver 异常。CDP 栈定位到无 URL 的浏览器注入脚本，调用链包含 Electron sandbox；源码片段为压缩束，与 mdo 无打包器的模块不符。记录完整堆栈及片段，未将它计入产品脚本错误。直接打开原生服务提供的工作台、刷新并续聊，CDP 和控制台无异常，见 `native-browser.json`。

## 复现与范围

```powershell
python -X utf8 tests/manual_session_export_recovery_qa.py --packed <候选 mdo.exe> --directory <全新隔离目录>
```

等待打印的会话载入，再通过回环 `GET /__qa/arm/meta`、`/binary` 或 `/slow` 注入对应故障，点击正式导出按钮。`GET /__qa/idle` 停止新故障，创建打印的 stop 文件收集证据并关闭自己的程序。全部验收进程及临时页已关闭。

本阶段仅修复图片读取。文字导出和长消息复制的等待路径仍需审查；实际下载落盘、系统剪贴板、Android WebView 和可信输入法也未据此验收。没有压力测试，没有覆盖日用程序、手机或官网安装包。
