# 任务停止确认恢复

2026-10-08，Windows 独立候选打包版与正式任务面板的有界功能验收。
测试在回环地址创建三个独立会话，由普通模型调用 `spawn` 创建三个空闲子进程；
未使用线上账号、真实 Key、压力或高负载。

## 行为与证据

- 基线：服务端停止成功但 DELETE 响应丢失时，`cancelTask` 抛出 `network_error`。
  新增集成测试先在基线失败，修复后通过。
- 丢失确认：只提交一次停止，通过一次原任务读取确认；界面正常显示已停止。
- 请求未送达：第一次 DELETE 在代理层返回 503；读取同一活动任务后重新停止。
  两次 HTTP 请求、一次实际服务端停止，界面没有中途错误。
- 确认耗尽：服务端已停止，DELETE 响应体丢失，后续五次任务详情读取失败。
  只提交一次停止；等待结束仅出现一条“暂时无法确认”提示。
- 连续两次点击：测试按钮同步点击正式停止控件两次。
  等待期间 `aria-disabled=true`，焦点保留，没有额外停止请求；最终控件恢复可操作。
- 原生核对：三个任务最终均为 `cancelled`、`terminal=true`。
  每个会话各两次模型调用，总共六次，最终模型错误事件为零。

[`acceptance.json`](acceptance.json) 保存 UI 提示、等待状态和原生核对计数；
[`confirmed.png`](confirmed.png) 与 [`unconfirmed.png`](unconfirmed.png) 保存实际页面。
回环代理在接收响应头后截断响应体，避免浏览器自动重发无响应头的幂等 DELETE
干扰应用层恢复计数；没有重放任务创建或工具执行。

## 实现边界

停止确认最多六次操作、共享一分钟总时限、单次请求最多八秒，使用带抖动的指数退避。
模糊结果先读取，再决定是否重复同一任务的幂等停止；详情不可读时不重发停止。
任务 ID、不可变归属、设备/宿主代次和写入令牌必须保持一致。
明确拒绝直接保留准确原因，离开页面取消请求及等待，不弹出取消错误。

该验收使用正式任务组件、正式模块和真实原生 API；代理页面没有启动完整主页面的
WebSocket/后台刷新。因此它不代表完整主页面的并发任务快照或 Android 真机已验收。

- 42 项 Node 检查：停止、所有权、任务问答/详情、恢复确认和多语言最终错误。
- 四项干净工作树前端合约：模块图、任务面板、运行控件及显式恢复。
  旧合约中的资源模块位置和 `renderMarkdown` 精确字符串断言已经过期，其他工作区
  的修正没有混入本提交，也没有宣称干净基线的完整合约通过。
- 新候选完成执行中断/重启队列回归和三种摘要最终失败回归；前者零最终错误，
  后者覆盖质量耗尽、准确额度错误和十秒退避的立即取消。
- 25 项原生模型重试/错误分类/时限/流式恢复检查通过。

`build.json` 记录构建源码、兼容 xs、当前宿主裁剪配置及候选哈希。
完整当前提交的宿主配置新增了已提交的 LAN 和 P256 能力，旧候选宿主的配置不一致；
因此本次重新编译宿主，没有沿用较早窄基线的二进制。

复现入口：

```powershell
node --test tests/test_task_stop_action.mjs tests/test_task_cancellation.mjs
python tests/manual_task_stop_recovery_qa.py --packed .build/conversation-acceptance/mdo-task-stop-final.exe --directory .build/conversation-acceptance/task-stop-ui-fresh
```

访问打印的本地地址，依次停止任务 1、2，再点击“停止确认耗尽（重复点击）”，
等待最终提示并查看验证记录。创建打印的 `stop_file` 可退出夹具并清理其子进程。
