# 图片等待期限与 API 取消

基线 `a44037e`。图片恢复原有单次 30 秒和总计 90 秒的限制，但计时器只 abort 后仍等待操作；正文或适配器不响应取消时，编辑器可一直等待。公共 API 也会保留该请求的写入计数，迟到的错误或启动令牌仍可能影响已经取消的操作。

图片传输现在复用统一 request-recovery 自行结束等待，保留原 30/90 秒期限、六次上限、指数退避及稳定图片 ID。上传结果未知时先查询同一图片，明确不存在才允许重试同一 PUT，不回退不确定的 POST。文件、名称或身份冲突，以及存储额度、写入围栏等永久错误不重试。正常响应刚好在导航之后返回时，仍保留原组件的清理路径；没有改动草稿归属。

公共 JSON 请求、图片上传和备份二进制块在提供 AbortSignal 时自行结束等待并释放客户端写入计数。迟到的正文和 fetch 拒绝先检查原信号，不能更新写入令牌、触发旧写入冲突提示或网络反馈。取消不代表服务器没有执行，原有结果查询和写入围栏继续负责确认；没有为普通写入增加重试。

## 实际原生服务与生产适配器

隔离树先恢复锁定依赖并生成 unity 源，再运行测试：

```powershell
python tools/build_mdo.py --xserver-root D:/GIT/mdo/.build/linux-xs --skip-host-build --output D:/GIT/mdo/.build/conversation-acceptance/image-upload-deadline-package/mdo.exe
python tests/test_image_upload_identity_runtime.py --host .build/host/xsw.exe --frontend-evidence D:/GIT/mdo/tests/acceptance/image-upload-deadline/native-image.json
```

正式生产 JS 向实际回环原生服务上传一个普通 PNG。服务返回 201、文件已保存，测试适配器故意让该响应的 JSON 正文永久等待。正式恢复器在原期限内取消旧等待，退避后 GET 同一图片元数据；实测正文到确认间隔 31,107 ms。只有一次 PUT、一次确认 GET、一份原件及元数据，原件字节相同，没有模型运行和网络错误通知。确认前后的公共写入计数均已释放；迟到旧正文不能改变结果。记录见 `native-image.json`。

原有原生身份检查同时覆盖内容/名称冲突、不同会话的同 ID、两次同 ID 的幂等处理、16 张小图片的功能边界和重启后确认；不进行吞吐或负载测试。

因为改动公共 API，再运行实际 HTTP/TLS 备份导入回归：丢失一次还原确认、一个正文挂起及两次 503 后恢复。每种协议均只执行一次还原、没有观察错误；源会话和历史/产物/草稿/队列不变，结果身份一致，见 `backup-regression.json`。TLS 夹具仅对自有回环证书沿用关闭 Node 验证的测试方式，不证明生产证书信任配置。
