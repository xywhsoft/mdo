# 启动会话位置的读取与保存恢复

旧实现首次读上次位置失败就报错、换到列表任务；读取已保存任务的详情失败则静默换任务。自动回退还会把未知的原选择覆盖为列表任务。位置 PUT 没有等待上限，回复丢失也不能核对已经完成的保存。

现在位置与详情读取共享公共恢复器的八秒请求、一分钟总预算和六次尝试；短暂错误安静退避，只有真正耗尽才提示。显式路线和更新的用户操作优先，删除的任务正常回退。读取不可靠时自动回退只显示可用任务，不保存替代位置；实际改变任务的用户导航仍正常保存。PUT 每次选择只执行一次，不确定回复通过有限 GET 确认，不盲目重放。确认失败的同一选择不会被可写状态通知反复提交，提示也准确说明当前对话不受影响。页面离开取消观察和订阅。

候选基于干净的 `2ea853c5` 工作树，仅加入本阶段生产模块及三种语言的新提示。Windows 紧凑宿主由锁定的 xs `a57d24e9` 新编译，未使用旧宿主，不包含同期其他任务的未提交改动。候选位于 `.build/conversation-acceptance/workspace-startup/package/mdo.exe`；匹配的宿主及完整收据保存在同级 `host` 目录。`build.json` 是去除符号长表的构建收据，四份实际服务源码的哈希与隔离源逐字节核对。

验收结果：

- 最初 11 项复现检查在基线 9 项失败、2 项通过；之后另加 3 项边界检查。修复后 52 项相关 Node 检查与两个干净前端契约全部通过。
- 真实打包程序和 HTTP/WS 页面完成七类有界故障。上次位置、上次详情分别两次 503 后恢复原任务，零位置 PUT。六次位置读取失败仅一条最终提示，原生保存位置仍是原任务，没有自动覆盖。
- 保存真实成功但丢失回复时，仅一个 PUT、两次确认读取 503 后成功。保存正文暂扣 12 秒时，约 9.72 秒通过第三次 GET 确认，未等旧正文、没有额外提示。
- 保存确认连续六次失败只显示一条“尚无法确认”提示。实际对话正常继续，焦点和可写状态变化没有重复 PUT。
- 启动读取正文暂扣 12 秒时，用户选择新任务并填写草稿，迟到结果不能换回任务。原生项目草稿保持 `STARTUP_USER_CHOICE_DRAFT`，上次保存位置保持原任务。
- 重启相同隔离 Home 后从首页恢复原任务与草稿；用户真正切到另一任务，原生位置随之更新。续聊成功，再从首页打开恢复该选择和全部三轮历史。原任务草稿及新任务项目草稿均未变化。总共三次模型调用、三条逐字核对的输入、零最终模型错误；重启验收浏览器警告/错误为空。

`native-snapshots.json` 保留只读查询的真实阶段快照；`browser.json` 保留页面观察，errors 数组为跨阶段累计记录，并非每次观察产生新错误。`restart.json` 记录进程重启前后原生数据，三个 DOM 文件和 `continued.png` 展示正常恢复和续聊。`checks.json` 由原始记录断言生成。

复现入口：`python -X utf8 tests/manual_workspace_startup_recovery_qa.py --packed <候选 mdo.exe> --directory <新的隔离目录>`。打开打印的验收地址，依次选择七种故障。写入类使用另一任务的显式路线；读到最终错误后可通过真实变化的导航验证位置保存。GET `/__qa/workspace-proof` 只读保存原生位置、任务和源码哈希；保存包装页 `#observations` 后创建打印的 stop 文件。夹具最多运行十分钟，过期后离线页面不是在线验收；本次过期后一次点击未完成，未计为通过，随后在同一 Home 重启实例完成上述验证。第一次重启夹具误追加重复模型注册，仅是准备失败；改用标准版本化设置 API 更新原提供方地址后验证。

本轮一次自动化 fill 出现精确两份文字，逐字守卫在发送前拦下，清空并重新核对后才发送。没有该次完整事件记录，不能判定产品、浏览器或外部输入来源；`input-observation.json` 只保留长度、哈希和未发送说明。未修改产品去重。另一次点击已经选中的任务不会触发导航订阅，不等同于真正切换任务；这不是保存成功的证据。

本阶段没有压力测试，也没有覆盖日用程序、手机或官网。可信原生输入法、Android、系统剪贴板及下载落盘仍不在本阶段验收范围内。
