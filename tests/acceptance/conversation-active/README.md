# 流式回复、中断恢复与排队续发验收

2026-10-08，使用独立便携目录和正式打包版工作台完成。
模型仅连接本机回环服务，全部输入为固定测试文字，未访问用户数据或付费模型。

发现并修复：停止后继续生成的回复丢失分叉和重试按钮。恢复没有新增用户消息，
之前的投影只按本次运行 ID 查找输入，因此新运行无法找到原来的提问。
现在恢复回复沿用最近保留的主 Agent 输入，包括原始事件边界、完整文字引用和图片。
子 Agent 提问不会覆盖它；缺失历史、旧事件格式和已清除输入不会生成错误操作目标。

实际操作：生成半段回复 → 停止 → 点击“继续任务” → 完成回复 → 分叉 →
在分支点击重试。分支使用原始提问，原会话仍保留完整的恢复回复和操作按钮。
恢复时没有重复用户消息，最终只有一个正常对话回合。

另验证两条断网路径：

- 回复正在生成时断网，编辑新草稿，服务完成回复后恢复网络。回复完整显示一次，
  草稿仍在，手动续聊成功。
- 回复期间将下一条消息加入队列，然后断网并编辑另一份未发送草稿。
  网络恢复后队列自动发送一次，新草稿仍保留；刷新和切换会话后内容仍正确。

两组共 9 次模型请求，包括两次主动停止。最终错误事件为零。
最终一组请求中的用户消息数量依次为 `1、1、1、2、3`：继续任务与原回合重试
都没有复制用户输入。原会话 10 条记录，重试后的分支 18 条记录，无待处理提交。

远程读取超时另以真实传输实现的有界时钟测试复现并修复（`8814636`）：
读取超时保留对话并退避重试，不误报“回复未完成”；已受理写入超时仍标记结果
未确认，不自动重发。相关连接、时间线与传输检查 23 项通过；恢复动作、历史、
图片和消息替换检查 49 项通过。未进行压力或高负载测试。

复现可使用 `tests/manual_conversation_retry_qa.py` 启动隔离打包副本，
输入 `streaming` 或 `stream-stop`。第一段会立即输出，之后最多等待 60 秒；
创建隔离目录的 `release-streaming-N` 或 `release-stream-stop-N` 文件可提前继续，
`N` 为对应提问的请求次数。每个请求有独立标记，已取消旧请求不会抢占新请求的释放。
创建同目录的 `stop` 文件结束测试，只停止测试自己的宿主。
