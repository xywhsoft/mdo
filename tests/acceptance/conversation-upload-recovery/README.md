# 图片上传确认丢失后的恢复验收

2026-10-08，Windows 单文件工作台、独立便携目录和本机回环模型服务。
使用已有公开测试图 `tests/acceptance/xge-pixel-editor/smoke_window.png`，
没有读取用户私人图片，没有调用线上或付费模型。

旧版本的实际问题：服务器已经返回 201 并保存图片，浏览器收到响应前连接
断开。页面没有附件，也没有恢复；服务器却留有一份原件和元数据。
`upload-lost-before.jpg` 保存了这次基线，基线没有启动模型请求。

修复后用浏览器调试协议仅丢弃这一图片 PUT 的 201 响应，随后取消拦截：

1. 自动通过同一 ID 的元数据 GET 确认，缩略图和名称恢复。
2. 网络记录只有一次 PUT、一次 `/info` 确认和一次预览原件 GET；服务器
   只保存一对 `.bin/.json`，没有重复上传。
3. Shift+Enter 换行没有发送，Enter 将两行文字及图片一起发送。模型实际
   收到一条用户消息和一个 image part，只有一次模型请求，运行成功。
4. 再输入 `UNSENT_AFTER_IMAGE`，确认保存后刷新。未发送草稿、图片历史、
   回复及重试/分叉操作仍在；最终错误事件为零。

`upload-restored.jpg` 与 `reload-after-image.jpg` 是修复后的完整工作台截图。
白名单请求与事件结果见 `acceptance.json`，不保存请求头或写入令牌。

自动验证：34 项 Node 检查、20 项前端契约检查通过；两个实际 HTTP/TCC
探针通过。覆盖确认丢失、核对失败、稳定 ID 重试、90 秒总期限、单次请求
取消、内容/名称冲突、旧设备、编辑范围变化、16 张配额边界、重启后确认，
以及图片发送、Unicode 名称、历史引用和分叉。配额边界使用少量小文件，
没有进行压力或高负载测试。

独立测试宿主已停止，网络拦截已清除。Android 安装包另行构建；手机上的
文件选择、应用切换、休眠恢复及软键盘体验仍待真机验证。没有发布官网。
