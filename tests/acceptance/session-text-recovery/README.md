# 完整正文读取的安静恢复和整次操作期限

基线：`96fd093f`。独立 Windows 候选从干净工作树构建，仅改变会话正文、时间线动作和工具内容三个生产模块，仍使用锁定的 `3232f7b8efb0` 兼容宿主。构建记录为 `build.json`；四个实际包内生产文件逐字节核对见 `served-source.json`。

## 修复行为

原文字导出和完整消息读取直接等待 GET，一次 503 就提前结束，挂起的请求则没有恢复期限。现在复用统一读取恢复器，单次请求最多八秒、短暂故障最多六次尝试、指数退避；整个导出、整条复制消息的所有片段及递归全文读取共用一分钟预算。工具完整输入/输出和产物正文采用同样规则。

正文仍无法获取时，复制保留原可见部分并说明范围，导出在文件中标注不完整；历史编辑/重试必须取得原文，不能拿前缀继续。分页事件本身读取耗尽则结束导出并交给原有最终提示，不伪装成完整记录。页面离开取消操作及等待，不触发旧复制或重复提示。原有事件身份、epoch、前缀和内容大小约束保持。

九项新增检查在基线全部失败、修复后通过，另与历史投影、工具显示、图片导出、恢复和剪贴板选择一起通过 65 项 Node 检查。干净工作树的两个前端合约通过。测试覆盖同一预算的多页/多片段/递归读取、503、忽略取消的挂起请求、正文预览降级、页面离开及不使用前缀修改历史。工具产物的故障验证在生产解析器的 Node 检查中完成，本阶段没有额外执行一次真实工具产物的页面故障操作。

## 实际打包页

使用标准 API 添加回环模型并生成一段 10,435 字节的回复，超出当前 8 KiB 时间线展示边界；界面只显示前缀。没有修改事件文件或模拟聊天控制器。

- 复制原回复：全文接口连续两次 503 后成功，交给浏览器 Clipboard API 的内容恰为 10,435 字节，SHA-256 与原文相同；原时间线仍为前缀展示。`clipboard-handoff.json` 记录真实接口入参及成功确认，只观察且保留原实现。
- 正式 Markdown 导出：事件分页连续两次 503，全文读取再连续两次 503，恢复后导出包含原回复尾标记，未标注正文不完整。
- 全文正文持续暂扣：六个响应都先返回正常头部，正文暂扣 65 秒。整次导出 60.00 秒结束，仅包含可见前缀并标注正文不完整；没有为后续事件重新分配一分钟。
- 服务恢复后，正式“读取完整内容”展示原文尾部并移除读取按钮；随后正常续聊。两个回环模型请求、零最终模型错误。直接访问打包程序工作台、刷新后仍见续聊记录，CDP 与控制台无异常。

`proof.json` 包含服务器请求、模型原始输入及事件；`browser.json` 是复制交接和两份实际 Markdown Blob 的摘要；`native-browser.json` 为直接工作台复测。第一轮复制后，内置浏览器独立虚拟剪贴板读回为空，记录保留在 `copy.json`。复制接口收到全文不代表系统剪贴板读回已经通过；真实下载落盘也未据此确认。

外层 iframe 页再次出现此前定位的浏览器注入 MutationObserver 异常，记录保留于 `continued-browser.json`；来源定位见 `session-export-image-recovery/wrapper-exceptions.json` 及源码片段。直接工作台的日志为空，没有将外层注入错误误报为 mdo 脚本错误。

## 复现入口

```powershell
python -X utf8 tests/manual_session_export_recovery_qa.py --text-recovery --packed <候选 mdo.exe> --directory <全新隔离目录>
```

加载打印的工作台后，`GET /__qa/arm/full` 注入两次全文读取失败；`/list` 同时为事件分页和全文各注入两次失败；`/text-slow` 暂扣所有全文响应正文。通过正式复制和导出按钮操作，`GET /__qa/idle` 结束新故障。创建打印的 stop 文件收集证据并关闭自己的程序。所有服务仅绑定回环，Home 与模型凭据为隔离测试数据。

本阶段没有压力测试、日用程序更新、Android 安装或官网发布。系统剪贴板、导出落盘、可信输入法及 Android 页面仍需后续验证；本阶段临时页、验收进程均已关闭。
