# 草稿异步返回期间的输入观察

本阶段继续调查重复输入，没有修改产品逻辑。发现异步草稿返回会再次执行 `prompt.value = text`，因此通过真实打包页面检查重复赋值是否会改变正文或选区，而不是凭代码观感加入去重。

使用上一阶段候选 `.build/conversation-acceptance/workspace-startup/package/mdo.exe`，正式 HTTP/WS、独立 Home 与回环模型。`manual_composer_draft_qa.py` 复用已有输入观察器，只在代理中暂扣指定会话的 GET 正文；原生草稿/队列/模型调用没有替换，文本框访问器未覆盖。阶段候选中 `app.js` 与 `c204fd86` 的 CRLF 源一致；相关源码摘要记录在 `native.json`。

两个实际冷页面的结果：

- 第一页暂扣超过一分钟，产生预期的最终草稿读取提示。之后用户填入英文、选中第一个字符，放回响应后文字保持一份、选区仍为 `[0,1]`。随后中文多行填入逐字一致，没有复现重复拼接。最终读取恢复；不把此案例表述为全程没有读取提示。
- 第二页在冷读取期间填入 `COLD_DRAFT_TYPED_ONCE` 并选中第一个字符。草稿在约 9.65 秒返回，对相同的 21 字符正文再次赋值；随后正式发送前正文指纹和选区都未变化。原生与模型各一份该输入，回复成功，最后草稿/队列为空，零最终模型错误。当前实例浏览器警告/错误为空。
- 记录中的 fill 为不可信 paste/input；选区键盘操作为可信 keydown/keyup。内置浏览器的 `Input.imeSetComposition` 命令不受支持，没有生成任何组合事件。因此本轮仅排除了所测普通填入/选区路径，不能断言真实输入法路径已经稳定，也不能解释此前所有重复现象。

`events.json` 是每页的原始输入观察，只有长度、指纹、光标和赋值栈，没有输入正文；`reads.json` 保留实际暂扣/放回时间。`native.json` 来自真实服务，`checks.json` 由原始记录断言生成，`continued.png` 是正常续聊截图。未对真实用户文字去重、截断或回放。

复现：`python -X utf8 tests/manual_composer_draft_qa.py --packed <mdo.exe> --directory <新的隔离目录>`。打开打印地址，选择“冷启动，暂扣草稿读取”，输入已知内容并移动选区。通过 `/__qa/composer-release` 后端测试入口放回响应可避免点击外层按钮改变编辑器焦点；`/__qa/composer-proof` 只读核查原生草稿。退出前保存包装页 `#input-events`，创建打印的 stop 文件。实例最多十分钟，单次测试正文最多等待九十秒；过期实例不计为在线通过。

没有压力/高负载测试，没有改日用程序、手机或官网。真实持续输入法和平台 UI 仍待可用环境验证；继续检查网页工具暂时失败即返回模型的问题，尤其区分可安全重试的 GET 和可能计费的搜索 POST。
