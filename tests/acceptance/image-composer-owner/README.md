## 已复现的问题

通过实际文件选择器上传仓库内公开测试图 `tests/acceptance/xge-pixel-editor/smoke_window.png`。原生服务保存图片并返回 201，但回环代理暂扣响应正文。此时打开设置，再放行正文，基线把设置路由的空会话 ID 当作切换会话：原图片被清理，返回后草稿只有文字。`baseline.json` 证明一次成功上传、附件目录为空、草稿未引用图片、零模型请求，实时连接握手为 101；页面状态见 `baseline-browser.json` / `baseline.png`。

设置和计划任务只隐藏原输入区，没有选择新草稿。现在图片上传、移除及其恢复判断使用导航已保存的工作区归属；真正选择其他会话或新任务仍更新归属。

## 修复验收

- 设置期间放行上传：返回后原文字、文件名及一张图片保留，正常发送。
- 计划任务期间放行上传：返回后原文字及一张图片保留，正常发送。
- A 上传尚未完成时选择 B，并在 B 上传图片：放行 A 后仅清理 A 的未引用新附件，B 的草稿与图片 ID 不变。A 前两轮历史图片保留。
- B 发送图片再续聊文字，返回 A 并刷新：A 未发送草稿保持，B 没有残留草稿或队列。

实际模型共四次调用，每次原始输入准确；当前用户输入携带的图片数量依次为 `1,1,1,0`，零最终错误。四个不同上传 ID，仅保留三份已发送图片；丢弃的新附件已删除。详见 `fixed.json` / `summary.json` 及页面状态文件。

五项浏览器组件检查通过：设置/计划任务期间的延迟上传、延迟移除，以及切换不同会话后旧上传的清理。它们直接导入候选包中的生产组件，但使用可控上传/移除回调，不能替代上面的实际 HTTP 验收。结果见 `component.json`，夹具为 `tests/fixtures/composer-image-owner-browser.html`。
