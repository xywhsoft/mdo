# 当前对话状态轮询的超时与取消

基线 `2126c3b`。WebSocket 不可用时，`scheduleRunPoll` 原先直接等待 `readRun`，没有超时或取消信号。一个不返回的请求会使该轮状态刷新停住，清除定时器不能释放已开始的 HTTP。响应也没有校验精确项目和会话归属。

新增小型 `run-poll-read.js`，复用请求恢复机制，单次八秒超时，只读，不在适配器里重复请求。已有调度器继续负责静默指数退避，到十五秒后保持低频检查，暂时读不到状态不会被当作模型运行失败。停止确认、开始运行和队列写入协议保持原行为。

切换运行或页面路由、进入后台、退出页面、实时连接恢复与服务运行代变化会取消等待。被取消的轮询保持安静，不再调度旧轮或显示错误。精确运行 ID、项目、会话和布尔 terminal 必须匹配才能应用状态。设置和计划任务视图不启动当前对话的兜底轮询。

## 检查

12 项新检查包含拒绝 abort 的传输、迟到数据、新旧运行交叠、HTTP 开始前取消、实际 API 客户端的 abort、错误响应归属、暂时 429 的退避、明确 403 原错误，以及不应读取的视图。三项检查从应用源码提取并执行真实 `scheduleRunPoll` 函数，避免另写一份调度算法充当验证对象。先新增适配器而尚未接入应用时，六项适配器检查通过，三项原调度器检查全部失败；接入后通过。

与停止、实时连接、运行恢复读取及目录读取一起执行，共 60 项 Node 检查通过，四项前端契约检查通过。
