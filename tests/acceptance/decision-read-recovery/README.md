# 对话询问、权限审核与运行列表的安静读取恢复

基线 `457ec93`。已复现权限 PUT 成功后被失败 GET 判成提交失败，以及询问回答被后续 GET 拖住的问题。读取恢复与写入确认现在各自负责自己的结果。

## 产品改动

- 询问、权限审核和运行列表的纯读取接入原有有界恢复：最多六次尝试、共同一分钟期限、单次最多八秒、指数退避和抖动。普通轮询合并到正在进行的读取；耗尽后保留准确提示，每 30 秒最多探测一次，正式重试按钮可立即读取。
- 已确认的回答和权限决定立即完成，不再等待附加读取，也不会因附加读取失败变成写入错误。保留已提交锁，读取失败和重复点击不会重放 PUT。
- 健康后台刷新保留已读内容；相同询问快照保留原状态对象及编辑器。旧请求取消、会话切换和页面缓存往返继续由资源存储的代次保护。
- 只有最终读取失败才出现一处可重试的持久提示，区别于回答提交失败；中英俄文均覆盖。明确权限拒绝等永久原因保留准确提示，丢弃不可用旧控件，不进入指数重试。
- 权限响应必须包含有效列表；畸形成功响应不能清除已接受决定的锁。普通设置等默认资源存储不自动重试。

## 实际打包页面验证

隔离原生实例运行普通可编辑回环模型。第一轮调用真实 `ask_user`，回答后调用真实 `exec`，通过正常一次性权限确认执行 Python 打印 `DECISION_VERIFIED`；最后正常回复。接缝只令 GET 返回有限次 503，不改变实际 PUT、原生工具、事件或确认结果。

回答后的询问、审核、运行读取各失败两次，界面没有错误 toast，已回答控件立即锁定，主输入草稿保留。审核确认后的另外六次审核读取耗尽时，只有一处“暂时无法读取权限审核”的最终提示；实际命令已成功退出，模型已经正常完成。30 秒探测等待期内点击正式重试按钮，提示和旧审核卡消失；发送保留草稿后正常续聊。

`native-runs.json` 记录四次模型请求、一次回答 PUT、一次审核 PUT、零最终模型错误；两个真实工具均成功，命令退出码为零。原验收脚本误选了不存在的 `tool_exec` 事件，本次工具正文从同一实例落盘的会话快照核对，脚本已改为读取正式 `tool_done` 事件。没有为了补证重启或重做对话。

界面记录：`answer-accepted.json`、`approval-accepted.json`、`final-read-notice.json`、`restored.json`、`continued.json`；截图包含最终提示和恢复后续聊。
