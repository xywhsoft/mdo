# 完整文字读取和导出的历史一致性

基线 `39de3921`，独立 Windows 候选只修改 `state/sessions.js` 与 `features/chat/timeline.js` 两个生产模块，使用锁定的 `3232f7b8efb0` 兼容宿主。构建记录见 `build.json`，四个实际包内文件与干净构建来源逐字节一致，见 `served-source.json`。期间主工作区另有提交，本阶段没有把这些修改混入候选或提交。

## 修复

原导出分页和后续全文没有绑定同一历史；历史被编辑、清空或导入替换时，可能拼接旧回合与新回复。单条全文也没有验证返回的 epoch，单事件投影的复制/编辑引用则遗漏了该标识。

导出现在固定首个历史 epoch，并把它传给每页和全文。第一次历史变化时丢弃整份旧快照、安静重新读取一次；第二次变化只给一条准确的最终提示，不生成混合文件。重读共用原有一分钟总预算，网络退避和页面取消规则不变。异常全文不能替换不相符的预览。用户、助手和最终回复的单事件投影均保留历史标识，复制降级仍诚实保留可见部分，编辑/重试仍要求完整原文。

八项新增复现检查在基线全失败、修复全通过；另增加共享截止时间检查。与全文恢复、历史投影、工具展示及图片导出一起通过 78 项 Node 检查，两个干净前端合约通过。原有模拟响应补上正式 API 已提供的 epoch，未放宽生产校验。

## 实际打包页

`manual_session_text_snapshot_qa.py` 复用隔离 Home 和回环模型。先完成一个 10,435 字节的真实模型回复。导出读取初始事件快照后，夹具通过正式清空 API 和真实新运行替换历史，再交接先前读到的响应；没有修改事件文件或模拟聊天控制器。

- 基线：导出 4,346 字节，仍包含已清空的 `EXPORT DOWNLOAD QA` 旧预览，并标注正文不完整。
- 一次替换：全文接口对旧 epoch 返回 409，修复版自动重新读取，导出 11,160 字节，仅包含 `SNAPSHOT_REPLY_1` 的完整新回合，没有旧输入或中途错误提示。
- 连续替换两次：请求状态为 `200, 409, 200, 409`，没有新 Markdown Blob，仅显示一次“消息已不在当前会话历史中，请刷新会话”。未发送输入“历史更新期间保留我的输入”保持原样。
- 停止注入后重新导出仅包含完整 `SNAPSHOT_REPLY_3`；直接发送保留的输入，得到准确的 `CONTINUED` 回复。五次模型请求，零最终模型错误。

`proof.json` 记录实际 API、epoch 变化和模型输入。浏览器文件记录原始 Markdown Blob 摘要、草稿、最终提示数量及续聊；观察器保留原下载动作。浏览器下载事件等待没有返回路径，`download.json` 保留这一限制，不能据此声称真实文件落盘通过。

外层 iframe 再次出现之前定位的浏览器注入 MutationObserver 异常，保留在浏览器记录中；来源证据见 `session-export-image-recovery/wrapper-exceptions.json`。直接工作台打开后已看到续聊记录，但尚未完成带异常监听的在线刷新，隔离服务就达到十分钟期限并结束；`native-after-fixture-expiry.json` 是缓存页面离线后的观察，不能当作在线刷新验收。其误导性的项目清除提示需另行审查。

## 复现

```powershell
python -X utf8 tests/manual_session_text_snapshot_qa.py --packed <候选 mdo.exe> --directory <全新隔离目录>
```

加载打印的工作台。`GET /__qa/arm/replace` 注入一次真实历史替换，`/repeat` 注入两次；随后点击正式 Markdown 导出按钮。`GET /__qa/idle` 结束新故障，再导出及续聊。创建打印的 stop 文件提前收集证据和关闭自己的程序，夹具最长十分钟。

本阶段临时页和进程均已结束，没有压力测试、日用程序覆盖、Android 安装或官网发布。可信输入法、Android 页面、系统剪贴板及下载落盘仍待验证。
