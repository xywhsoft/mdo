# 区分本地模型配置失败与上游拒绝

安卓验收中，测试模型漏声明思考控制能力，客户端在发送前校验失败，
但最终提示描述成“模型服务拒绝了请求”。这会把本地配置问题误导为服务问题。

现将 `XLLM_ERROR_INVALID_ARGUMENT` 且无 HTTP 状态的失败分类为
`request_configuration`，说明本地配置无法生成有效请求，并指出接口地址、
模型能力、思考强度与输出上限四个检查方向。实际上游 400/422 保留
`invalid_request`。三种界面语言均支持新分类，未知旧记录的原解释继续保留。
不增加重试、不反射底层原文，也不改变额度、认证或取消分类的优先级。

回归及真实打包检查：

- 增补前，26 个原生案例中仅新增本地校验案例仍得到旧分类；
  四项 Node 检查中的语言检查失败（新分类仍使用原文）。
- 增补后，26 个原生案例、四项 Node、六项模型契约检查通过。
  本地输出上限校验案例没有发送 HTTP 请求，上游 400 仍归类为请求拒绝。
- 完整打包页配置为缺少思考控制能力；实际 Enter 提交后只有一条准确最终提示，
  原生事件记录 `request_configuration`、HTTP 状态 0，模型服务收到零请求。
- 经正式设置 API 恢复能力后，实际点击“继续任务”，原请求成功；
  再用 Enter 发送新消息成功。共两次模型请求，旧失败提示退出页面，
  草稿与队列清空，没有重复模型请求或新最终错误。
- 页面实际加载的错误映射及三份语言文件与隔离 QA 源码逐字节一致。

`failed.json`、`continued.json` 保存原生事件、请求计数及回合投影；
`*-browser.json` 和图片保存真实页面状态。`build.json` 保留构建来源及候选 SHA-256，
只删去冗长的宿主导出符号清单；完整构建记录仍在候选目录。
