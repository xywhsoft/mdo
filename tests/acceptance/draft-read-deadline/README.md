# 首次草稿读取的有界恢复

在实际打包页面复现：当前会话草稿的 GET 已收到成功响应头，但响应体不返回时，输入仍可编辑，发送按钮一直禁用。修复前没有该读取的超时；四项针对性检查全部失败。`baseline-blocked.png`、`baseline-browser.json` 与 `baseline-proof.json` 来自隔离打包实例。故障只命中该会话 `/draft`，没有篡改草稿、队列或模型事件。

首次读取现在使用已有的请求恢复器：单次八秒、最多六次、有抖动的指数退避、共同一分钟期限。临时失败在这轮恢复内不通知用户；耗尽或永久拒绝才报告一次准确的读取错误。草稿版本、已保存的提交及待确认运行仍必须读到以后才能写入或发送，本次没有增加写入重放。迟到且忽略取消的响应不会覆盖当前输入或移除已恢复的提交保护。

离开页面取消冷读取及其重试；仍在内存中的页面返回时可以重新读取并保存输入。已加载草稿的退出保存保留原有机制。普通刷新后的持久化验证是在草稿已成功保存后进行；本阶段没有证明读取尚未完成就关闭窗口也能持久保存新输入。

读取失败提示使用独立的中英俄文文案，避免把“无法读取”误称为“草稿未保存”。已有的外层断线重连调度保留；`test_draft_read_recovery.mjs` 隔离检查一轮恢复结束后的调度，新增 `test_draft_read_deadline.mjs` 使用生产恢复器验证超时、退避、最终一次错误及页面生命周期。

## 真实打包验证

- `manual_image_upload_deadline_qa.py --draft-read-fault` 在回环代理挂起第一次成功响应体三十五秒，再让两次恢复 GET 返回 503。两个修复后实例均在约十二秒恢复，早于旧响应放行。
- 第二个实例在读取仍挂起时输入中文草稿，见 `early-browser.json`。恢复后自动保存，输入内容未变；普通刷新初始化完成后草稿相同、输入框获得焦点、发送可用，见 `restored-browser.json` 与 `reloaded-browser.json`。`reload-initializing-browser.json` 是初始化未完成的快照，不作为恢复成功的证据。
- 两个实例合计三次实际模型请求、三次相符输入、零最终模型错误。第二个实例连续两轮均 `succeeded`，结束时草稿及队列为空，见 `proof-first.json`、`proof.json` 和 `continued.png`。测试模型仅在回环服务返回标记回复，不调用线上模型。
- 调试事件记录安装时读取已经恢复，因此 `debug-observations.json` 不证明此前整段界面无错误。临时失败不报告和六次耗尽只报告一次由新增确定性检查覆盖；页面早期和恢复后快照均未显示草稿错误。刷新后文档日志为空，只代表该文档。

88 项相关 Node 检查、四项干净前端合约通过。五个实际 HTTP 返回的生产文件与独立源码逐字节相同，见 `checks.json`、`source-parity.json`。构建基线 `22d7fa9` 加本阶段生产改动，锁定 xs `3232f7b8`；候选 `.build/conversation-acceptance/draft-read-deadline-package/mdo.exe`，SHA-256 `5eb3dbe74e2b79fb06e3ee7be0625ed3d515a4c458aaa5557aa398d45cec5273`。语言文件仅加入本阶段文案，没有打入根目录其他未提交改动。

本阶段从重复输入排查开始，但可用的内嵌浏览器明确不支持 `Input.imeSetComposition`，不能生成可信的输入法组合事件。此前重复输入的原因仍未查明；本次普通自动化填值未重复，不代表真实输入法场景全部通过。临时浏览器调试记录已经随测试页关闭清理，没有进入产品代码。

没有压力或高负载测试，没有更新日常程序、手机或官网。安卓真机、原生剪贴板/导出，以及备份源清单的间歇失败仍待验证；草稿写入确认等剩余等待路径继续排查。
