# 编辑重发确认丢失验收

独立打包程序和便携 Home，仅使用回环模型；没有压力测试或付费模型请求。

旧候选包来源为 `8df7160`。真实浏览器在服务端成功修改历史后丢弃响应：编辑框立刻显示连接错误，再次保存显示“消息已不在当前会话历史中”。原输入仅留在编辑弹窗，原消息已被移除，持久化草稿为空。两个 `baseline-*.jpg` 保留此结果。

最终候选包的 SHA-256、请求摘要、原生草稿和模型调用计数见 `acceptance.json`，服务端协议检查见 `protocol.json`。当前检查包含：

- 丢弃一次成功编辑的确认：两个 POST 使用同一编辑 ID、原始消息 ID 和边界，自动完成一轮回复，编辑模型只执行一次。
- 丢弃六次确认：六个服务端响应均为 200，重放只返回已有结果。最终只显示“暂时无法确认编辑重发的结果”，没有自动启动替代模型。输入关闭弹窗并刷新后仍然保留；手动发送后正常回复。
- 丢弃一次草稿 PUT 的成功确认：只保存一次该编辑输入，通过 GET 读回确认，再执行一次历史修改并正常回复。
- 四个明确启动的模型回合各执行一次；最终草稿为空，原生事件没有最终错误。协议检查另外只执行两个回环模型回合，验证文件字节不变、原始事件保护、修订冲突、参数冲突、旧接口及重启写入屏障。

Node 状态检查覆盖退避次数与总时限、可取消和不响应取消的 I/O、页面离开、切换会话、预先保存失败及模型启动不重复。草稿、发送意图和排队回归同时通过；前端模块图及 API 合约检查通过。API 合约里旧的响应大小字符串断言已跟随现有生态下载专用上限更新，普通 JSON 响应上限仍受检查。

复现服务端检查：

```powershell
python tests/test_packed_message_edit_recovery.py --packed .build/conversation-acceptance/mdo-edit-final.exe
```

浏览器注入使用精确路径、Fetch 类型、Response 阶段，在捕获 200 后以 `ConnectionClosed` 丢弃响应；每个用例的拦截都已清除，临时页面和服务均已关闭。截图验证的是 Windows 打包页面；不代表 Android 真机验收，也未更新官网安装包。

候选构建见 `builds.json`：Windows 验收实例已更新；精简、完整 ARM64 APK 的 v2/v3 签名与 16 KiB 对齐检查通过，两者应用包与 Windows VFS 内容完全一致。默认 WSL 挂载曾返回 EIO，本次使用独立验证的挂载完成构建，随后已卸载。

构建检查在当前构建目录未找到旧开发签名文件；新候选 APK 的开发签名与上一批不同。因此它们不能直接覆盖上一批候选安装，尚不能作为设备更新或官网发布包。已检查本地构建目录和 Linux 用户目录，没有找到对应旧私钥；需恢复原签名文件或使用正式发布签名流程后再进行升级验证。没有卸载手机应用或变更线上签名关联。
