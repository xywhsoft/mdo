# 任务读取的准确提示与失效详情

基线为 `206d3d2`。任务不存在、详情/列表/输出暂不可用和停止被拒绝等稳定 API 代码没有界面文案映射；读取 `asks_unavailable` 又共用提交回答的文案，导致错误含义不准确。

生产组件复现还确认：详情 GET 返回 403 或 `task_not_found` 后，旧快照仍保存，询问编辑器和提交按钮继续显示。`denied-before.json`、`missing-before.json` 与截图记录这一现象。

## 变更

- 补齐任务 API 的中、英、俄文提示；未知永久错误仍保留其具体解释。任务读取界面对询问失败使用读取文案，提交回答继续使用提交文案；未知临时传输错误最终以可操作的读取提示呈现。
- 任务列表/详情的纯读取在永久拒绝时丢弃不可用快照并清除成功时间，重试确认前不会重新出现旧询问/输出。普通资源存储和设置写入保持原策略，临时故障耗尽仍保留已有进度。
- 权限拒绝后隐藏询问，恢复成功后保留未提交回答；明确任务不存在则清除该任务已失效的回答状态。
- 首次列表读取或丢弃旧快照后的载入显示“正在载入任务…”，不会提前显示“暂无后台任务”。没有旧列表的最终失败也提供正式的“重试读取”按钮。

## 验证

56 项 Node 检查和三个相关干净前端合约通过，包括原模型错误分类、任务取消、输出追加、页面生命周期、设置保存和读取策略。新检查先复现稳定代码直接显示内部诊断、403 保留旧快照，再验证修复。

`task-read-errors-browser.html` 使用正式生产组件与可控 API 返回值：403 后询问不再显示，恢复成功保留“保留未提交的回答”，404 后再次返回不会带回已失效草稿，全部零写入。初次载入显示状态的记录见 `cold-list*.json`。临时测试源曾缓存旧文案模块，最终结果使用新测试源核对；没有清除用户浏览器缓存。

已提交回答回归的 11 项实际组件检查全部通过：轮询/中文输入法不重建编辑器、语言切换保留焦点、按任务隔离草稿、UTF-8 字节限额、重复提交保护、接受回答后的安静读取恢复、正确任务和询问 ID、页面不溢出。该旧夹具也改为等待自动恢复，避免继续要求已经移除的即时错误分支。

完整原生打包页面通过普通模型 `spawn` 创建真实进程，再仅令任务询问 GET 临时返回 503。首次详情读取安静退避，最终只显示“暂时无法读取任务询问，请稍后重试。”，输入保留；读取恢复后提示消失、显示真实任务输出，随后发送原输入正常得到回复。该实例仅一次 DELETE、三次回环模型请求，零最终模型错误，见 `fixed-runs.json` 与 `questions-*.json`。

该夹具故障上限为 12，确保能够检查第一轮六次读取尝试耗尽后的提示；随后常规刷新又消耗了剩余故障。它不是一个十二次尝试的预算，也没有再次创建任务或执行工具。后续仍需核查常规轮询在已耗尽读取后的界面状态，防止错误/载入反复切换造成干扰。

基线原生实例两轮各六次读取失败后均已自动恢复，未及时捕获最终错误画面；`questions-baseline-recovered.*` 明确记录的是恢复后的状态，不作为错误画面证明。读写文案混淆由 API 稳定代码、旧源码及文案检查确认。

## 构建与范围

`build.json` 记录独立候选 `mdo-task-errors-final.exe`，约 4.4 MB。仅前端和测试修改，复用匹配版本/裁剪配置的宿主收据；八个实际 HTTP 返回文件与隔离源码逐字节一致，没有纳入根工作区其他未提交修改。夹具控制端点只存在于隔离 app 副本，产品候选不含这些端点。

重现完整页面可使用 `manual_task_read_recovery_qa.py --failures 12 --read-target questions`，其余参数和操作见上一阶段说明。`/api/v1/qa-task-release` 仅停止夹具注入故障。实例最长六分钟，只做有界功能测试。

没有压力或高负载测试，没有安卓真机验证，没有替换日常程序、手机或官网安装包。
