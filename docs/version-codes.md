# mdo 版本码与迁移规则

本规则为长期发布约定，修改更新、安装、扩展兼容条件时均需检查。

## 三个字段

- `version_name`：用户看到的三段十进制版本，如 `0.6.1`。
- `version_code`：四个十六进制字节，JSON 中必须使用字符串。标准输出为八位大写，例如 `05000601`；读取也接受 `05.00.06.01`。每个实际版本分量范围为 0～255，`0.10.0` 编码为 `05000A00`。
- `build_id`：历史客户端与 Android 安装器使用的递增十进制安装编号，现阶段保留八位格式。不同产物使用不同编号，重新打包也必须递增。它与语义版本码独立，**不要将十六进制版本码填进这个字段**。

## 比较与前缀

用户已将迁移前缀最终更正为 `0x05`，不是 `0x50` 或 `0x60`。当前 `05000600` 的十进制为 83,887,616；1.0 之前的最大编码 `0500FFFF` 为 83,951,615，仍在八位十进制范围内。此前 `60000000` 特殊基线约定已取消，读取端仍兼容该旧标记。

版本码存储为 uint32，比较统一使用 `code & 0x00FFFFFF`，忽略整个最高字节。最高字节为迁移标记，因此实际版本排序空间为低 24 位，即最高 `255.255.255`。不能把它描述成四个有效版本分量。

官方版本以三个十进制版本分量转换为三个字节；比较值小于 `00010000` 时添加 `05` 前缀，达到 `1.0.0` 时清除前缀。

| 展示版本 | 官方版本码 | 比较值 |
| --- | --- | --- |
| 0.6.0 | `05000600` | `000600` |
| 0.6.1 | `05000601` | `000601` |
| 0.255.255 | `0500FFFF` | `00FFFF` |
| 1.0.0 | `00010000` | `010000` |
| 255.255.255 | `00FFFFFF` | `FFFFFF` |

读取端也接受其他最高字节，包括提前清除前缀的 `00000601`：它比 `05000600` 新，与 `05000601` 等价。**1.0 切换点是 `00010000`，不是 `00100000`。**

新清单带 `version_code` 时先比较低 24 位；同版本用更大的 `build_id` 区分重新打包。清单没有新字段时兼容旧的 `build_id` 比较。字段存在但类型或格式错误则拒绝清单；强制更新缓存使用同样的解析与比较规则。运行文件哈希相同时不重复安装。

Android 系统强制安装编号递增。APK 的 `android:versionCode` 继续使用安装编号，不能在 1.0 时清零、改用掩码值或以卸载应用规避。Windows/Linux 的兼容编号也继续递增，因此旧客户端可以先升级至具备新规则的版本。八位旧协议编号与语义版本不再按大版本一起膨胀；如果将来确实耗尽该安装序列，仍须独立升级旧协议，不能声称这次已无限扩容。

## 协议和发布

新客户端请求 `/update/version` 时增加 `version_format=hex24&version_code=05000600`，保留 `platform`、`edition`、`build_id`。显式格式参数使服务端可以区分旧客户端与被旧 SDK 丢弃的畸形版本参数。旧服务端忽略额外参数并返回旧清单，新客户端按兼容路径处理。

服务端对新请求按语义版本选择，再用安装编号排序；旧请求继续按安装编号选择。没有新版本码的历史记录仍可用，后台编辑历史记录可保持字段为空，新上传必须填写文件内的版本码。发布记录、APK 资源元数据、打包回执、离线更新缓存均保留新字段。

修改 `app/release.json` 的 `version_name`、`version_code` 和八个安装编号，然后完整重新编译。`tools/version_code.py` 检查官方编码与 1.0 前缀切换；`tools/prepare_release.py` 核对清单、构建记录、APK 元数据与打包 C 宏一致，拒绝复用旧产物。构建汇总 `mdo-builds.json` 也须记录 `version_code`。

客户端和服务端使用相同的 `version_code.h`；改动时同步两份并运行以下回归：

```
python -m unittest discover -s tests -p test_version_codes.py
python tests/test_update_runtime.py
```

平台仓库另运行 `python tests/test_mdo_version_codes.py`、`node tests/test_mdo_version_codes.mjs`。测试仅使用隔离服务与模拟安装包，不调用真实模型，不写生产数据。
