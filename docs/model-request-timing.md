# 模型请求耗时诊断

回复操作区的“请求耗时”详情提供首段思考、首段正文、已观察到的重试等待、请求次数、末次请求首字节/首模型数据与 Request ID。首段思考和正文从持久事件的 model_start 起计算，包含此前排队和恢复等待；空白 delta 不计作可见输出。末次请求的传输统计只覆盖最后一次 HTTP 尝试，不能与整轮总耗时混用。

SDK 首模型数据可能为思考或工具调用，并不等同首正文；网关心跳原始字节也不等同首正文。客户端首次绘制和服务器内部排队耗时没有直接测量，不凭这些数据推断其数值。排障时用 Request ID 对齐线上请求记录。

事件 schema 10 保存传输统计，旧记录仍可读，缺失记录不伪造时长。历史裁剪会保留统计。网络恢复继续支持不限次数、单次最长五分钟退避及用户取消，未新增隐式重试上限。

验证：首段思考/正文与重试分离、空 delta、缺失历史、交叠调用，原生 journal/API 往返及 schema 9 兼容测试通过。
