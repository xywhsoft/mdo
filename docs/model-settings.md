# 模型设置

模型设置分为供应商引导和高级编辑。中文界面统一使用“供应商”；配置文件中的 `provider` 字段和协议标识保持不变。

## 账号模型与启动

原生 `MdoModelInfo.RequiresLogin` 和 `/api/v1/models` 的 `requires_login` 标识需要账号的模型。
目录同时返回 `login_state`：`pending` 表示登录恢复或账号模型目录尚未加载，`signed_out` 表示需要登录，
`unavailable` 表示目录加载失败，`ready` 表示账号及目录均已就绪。账号快照通过 `model_catalog_state`
报告这一状态，独立于额度查询结果。

启动时保留原来的模型选择。所选模型需要登录时，发送、自动队列和恢复运行等待目录就绪，草稿仍可编辑，
也可以选择自己的供应商模型。目录就绪后自动刷新模型及会话恢复状态；只有成功加载的目录中确实没有
该模型时才报告模型不存在。网络失败不等同于模型被移除。线上模型目录不写入用户模型配置，保存过的
`mdo-online.*` 身份在启动时仍可识别；同名的明确个人配置优先。

回归：`python tests/test_login_model_startup.py` 使用本地模拟账号、模型与独立 Home，覆盖记住登录后的
启动、延迟登录和目录读取、读取失败、确认移除，以及就绪后的一次真实协议请求，不访问线上服务。

## 普通用户

1. 在“基础设置 → 模型管理”选择“添加供应商”。
2. 选择供应商和 API 产品，填写 API Key。标准 API 与 Coding Plan 使用各自的地址，不会自动混用。
3. 连接并读取模型列表，搜索、勾选需要的模型，再添加。供应商没有模型列表接口时，可以使用模板中的模型 ID，或手动填写。
4. 点击“添加并验证所选模型”，自动保存并适配配置，再逐个验证流式回复和工具调用。请求会消耗 Token；工具测试携带本机已注册的内置工具定义，并指定不执行的探针，不执行任何实际工具。未声明工具能力的模型只验证流式回复。
5. 详情显示每个模型的验证结果；失败时显示原因，可点击“完整验证 / 重试”。验证期间可停止后续请求，也可关闭设置页；已保存的模型保留，可稍后继续验证。

第三方兼容服务统一从“自定义供应商”进入，选择 Chat Completions、Responses 或 Anthropic Messages 协议，填写包含 `/v1` 等前缀的服务地址和 Key。切换协议保留已经输入的地址、Key 和手动模型 ID；只为所选协议创建端点，不假定兼容服务支持其他协议。原先配置的 OpenAI/Anthropic 兼容供应商继续可用。

勾选“首个新增模型验证通过后设为默认”时，首个模型验证通过后才修改默认选择；失败、取消或配置变化时保留原默认模型。也可手动点击“设为默认模型”。内置 ornith-1.5-35b 保持只读。同一供应商可配置多个实例，同一 API 模型也可配置到不同实例。

PC 显示供应商列表和详情；手机先显示列表，选择后进入详情。聊天输入区的模型面板有“管理模型”入口。

## 专业配置

“高级编辑”保留多协议地址、凭据引用、TLS 校验、超时、模型能力、思考强度、附件类型和独立输入/输出限制。模板只填初始配置，刷新模型列表不会覆盖已有模型的名称或高级参数。

未知模型采用保守的上下文和输出限制，不推断图片或并行工具能力。模型目录通常只提供 ID，不足以证明实际能力。若供应商的限制更小，应在高级编辑中调整；回复和工具测试也分别验证，不把模型列表连接成功当作模型可用。

新增模型默认跟随供应商的代理，与读取模型列表的网络路线一致；显式选择的模型代理仍优先。构造请求时按模型声明省略未支持的可选并行控制和无思考控制，不更改已有模型的高级参数，也不轮流试用不同协议。

“已验证”表示该配置下的简短流式回复和（如声明支持）携带本机内置工具定义的指定探针调用曾通过，不证明所有上下文长度、附件、用户角色的模型选项、按需加载的第三方 MCP 工具或未来服务可用性。回复必须包含可见文本，仅有思考内容不算成功；工具调用必须具有正确名称、调用 ID 和符合探针 schema 的参数。测试不读取会话历史，不启动用户 Agent 生命周期或工具执行。

OpenAI 的严格工具模式要求每个对象关闭额外字段、将所有字段列入 `required`。mdo 在 SDK 的公开请求正文回调中检查实际序列化的函数定义：兼容的严格定义保持 `strict:true`；具有可选字段等不兼容约束的定义明确发送 `strict:false`。SDK 本身不修改，工具原有参数 schema、可选字段、名字、权限与执行校验保持原样；调用方请求级回调继续转发。明确发送 `false` 也避免 Responses 在字段省略时自行归一化参数。参考：[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)。

验证记录保存在 Home 的 `data/model-verification/<模型ID的SHA256>.json`，刷新页面和重启后保留。schema 2 的 `contract` 为 `runtime-tools-stream-v2`，原 schema 1 的简单探针记录不再当作已验证，需要重新测试。记录绑定模型、供应商、全局传输配置及本机内置工具定义的指纹，能力、限额、端点、凭据引用、代理或工具定义变化后不再显示旧标记；修改默认模型不使记录失效。只存阶段状态、耗时、稳定错误类型及指纹，不保存 Key、请求正文或回复。外部 `env:`/`file:` 引用内容、系统代理或上游服务变化后，应重新验证。

“恢复模板连接参数”只修改编辑中的地址、TLS 和超时，仍需保存。原有 `env:`、`file:` 等凭据引用继续可用。模型可停用后重新启用；默认模型不能直接停用或删除。

## 凭据与保存

直接输入的 Key 由本机 xs 凭据封装接口加密，保存为：

```
mdo-home/config/secrets/models/<random-id>.key
```

模型配置只有 `vault:<random-id>` 引用，不含明文 Key。浏览器不把 Key 写入 URL、localStorage 或 sessionStorage；草稿只保留在当前设置页内存中。移动 Home 到另一台设备后，加密 Key 可能无法使用，需要重新输入；环境变量和文件引用适用于自行管理跨设备凭据。

Key 更换使用新的不可变文件，旧文件继续为配置备份和正在运行的客户端保留。设置事务失败时清除本次新增的密钥文件，回滚无法确认时保留文件以便恢复。清理旧凭据必须同时考虑配置备份和活动客户端，不能仅按当前配置引用删除。

保存使用配置 ETag。提交前重新读取模型配置：无关的设置保存只更新版本号；真正的模型配置冲突会拒绝提交，并保留草稿。已保存但回读失败时，先刷新再继续写入。

## 接口与运行时

以下接口使用现有 API 的认证和错误结构：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/models/config` | 非明文密钥的完整模型配置及 ETag，附加只读 `verification` 对象，以模型 ID 为键 |
| `POST /api/v1/models/setup` | `{patch, keys:[{provider,value}]}`，带 `If-Match`；凭据与配置在一次设置事务内提交 |
| `POST /api/v1/models/discover` | `{provider,key?}`，只读取草稿供应商的模型目录，不保存 Key |
| `POST /api/v1/models/test` | `{model_id,tools?:boolean}`，只测试已保存且启用的模型，保存对应阶段结果 |

发现请求按完整模型地址推导 `/models`，保持代理、证书设置，禁止携带凭据跟随重定向。目录限 256 KiB、2048 项、15 秒，浏览器列表显示前 100 个搜索匹配项。每个测试限 30 秒、最多 1024 输出 Token（不超过模型自身上限）。专用后台任务池为一个工作线程和一个等待项，避免在 xs 网络工作线程内同步阻塞；卸载前取消并等待任务结束。添加向导只测试本次新增的所选模型，顺序执行，不遍历整份目录。停止后续验证不会撤销配置保存，已经发出的原生测试仍受 30 秒期限约束。

测试成功响应中的 `verified` 表示本次阶段通过，`verification.verified` 才表示整体通过；整体还要求已声明的工具能力验证成功。测试期间配置发生变化返回 `409 model_config_changed`，不为新配置写入通过标记。`verification` 不属于模型配置补丁，不应随 `providers`、`items`、`default_model` 一起写入设置。

当前 xs TCC SDK 没有提供全部 xhttp 扩展声明，`app/include/mdo/model_http_sdk.h` 补充锁定版本的公开声明，不包含第二份实现。升级 SDK 时运行 `python tools/model_http_sdk.py <locked-xs-root>`；CI/本地可用 `--check` 检查声明是否一致。

## 对话模型重连

上下文圆环与自动压缩使用同一份原生上下文状态：以上次主模型返回的 input+output
为基准，累加之后新增消息、工具结果和当前输入的估算。在每次调用前检查压缩阈值，
并保留输出预算；重启不会清除有效基准。旧记录缺少服务端用量时明确显示估算。
这与 HTTP 正文字节上限不同：官方网关支持 32 MiB 请求正文，超过时提示字节限制。
估算不等于供应商精确分词，单次极长输入、图像及模型切换仍需安全余量。

网络中断、超时、临时限流、502/503 等服务异常，以及没有明确业务原因的
上游错误会持续自动恢复，直到模型回复成功、用户停止、账号退出/切换或调用方
明确设定的任务期限到达。没有固定的连接重试次数上限，也不再用两分钟恢复
预算截断后续请求；在线模型每次请求仍保留自身的十分钟超时。

同一次连续故障按 1、2、4、8、16、32、64、128、256 秒递增退避，加入少量
正向随机抖动，常规上限五分钟。服务端要求更长的 `Retry-After` 时遵守该最小
等待时间，后续失败也不会把间隔缩短。一次完整回复成功后，下次请求从第一次
尝试和最短间隔重新开始；统计里的实际尝试总数仍保留，不伪装为一次请求。

余额/额度不足、账号及权限、模型或请求配置错误会按明确原因结束。已交付且
不能替换的流不自动重放；Agent 可替换的失败草稿在完整回复成功前不会执行
工具。明确的输出上限或格式错误仍只进行有界修复，不重复已经完成的工具。

## 对话权限即时切换

输入框中的“询问 / 完全访问”修改成功后立即作用于当前任务，无需重新发送消息或重启任务。
切换到完全访问会唤醒该会话尚未决定的工具审批；切回询问会清除“本轮均允许”的授权，
之后的工具调用重新遵守询问策略。文件工具的工作区边界与权限同步切换，已创建的子任务
（包括后台任务）共享该状态；其他会话不受影响。已开始执行的操作继续完成。
显式声明只读的 Agent 保持只读上限。

模型和思考强度在任务运行期间仍作为后续消息配置保存。排队消息里的旧权限不覆盖
会话的最新权限；切换权限也不提前应用排队消息的模型或思考强度。
权限更新使用独立的 `PUT /api/v1/projects/{project}/sessions/{session}/permission`，
请求体只含 `permission_profile`，并要求当前会话的 `If-Match`。先持久化，再发布运行时
权限；写入失败时维持旧权限。客户端会确认丢失的响应，仅在权限字段未变时合并无关的
元数据版本变化。设置在重启后保留。
