## 实现与兼容性边界

宿主始终由当前 `lib/xrt.h` 提供唯一 XRT 实现。该文件和声明头与已提交上游字节一致。xwork 原先通过 xhttp 合并头嵌入的旧实现已退出编译路径，HTTP 客户端改用原生模块；完整与精简配置都从同一组实际声明生成脚本导出。

保留产品已有 xllm、session、xwork API 和上下文治理、工具诊断、文件权限等修复。它们与 xs 通用主干的新扩展 API 不同，直接替换整套 API 会破坏现有产品。因此本次升级基础运行时并移植调用处，没有添加伪装成旧 XRT 的接口层。

新版原生等待和定时器采用相对、有符号毫秒，`xrtTimer()` 采用单调秒。产品现有绝对截止时间继续采用单调微秒，并在原生等待边界转换。新版公元 UTC 毫秒时间转换为产品原有 Unix 微秒，既转换单位，也转换起点。原有会话、事件、账号过期时间、计划任务和模块 ABI 字段含义保持不变。

完整 API 回归曾捕获附件被误清理：新起点与旧 Unix 时间混用使新文件被误判为过期。已同时修正文件元数据转换并重新跑通该回归。计划任务保留亚毫秒余数。

根内原子、禁止覆盖的文件/目录/末级链接移动由 `xsRootRenameNoReplace` 保留。Windows 使用已锚定句柄的 NT 操作；Linux 使用 `renameat2(RENAME_NOREPLACE)`，缺少原语时失败，不退化为检查后覆盖。原生库中不可变结果文件使用根内硬链接原子发布。TLS 代理拨号用当前公开的 Dial/FutureBridge 保留取消和完成引用生命周期。

Linux 嵌入脚本 SDK 补齐当前公共声明需要的数学声明和分类宏，使用既有宿主 libc 实现。未引入外部依赖。

## 已验证

- Windows 与 Linux GCC 构建；精简配置和带 xrudp 的宿主。
- 两平台 560 个扩展导出在外层与嵌套 TCC 可解析；xrudp IPv4/IPv6、固定密钥 Noise 握手、可靠字节/FIN、取消、关闭句柄行为通过。
- 两平台实际条件等待、进程超时、XS 60 ms 定时器、Unix 起点、持久化日历递归、根内文件/目录禁止覆盖移动通过。
- 两平台 HTTP/TLS takeover 空闲生命周期、HTTP 获取边界、模型请求、TLS 代理和计划任务持久化通过。
- Windows mdo 完整 API、模型重试/取消/截止时间/部分输出保护、web_open 重试与 Retry-After、远程回环请求通过。
- Windows 隔离的单文件服务端候选包构建和 Home 独占租约通过。

日志与候选包在 `.build/xrt-upgrade-*` 及 XS 产品宿主检出的 `.build` 中。候选包包含当前工作区其他任务的未提交产品修改，不能视为纯 mdo 提交的发布产物。本轮不发布官网、不替换已安装程序；Android 未重新构建或实机验证。

本次仅完成基础升级。mdo 内嵌 xrudp 适配、打洞/中继切换、Android、真实 NAT 矩阵和 72 小时 soak 仍属于后续长期任务。
