# 0.1.1 安卓完整版更新安装修复

用户反馈多台设备出现“无法安装更新：更新文件路径或大小无效”，并确认下载的是
包含本地工具的完整版。

## 根因

下载及 hash 校验允许最大 512 MiB，但锁定 SDK 中
`android/src/org/xserver/android/PackageInstall.java` 的 `validate()` 仍拒绝
超过 32 MiB 的文件。0.1.1 完整版 APK 为 60,977,998 字节（58.2 MiB），会在
启动系统安装器前被确定性拒绝。轻量版为 4,220,141 字节，不触发这项大小限制。
原错误把路径、文件是否存在、文件大小合并，容易让用户误以为是文件权限问题。

## 修复及发布

mdo 打包器将锁定 SDK 的文件校验块替换为自有 `MdoPackageInstallPolicy`，统一为
512 MiB。初次确认和系统安装前复检调用相同策略；继续规范化文件路径、限定应用
私有目录，并保留 SHA-256、包名、签名、versionCode 和系统安装确认。路径缺失、
越界、文件缺失、空文件和大小超限分别报错。锁定 SDK 校验块改变时构建会失败，
防止静默漏掉 overlay。SDK、native host、C 应用逻辑和本地工具均沿用已经发布的版本。

版本仍为 0.1.1；新构建号使用 30000089（轻量）和 30000090（完整），没有复用
旧编号或已发布 hash。其余六个桌面/服务版文件保持此前的发布字节和构建号。
`mdo-builds.json` 每个产品保留其应用源指纹，新增安卓 Java 策略指纹及独立修订验证。

## 验证

- 实际 Java 文件策略执行 19 项用例，包括已发布完整版精确大小、32 MiB 上下边界、
  512 MiB 边界、空文件/缺失文件、目录、规范路径、相似前缀及软链接越界。
- 实际 SDK 的 PackageInstall overlay 通过 android.jar 编译，验证 SDK 变化时构建拒绝。
  这项验证现已加入每次 Android 构建。
- 两个最终 APK 校验内置修复 DEX、CRC、包名、版本号、非 debuggable、正式签名
  v2/v3、完整工具映射、ELF 依赖及 16 KiB 对齐。
- 公开 HTTPS 完整下载并核对 9 个文件，包括两个模型更新下载对象、两个官网 APK
  和 5 个网站文本文件；核对八条更新通道元数据，确认其余六条未变，源码旧链接 404。
- 没有连接的 ADB 测试设备，未进行本轮真机系统安装和数据保留测试。上一轮发布
  门禁只作为未改动代码/产品的基线，本次修订不声称补做了完整门禁或真机验收。

## 旧版首次升级

旧安装器存在于设备当前 APK 中，服务器无法将其替换。因此仅下载新的完整版仍会
被旧安装器拒绝。请从官网下载修订 30000090 的完整版，直接在系统中覆盖安装，
无需卸载；正式版本签名相同。或者先在应用内更新到轻量版 30000089，再切回完整
版 30000090：轻量版小于 32 MiB，且两次 versionCode 均递增，共用原数据目录。
完成首次升级后，后续应用内完整版更新使用修复后的安装策略。

私有构建、回归及公开验证收据位于
`.build/android-update-size-20261013/`；线上回滚备份位于
`/home/xs/mdo-android-update-size-20261013-30000089/backup/`。
