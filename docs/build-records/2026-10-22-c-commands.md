# C 命令体系实施与回归

2026-10-22，在 `master` 完成开发并分目标提交。版本保持 0.2.4，本轮生成本地测试包，未发布官网或自动更新。
产品源码冻结提交：`fa21385a6fd0d95865102d6674ac5cf955f7a8f3`。

## 实施结果

- 每个命令为独立 `.c` 文件，公开 SDK 为 `include/mdo/command.h`；静态 JSON 元数据、内容修订与类型化 xvalue 数组参数。
- 项目 `.mdo/commands`、个人 `commands`、内置文件依次覆盖；无效、停用覆盖不会回退执行其他来源。发现不执行代码。
- 命令在独立原生 Worker 编译、运行；宿主通过受限 RPC 暴露界面操作、真实会话创建、上下文压缩及现有本机 API。
- 支持取消、截止时间、父进程退出清理、崩溃/编译错误分类、持久化执行记录和不确定提交查询；丢失响应不会重放有副作用的 POST。
- 个人和项目 C 编辑器、启停、版本冲突检查、生态包代码信任确认；结构化结果和待发送草稿不会自动发给模型。
- 旧个人 Markdown 命令保留原文件，迁移为 Skill 与 C 包装命令；原名称可继续使用，删除后不会由备份复活。
- 保留 `/skill:<id>` 与 `$<id>` 手动入口，以及现有模型发现、加载 Skill 的路径。

## 验证中修复的缺陷

分目标提交包括：父进程退出后的 Worker 清理、损坏执行记录不能当作未执行、丢失响应不重放提交、旧命令删除后不复活、MCP 参数校验与项目覆盖、停止命令只作用于捕获的运行、执行状态与编译错误保真、项目编辑器草稿保护。

Android 补查发现旧紧凑库隐藏了 `xsHostRun`，会使独立 Worker 启动失败。兼容补丁仅为 Android 导出嵌入入口，并增加 APK 打包前的动态符号校验；用真实旧库验证拒绝、重编的新库验证通过。未修改其他工作区。
