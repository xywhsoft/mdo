# 整轮对话操作与主要回复复制

用户要求：中间进度和工具调用之间的模型输出不再各带复制、分叉、重试按钮。整轮结束后，统一操作整轮；复制主要回复，避免复制到回答后的记忆保存提示。

## 实现

- 新增整轮操作目标投影，按用户输入组织所有执行及继续执行记录。在主 Agent 的整轮终止事件到达前不显示操作栏，单个 `model_done` 不算整轮完成。成功、停止、失败均属于已结束状态，允许后续分叉或重试；继续执行期间再次隐藏该轮操作栏。
- 每轮末尾仅有一组操作：复制主要回复、从整轮结束处分叉、按原始用户消息重试。原始用户消息的复制和编辑保留。代码块及展开的工具原始内容仍有其独立复制能力。
- 复制通过原有全文读取/截断恢复逻辑获取目标正文。分叉沿用整轮的历史边界；重试沿用原始输入、图片和来源事件 ID，不将中间进度当成新的输入。无法证明的来源不补造操作目标；归档、回收站及成员只读历史不开放修改操作。
- 子 Agent、明确的系统压缩输出不能成为主要回复。压缩阶段的流采用独立键，避免与同一次数的正常模型输出拼接，也避免内部摘要挤掉主回复。
- 用户确认的“主回复之后保存记忆，再补一句完成提示”场景，根据明确的记忆文件调用判断：尾段仅有作用于 `@memory-global/` 或 `@memory-project/` 的文件操作，且包含 `write/edit` 时，复制进入该尾段前的公开回复。末尾保存提示仍显示，但不作为复制目标。仅读取记忆、混合工作区路径、截断参数、shell 命令不作此判断；旧记忆操作也不会捕获后续新执行的正常回复。
- 新操作说明覆盖简体中文、英语、俄语，沿用现有可扩展语言字典。

识别边界：当前普通 Agent 的输出没有统一的“主要回复”语义字段，因此上述规则依赖确定的事件与记忆调用边界，不依据“记忆”等正文关键词或文本长度判断。没有明确维护调用的普通回复、同段混写的业务结论与维护说明，仍作为普通完整回复处理；不会擅自从正文删句。规则不是对任意自然语言的百分之百语义识别。

功能提交：`82e4604b`。

## 验证

- 108 项时间线、整轮操作、继续执行、工具分组、文件变更和多语言回归通过。
- 新增真实浏览器用例 `tests/test_turn_actions_browser.py`，三种语言 × 1400px/390px 共六组通过。验证运行中无操作栏、完成后一组操作、复制接口接收到主回复而非记忆提示、分叉/重试目标、继续执行期间隐藏、系统摘要排除、只读状态仅可复制、失败轮次恢复和多轮独立边界。
- 原工具分组浏览器回归同样六组通过，保留分组开合、焦点、文本选择和流式节点稳定性。
- 原生服务 `tests/test_stopped_message_edit.py` 通过，确认上轮“停止后编辑重发、消息立即上屏、元数据更新、丢失响应确认、真实历史冲突保护”的修复不受影响。
- 268 个前端模块解析并连通，差异空白检查通过。已检查桌面和窄屏截图。

证据位于 `.build/turn-actions-browser/`、`.build/tool-call-groups/` 和 `.build/stopped-message-edit-qa/`。未复制 app/SDK，未创建 worktree，未修改版本号、打包或发布线上。
