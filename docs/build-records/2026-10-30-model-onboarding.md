# 四步添加模型与卡片简化验收

## 最终行为

1. 填写 API Key。API 产品、套餐说明和文档链接保留；供应商与新模型代理集中在同一个默认收起的高级设置，供应商在上、新模型在下，模型默认跟随供应商。
2. 自动获取 / 手动填写使用页签。进入自动页签立即获取目录；可直接切换手动填写，支持换行、逗号及分号分隔模型 ID，并去重。过时请求取消，手动输入保留。
3. 搜索和勾选模型，自动复用供应商参数，只向公开目录补查缺项。API 声明和用户明确填写的字段优先，不猜必要参数。预算按合并后的实际限制计算，避免公开目录较大限制覆盖供应商较小限制。
4. 添加并验证。后端使用未发布的临时模型目录执行生产流式传输与原生工具 schema 验证，通过后才保存这一模型及所需凭据。部分失败只保留失败/未处理项，成功项不再请求。用户可停止；已成功提交项保留。纯文本模型不会成为 Agent 默认模型。

卡片显示上下文、输出预算和思考选择；只保留一个“验证”入口，“高级编辑”改为“编辑”，“模型参数”改为文字链接。三种语言均补齐。

新增 `POST /api/v1/models/add` 复用有界后台工作池和设置事务，要求 ETag，提交前检查配置、工具定义和连接状态；验证期间阻止破坏性清理穿过事务。已有供应商不能在添加模型时被替换凭据。失败/取消不安装模型、供应商或 Key；回包不确定时先回读，避免自动重复计费请求。详见 [模型设置](../model-settings.md)。
