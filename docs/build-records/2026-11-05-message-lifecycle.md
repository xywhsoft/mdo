# 消息提交、停止与编辑生命周期整治

范围：准备阶段停止后消息不可编辑、旧气泡落在新回复之后，以及相关的队列、历史接管、刷新恢复和编辑重发竞态。版本保持 **0.9.2**，本轮不发布、不替换用户正在使用的安装目录。

## 根因

1. 临时消息与正式历史分别渲染，旧的临时气泡一直追加在历史之后；只看当前已加载的 `agent_start` 去重，翻页和迟到状态容易留下残影。
2. 停止主要面向已有运行，准备阶段尚未发布运行 ID 时没有可取消的稳定对象；迟到的入队/启动请求仍可能继续。
3. 原生运行已受理不等于输入已进入正式历史。原流程会过早删除队列原文，使“受理到 Agent Start”之间的停止无法恢复编辑。
4. 编辑重发原先先截断历史、再单独保存并提交替代输入，中间有缺口。部分编辑入口又把已交给历史但尚未清理的队列副本当成待发送，拒绝操作。
5. 迟到的非终态读数可以盖过停止状态；停止确认稍晚返回时，也可能在用户已输入并发送下一条消息后自动恢复旧输入。

## 实现

- 消息从草稿、待发送、准备、原生运行到正式历史共用提交 ID；重复点击与丢失响应均按该 ID 核对。
- 新增统一的提交状态模型与协调器。准备、停止中、已停止、待确认、失败和编辑暂存都有明确状态。刷新/核对只读，不因不确定而盲目重发。
- 临时消息加入正式时间线，以进入时的事件锚点固定位置。迟到的取消确认不会把旧输入挪到后来的回复下面；重新加载的已停止输入使用服务端保存的锚点。
- 新增精确取消端点 `POST .../queue/{id}/cancel`。取消标记在运行创建前持久化；原生管理器在打开/准备会话前发布可取消的运行 ID。迟到的相同 ID 请求被拒绝。
- 队列直到匹配的根 Agent Start 输入真正写入事件历史才释放原文；以收据缓存对应事件 ID，避免后续轮询重复扫描大历史。当前历史分页未覆盖该输入时，也不会一直显示“准备中”。
- 未执行的输入停止后保留正文、附件和会话配置。空草稿且停止期间没有新的本地编辑时可自动恢复；有其他草稿、或用户已开始下一条输入时，保留一个可编辑/移除的已停止条目。显式编辑不会覆盖正在输入的草稿。
- 执行过的输入归正式历史管理，不复制成第二条输入。编辑入口也按历史中的提交 ID 排除尚未清理的队列副本。
- 同一运行的已确认取消/终止事实保持单调，迟到的旧读数不能恢复成执行中。停止请求在历史接管后仍继续完成，不随临时气泡移除而放弃。
- 编辑重发改为一次产品操作：先保存不可自动执行的替代输入，再按原历史令牌截断，最后释放该输入。相同编辑 ID 不允许替换成另一个正文；丢失成功响应后核对已有队列/收据，不重复启动。
- 标题更新等同一路由刷新不关闭正在使用的编辑器。状态栏和发送/停止按钮同步显示当前生命周期。
- 新文字包含简体中文、英语和俄语。

## 持久化与中断边界

取消标记与队列收据均位于会话的 Home 相对路径内，已接入备份校验与输入归属判断。只在生命周期转换时记录，不恢复逐 token 的流式落盘。

历史截断、队列文件和模型启动不是跨文件数据库事务。若进程恰在历史更新后、替代输入释放前崩溃，`hold_for_edit` 会保留原文并阻止自动执行；用户可停止/恢复编辑后显式重发。系统不会在不确定历史上自动再次截断。

本报告取代 [早先停止后编辑报告](2026-11-05-stopped-message-edit.md) 中“截断与随后入队分成两个客户端步骤”的现状说明；历史记录本身保留。
