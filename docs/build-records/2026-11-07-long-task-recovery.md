# 可配置重试与长任务恢复

本轮只实现、构建和本机验证；不发布、不修改版本号、不替换 E 盘用户程序，不调用生产账号或付费模型。

## 变更

详见 [长任务恢复](../long-task-recovery.md)。此前账号中断检查记录是修复前行为快照；其中固定十次、十五分钟总窗口、续期耗尽清凭据、权限五分钟超时等描述已由本轮实现取代。

实际联合回归另外发现并修复：低频等待时间污染恢复后的正常退避；同账号重新登录没有及时唤醒旧任务；短写后使用 append-only 句柄回滚失败；必需回调等待中取消被误报为一般错误。显示事件的故障注入确实写入了七个字节后返回失败，再验证尾部修复及事件唯一性。
工具钩子的恢复还需要避开已持有的串行事件锁，已有原生持锁回归和实际 C 工具前置回调重试回归。MCP 回归补充了失效绑定不得换账号、同一 Agent 可使用重新连通的服务、恢复后警告清理。持续存储故障中停止也明确验证为取消，不误报为 IO 失败。

XRT 的通用改动在 master 分阶段提交，最终引用 `a01b4a13f0c1b82e4a428236800230671bcbd6aa`。mdo 将三个配套库一起机械导出到锁定宿主，保留原核心和宿主基线。独立 XS 仓库尝试的单库更新因缺少配套 ABI 无法编译，已撤回该尝试、恢复其原有源码内容；没有留下半套更新。mdo 的完整配套 SDK 已实际编译运行。

- XRT xwork 全量原生回归：条件探测、等待中取消、检查点恢复、工具执行后 OOM 不重放、原有工具/压缩/恢复行为。
- xllm-session 全量原生回归：标题补齐保留候选全文并重新过质量门槛；不允许给不足的摘要填充文字蒙混通过。
- `test_recovery_policy_runtime.py`：默认/自定义次数、耗尽后保留、取消、明确截止、有限探针、配置及余额条件唤醒、条件未变时不重试；连续签发新凭据不能绕过实际模型 401 的重试上限。
