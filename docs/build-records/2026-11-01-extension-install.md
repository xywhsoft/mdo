# 扩展商店后台安装与外部工具修复（2026-11-01）

## 行为

九类商店共用一次“信任并安装扩展”公共弹窗。确认后使用现有 Application SDK 独立操作加入全局下载任务，自动下载、校验、解压、事务提交与运行时加载。列表及详情的安装按钮显示旋转圆环，最终显示成功或失败；失败可查看实际原因并重新确认后重试。关闭详情、设置页或下载窗口不会取消已接纳的操作。

页面刷新以保存的 SDK 操作 ID 查询原操作，不自动重放安装请求。切换设备隔离状态；取消通过原生操作传递。下载任务合并显示整组安装与其归档进度，避免重复条目。完整回执缺失时保留“状态待确认”，运行时加载失败不会误报安装成功。

首装推荐仍只是普通外部工具的批量入口，也使用一次信任确认；已安装的相同版本复用并启用，其余加入各自下载任务。Android 保留完整版 APK 预制程序策略。

## 已确认的问题

1. 下载或整组安装失败后统一调用取消清理，真实错误被替换为 `cancelled`。改为持久化 `failed`、原始错误和实际传输字节，清理归档后仍保留收据；用户主动取消不被后续失败覆盖。
2. 推荐工具请求目录 `limit=200`，超过平台允许的 100；同时混淆逻辑 ID 和物理目录 ID。已修正。
3. 多个已确认计划排队时，前一安装产生的无关状态变化会使后一计划的全局状态指纹过期。提交前仅重新验证无关变化，保持原计划 ID、批准版本、哈希、目标目录指纹、启停意图和受影响依赖用户不变；目标实际被修改仍拒绝。
4. 同时安装多项会超过三个归档传输槽位。后台下载现在可取消地等待槽位，不增加并发上限；参数、存储和字节配额错误仍立即失败。
5. SDK 路由仍将已支持原生回复的生态接口转回旧 HTTP 队列，七个安装虽被 SDK 接纳，部分随后因旧三任务队列返回 `ecosystem_busy` 而失败。取消该过时回退，直接由既有 SDK 工作线程调用，同时把原始调用的取消信号传给产品接口。普通 HTTP 接口的并发限制不变；元数据读取不再排在 SDK 安装之后。
6. 实际平台读取中捕获一次原生 HTTP 连接失败。仅为幂等 GET 的连接失败或 408/502/503/504 加入最多两次短退避重试，取消可及时中止。提交、鉴权、重定向、哈希/ZIP 校验失败不自动重试。

用户运行目录 `E:/software/mdo` 原有两次 7-Zip 任务只保留了取消收据，无法从旧收据还原当时的底层错误；清理后的 0 字节不能证明从未下载。当前同一公开版本已经在该目录完成安装并启用，`runtime_ready=true`，没有修改账号与会话数据。不能据此将历史失败归因于某个未经证实的网络或平台故障。
