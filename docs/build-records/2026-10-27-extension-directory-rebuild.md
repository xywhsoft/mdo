# 九类扩展目录重构实施记录

目标以 `docs/extension-archive-design.md` 为准。单线程、主分支、小阶段提交；不创建仓库或大运行时副本。不保留旧发布格式、目录和版本兼容分支。

## 阶段一：共用路径和标准 ZIP（已验证）

- 新增九类类型及目录路径规则，安装名称可使用 XID，普通文件允许隐藏路径。
- 新增基于 xrt 文件/压缩/CRC/SHA 的原生 ZIP 读写；Store/Deflate、流式解压、空文件/目录、UTF-8、权限和标准数据描述符。
- Unicode 文件及父目录冲突检查采用生成的统一映射；限制大小、条目数量和路径，拒绝越界、重名、链接、设备名、重叠和校验失败。
- 原生回归使用现有 `127.0.0.1:58013` XS/TCC；临时 C 命令按摘要清理，没有模型或供应商请求。Python 标准库 ZIP 用于独立互操作核对。
- 28 个标准/异常归档用例、九类目录契约，以及原生写入后由原生和 Python 分别解压核对全部通过，包含 1200 个文件、ZIP64 本地扩展字段和 Unicode 父目录冲突。

后续阶段：目录登记/事务和 SDK → 九类发现、编辑及执行 → 平台、创作中心及官方 ZIP → 全链路及平台回归、上线。以上后续工作尚未完成，不以 ZIP 基础能力通过代替整个任务完成。

## 阶段二前置：目录根清单（已验证）

- 增加小型 `extension.json` 契约：类别、显示名称、调用别名、相对入口和平台；安装标识不再由调用名称承担。
- ZIP 根必须直接包含清单；拒绝旧 JSON 包字段、旧分类、外层 payload 包装及缺失的声明文件。
- 原生用例扩展至 44 项，覆盖九类清单和错误声明，标准 ZIP 双向互操作继续通过。

原有 `app/xs.json` 和 XRUDP 测试改动保留。阶段一回归证据在 `.build/extension-zip-native/native-result.json`。

## 阶段二：共用目录存储与事务（已完成原生单元验证，尚待运行时接线）

- 新增 `extensions/manager.c`：九类物理目录枚举、清单与相对入口、XID/别名分离、目录内容摘要及整目录 ZIP 导出。
- 安装先解压到宿主任务目录，逐文件校验，再替换唯一的 类型/标识 目录；卸载删除完整目录。事务日志只含路径身份、阶段及原登记，不含文件内容。
- 更新保留启停状态，清理旧目录中不再存在的文件；源码辅助文件也参与摘要。商店来源不能重新导出，实际文件修改后不能通过执行前校验或重新启用。
- 原生测试对九类分别执行安装、更新和完整卸载，覆盖代码许可、XID 大小写别名保护、损坏更新不破坏旧目录、prepared 安装/卸载恢复、首次安装回滚、committed 只清理及非法日志不影响目录外文件。
- 测试只创建项目内的小型文件系统夹具，并在结束后删除；复用现有 XS/TCC，不创建新的应用部署。收据在 `.build/extension-directory-native/native-result.json`。
- 九类实际运行时、API、SDK、平台、前端及官方工具包接线尚未完成；此阶段通过不代表发布链路已完成。

## 阶段三之一：SDK 资源根、内置目录和编辑器命令执行（已验证）

- 在 Home 初始化后执行共用目录事务恢复和内置 ZIP 安装。内置命令转换为各自目录，构建时从目录生成标准 ZIP；单独的首次安装收据保证卸载、停用后重启不复活。
- SDK 增加 extension.current/list/read/fingerprint、extension 资源空间及宿主绑定的类别、物理目录 ID、原生资源根。调用别名与安装目录分开；设备状态仍通过 storage.* 保存在 data 下。
- 命令只发现 Home/commands/目录，不再扫描散文件、项目命令目录或自动迁移旧命令。相同别名冲突时阻止调用，项目配置只决定是否启用。
- 命令生命周期持有共用目录租约，运行时拒绝替换/删除；编译后、调用前复核整个目录摘要，辅助文件也参与判断。
- 原生实测发现 XS 子进程的编译器不能直接读取工作目录之外的 include 路径，已使用专用 VFS 映射源目录，支持根部及嵌套入口旁的头文件。mdo_command_context_v1 提供资源根及物理目录 ID。
- 完整应用通过原生编译、重定位。九类存储回归仍通过；命令目录测试实际运行 C 代码并验证头文件变更使结果从 17 变为 29；实际命令子进程验证两个位置的头文件和资源读取，以及编译期间内容变化时拒绝调用。
- 内置 ZIP 原生测试验证 11 个命令和两个 Skill 安装目录、完整性、卸载与停用后重新初始化不复活。证据分别在 .build/command-directory-native、command-worker-directory、builtin-directory-native、extension-directory-native。

剩余：其他八类运行时和全部管理/发布 API、客户端 UI、平台/创作中心/后台、官方外部工具归档、跨平台及端到端验收。生产尚未切换。

## 阶段三之二：Agent、SubAgent、Agent 工具目录运行时（已验证）

- 三类只从 Home 的独立扩展目录发现入口，可包含配置与原生 C 入口；原 modules/agents、modules/subagents、modules/tools 和散文件不参与发现。默认 Agent 也合入单一目录。
- 原生编译提供入口所在目录及扩展根的 include 路径，SDK 回调绑定物理目录与资源根；整个目录摘要参与编译标识，编译前后核对实际内容。
- 角色配置的 prompt_file、上下文附件及继承分别保留所属目录。配置与 C 角色只有位于同一扩展目录时才能组合，停用会同时移除二者。
- 已加载的代际持有目录租约，SDK 回调、工具及角色引用释放后才允许移除目录。
- 新增不启动应用的原生产品测试：使用当前完整 unity 源码及实际 Home/模块/SDK 实现，只为小型夹具挂接文件根。实际执行 Agent 工具、主 Agent 与 SubAgent 的 C 回调，验证资源读取、目录身份、父子上下文来源、辅助头文件修改后从 17 改为 29、整体停用和释放运行时后的卸载。
- 当前完整应用原生编译通过；三类上述运行回归全部通过，证据在 .build/module-directory-native/result.json。未调用模型或供应商。

本阶段只完成运行时；三类编辑/发布管理接口与前端仍需统一，其他五类运行时及平台链路继续实施，尚未上线。

## 阶段三之三：Skill 与知识库目录运行时（已验证）

- Skill 从共用清单读取物理 XID、调用别名和入口，支持非 SKILL.md 文件名；资源根直接返回已安装目录，删除内置 Skill 另行释放内容缓存目录的旧机制。
- 去掉自动项目/祖先/第三方 Skill 扫描及旧组合包别名登记。项目配置只筛选 Home 已安装条目；单独的来源预览接口保留为显式导入用途。
- 共用目录文件索引与 SDK extension.files 支持隐藏、空文件和深层路径；Skill 的按需资源读取沿用此索引，模型响应的文件清单限制数量与字节并标明截断，避免大量文件撑爆结果。
- Skill 的校验、读取及参数目录替换按物理目录解析；停用后旧的缓存目录引用也不能继续加载内容。
- 知识库从共用清单读取入口并检查安装来源完整性，提示路径对应实际物理 XID；索引路径使用共用便携路径规则，支持隐藏及深层目录。无效索引仍汇入统一警告。
- 实际产品原生测试通过：XID 与别名分离、定制入口、Skill 校验/正文/资源根、隐藏和 12 层文档、第三方项目目录不自动发现、项目筛选、停用后阻止缓存读取、知识库提示/停用/警告及整目录卸载。证据在 .build/reference-directory-native/result.json。

## 阶段三之四：MCP 目录服务及私有连接运行时（已验证）

- MCP 模板与程序依赖位于 mcp/物理目录，连接值和确认记录位于 data/mcp/connections；同一扩展可创建多个独立连接，不把模板副本和私有值存入可发布目录。
- 删除 mcp/id.json 与项目 .mdo/mcp 的运行时扫描。项目范围从私有连接的 project_id 筛选，安装目录统一。
- 模板支持相对程序、相对工作目录及 {$path}；宿主加入目录 ID、根路径、摘要环境变量。可执行内容与凭据仍分别需要明确批准和有效引用，模板不能注入宿主保留变量。
- 启用连接绑定整个目录的确认摘要；更新后需重新确认启动/目标，旧凭据不因新模板而自动发送。stdio 运行配置包含目录摘要，避免辅助文件改变后复用旧进程。
- 已核对锁定 xwork 实现：替换来源会拒绝活动请求，并同步终止退役连接和进程；代际目录租约在旧目录停止使用前保留。
- 原生测试编译约几十 KiB 的真实 MCP 测试程序（不复制运行时），验证初始化、资源协议交互、两个连接的不同私有参数、附属文件与 cwd、目录变更后的重新确认和重连、运行目录保护、关闭后的完整卸载。
- 原生打包生成的 ZIP 由 Python 独立校验，根部直接包含清单、模板、bin/server.exe、源码和 support；逐文件检查未含连接私有值、测试凭据或凭据引用。证据在 .build/mcp-directory-native/result.json 和 exported-mcp.zip。

MCP 管理 API、客户端表单、发布/下载和平台仍待切换；外部工具、插件运行时及整体验收也未完成。不能据此宣布整轮任务完成或发布半成品。

## 阶段三之六：插件目录、覆盖和运行中的文件保护（已验证）

- 插件从 plugins/物理目录读取 extension.json 与 plugin.json，直接使用同目录的原生入口、前端入口及覆盖源文件；不再发现或生成永久 revisions/hash/files。虚拟前端地址仍带内容摘要用于缓存隔离，但不对应额外实体目录。
- 安装身份、显示元数据与运行配方分开；互斥标记、依赖存在/启停及循环、覆盖目标冲突继续校验，删除插件版本区间和历史修订切换。插件组合只保存当前安装身份和启停状态。
- 启停组合由共用扩展状态一次原子写入。有效视图独立持有目录租约，前端未确认清理或原生代码仍在使用时不释放目录；原生代码改动需要完整重启，普通模块重载不会重复注册同一插件的新旧代码。
- 原生模块的 SDK 上下文绑定插件实际目录，整个目录摘要参与编译。物理 XID 与 plugin.<别名> 的模块标识分开。
- 产品原生测试实际执行插件 C 回调、包含本目录头文件、读资源并覆盖 VFS 文件，检查版权归属和互斥，生成标准 ZIP（含隐藏空目录）；运行中删除被阻止，辅助文件变化拒绝热重载，重启后结果从 17 变为 29，前端清理确认后才可卸载，重启不复活。证据在 .build/plugin-directory-native/result.json。

## 阶段四之一：共用创作与整目录导入基础（已验证）

- 提供共用新建、显式本地目录导入与带整目录摘要前提的文件编辑接口。新建先在任务区准备清单与入口，再整体提交，并保持停用；C 等可执行内容须明确批准。
- 本地导入锚定所选目录，先检查根部 extension.json，将所有实际文件与空目录流式写入普通 ZIP，再使用共用安装事务解压到唯一安装目录。导入前后复核全部来源，隐藏文件与依赖不被漏掉，链接/路径冲突拒绝导入。
- 编辑只允许空闲的手工作品，拒绝商店/内置来源、摘要已变化、已加载租约及破坏清单入口的操作；使用同一便携路径和 Unicode 冲突规则，支持隐藏/深层资源。
- SDK 增加 extension.create/import/pack/install 和 extension.file.write/mkdir/move/remove；归档返回路径、大小与 SHA-256，不把作品编码成 JSON 文件容器。上述属于存储层接口，运行时暂停/重载协调及 HTTP/界面接入仍须完成。
- 新增原生产品测试验证批准、新建停用、深层写入、旧摘要保存拒绝、入口保护、运行中文件保护、整目录导入、完整资源、安装身份前提、更新与卸载，以及实际 SDK 创建与 ZIP 路径返回。证据在 .build/extension-authoring-native/result.json。
- 九类目录事务回归重新通过。随着测试源码超过现有验收宿主的 128 KiB 单命令限制，测试驱动改用小型源码夹具由现有编译器读取；未复制运行时、创建服务或放宽生产命令限制。

## 阶段四之二：运行时协调、延迟卸载与修复入口（已验证）

- 新增共用管理协调层，串行执行多管理器变更：先停用并刷新所属运行时，确认租约释放后才替换、编辑或删除目录；失败时恢复原启用状态。已完成安装但运行配置加载失败时返回明确 runtime_error，并保持停用，不把已完成的文件操作伪装成可盲目重试的失败。
- SDK 的创建、导入、安装及文件编辑转入此协调层，新增 extension.enable/remove/cancel_remove。商店替换只接受宿主核验的来源，不能借手工导入覆盖商店归属。
- 活动原生插件卸载返回 removed=false、pending_remove=true、restart_required=true，持久化内容摘要和停用状态；启动恢复时完成整目录卸载。等待期间目录改变则保留目录并发出统一警告，可取消或重新申请卸载。
- MCP 卸载实测先退役连接进程，再移除完整目录及其私有连接文件；共享凭据仓库不做猜测性删除。其他连接不受影响。
- 损坏扩展的列表仍保留来源与停用状态；手工作品的无效清单/缺失入口可以通过带摘要前提的修复操作恢复，不能因清单已损坏就陷入永久无法编辑。
- 插件、MCP、创作与九类目录事务原生回归通过。新增覆盖真实进程与连接退役、原生插件延迟卸载/重启恢复、内容变化不误删、取消待卸载、SDK 修复损坏清单以及统一警告。现有通知聚合测试、外部工具真实执行回归和完整应用编译也通过。

仍未部署。下一步必须替换旧 HTTP 管理/JSON 分发接口、完成二进制任务和全部客户端/平台页面；Android 预置程序、官方作品转换及最终全链路/跨平台验收仍在待办中。

## 阶段四之三：原始二进制归档任务与 SDK 文件传输（已验证）

- 增加共用归档暂存任务，JSON 收据仅记录身份、大小、摘要、状态及少量显示信息，实际文件为 archive.part/zip。每片上限 1 MiB、每包 512 MiB、最多三个活动任务、暂存预留总量 1 GiB，支持过期清理与显式清理。
- 写入按磁盘实际长度恢复；重复分片逐字节核对，冲突拒绝，进程停在分片中途时可以补齐匹配前缀的剩余部分，不把未收到的字节计作完成。
- 封存核对总大小、SHA-256、全部 ZIP 条目 CRC/解压限制及根部清单，拒绝旧 JSON 包；真实 ZIP 可以直接进入统一目录安装。安装完成释放临时归档，保留小型任务收据。
