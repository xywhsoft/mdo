# 2026-10-20 IPv6 / IPv4 并行探测测试版

原实现已有双协议族端点，但 IPv6 主机候选仍等待 STUN/DNS，IPv4 原生握手还受会话开始时的优先窗口约束。本次将探测、Noise 握手与最终选路分开：两个协议族独立推进；IPv6 有公网主机地址时直接发布候选，不等待 STUN 的 AAAA 查询或 UDP 回复。ULA-only 网络继续保留原有映射发现，显式数值 STUN 配置也保持有效。

两个协议族均可立即执行认证检查和 Noise。IPv6 握手完成即可选定；IPv4 先完成且 IPv6 尚在尝试时，最多再给 IPv6 250 ms，随后使用已经就绪的 IPv4。总启动期限仍为 10 秒，不因 DNS、重复信令或另一协议族而重置。最终方向/协议族仍由控制端选定并由目标确认；落选端点关闭，业务授权及写入不重放规则不变。

候选列表仍按原协议限额限制为每族四项；IPv6 全局地址优先于虚拟网卡 ULA，避免先枚举的虚拟网卡挤掉实际公网候选。未改动 v2 信令格式、账户协议或 XRUDP 库/SDK。

## 验证

- Windows 原生运行时：正常及反向握手、IPv4/IPv6、双栈选择、分别屏蔽一个协议族、两族都屏蔽时固定期限、单栈及绑定失败降级、取消和端点归零通过。
- 新增 IPv4 STUN 无响应时 IPv6 提前连接，以及 IPv6 映射无响应时 IPv4 提前连接；均验证另一族的映射尚在 pending 时已成功选路及双向加密传输。新增多网卡候选排序回归。
- Linux ASan/UBSan/泄漏检查的完整原生协商回归通过；最终构建源复验记录在私有构建目录。
- 隔离账号站点的双栈真实远控业务回归分别屏蔽 IPv4/IPv6：HTTP、实时订阅、只读拒绝、一次性 offer、写入回执、取消后中继可用及登出清理均通过。未对真实账号或公司项目写入数据，没有模型调用。
- 前端认证信令、启动超时、直连选择、取消/迟到回调、中继回退及写入不重放回归通过。

线上 `xrudp-stun.service` 为 active，UDP 3478 同时监听 IPv4 `0.0.0.0` 与 IPv6 `[::]`；现有中继已支持本次未变的双栈信令，无需替换或重启线上服务。

本机检查时仅有 `fe80::` 链路本地 IPv6 与 `::1`，没有 `::/0` 默认路由。该网络状态无法验证公司至家用电脑的公网 IPv6 直连；测试版不会凭空提供公网 IPv6，需要家用宽带、路由器及终端实际获得可用 IPv6。跨电脑成功率仍待用户在实际网络复测。

构建从本次提交冻结源码，排除工作区其他任务的未提交修改；版本为 0.2.0，Windows 测试 build 为 30000101，账号服务仍为正式域名。未发布官网下载或自动更新。交付包与实际 EXE 的启动、哈希、ZIP 核对结果在后续构建收据中记录。
