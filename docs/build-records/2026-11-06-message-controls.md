# 首条消息与普通消息统一操作

按用户 2026-11-06 的补充要求：首条消息不提供独立的编辑、停止、移除或取消重发按钮；停止只使用输入框的停止按钮，确认停止后才允许编辑。

## 修改

- 删除临时回复下方的文字操作按钮及样式，停止等待中的编辑重发同样使用输入框停止。
- 提取 `message-actions.js`，正式消息与准备中的消息复用复制/编辑图标、按钮结构、提示文字和触摸尺寸。
- 消息处理、准备及停止确认期间不显示编辑图标；停止后留在原位置，显示普通编辑图标。编辑仍使用已有的同一个行内编辑器、参数展开和保存/取消流程。
- 停止不再自动把输入搬回输入框，不覆盖后续输入；取消编辑保留原消息。对尚未执行的输入，先保存编辑稿，再移除旧的非执行输入，接入正常发送流程。正式历史的编辑继续使用原有历史令牌和边界校验。
- 已停止并已在聊天中展示的输入不再单独触发“队列已暂停／移除待发送消息”面板；真正尚未发送的队列仍保留原有管理入口。
- 去掉已不再需要的自动恢复草稿逻辑和编辑代数计数。

此规则取代 [前一轮生命周期记录](2026-11-05-message-lifecycle.md) 中关于“停止后自动恢复空草稿”和独立移除按钮的交互说明；取消围栏、防重复执行、原文/附件保留和时间线顺序保护继续保留。

## 验证

- 相关前端测试 **373/373**，前端模块图 **271** 个模块连通。
- 实际 Edge + 原生服务：首条消息准备阶段只有输入框停止；停止完成后才有编辑图标，使用同一行内编辑器重发成功；输入不会自动移回输入框，无残留队列面板；原文、顺序、防重放和刷新后状态均验证。
- 原生 Agent 已受理但仍阻塞在准备回调时，同一停止入口可取消；取消的输入没有调用模型。停止后的编辑取消、重新加载和手机宽度检查通过。
- 普通正式历史消息：执行中停止、编辑重发、丢失截断响应、标题变化、真正历史冲突和输入保留均通过；待重发的取消入口已切换为输入框停止。
- 模型均为离线回调或回环测试模型；没有调用用户账号和计费模型。本轮没有 Android 真机测试。
