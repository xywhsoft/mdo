# 登录续期恢复修复与任务中断路径检查

范围：0.9.4 主线源码及 deps.lock 固定的 xwork/xllm-session；本次只修复账号恢复，不发布客户端、不变更版本号、不修改线上账号或服务。

## 已复现的缺口

1. `account/session.c` 遇到一次续期 HTTP 401 就调用 ClearTokens，删掉刷新凭据和在线目录。Profile 仍保留，因此界面能显示用户信息，但任务已经没有续期条件。原模型重试覆盖了模型端 401，没有覆盖此处的提前清理。真实 HTTP/TCC/Agent 测试在旧代码上失败，修复后成功。
2. `models/completion.inc.c` 要求 login_required 同时具有 HTTP 401 才恢复；明确的同名业务错误以 403 返回时直接失败。新增实际 HTTP 测试复现并修复；保留原 HTTP 状态，仅向账号授权管理器提交凭据拒绝信号。
3. `models/online_access.inc.c` 在取令牌失败、随后查询账号状态又已 ready 的竞态中，生成不可重试 login_required。新增授权回调场景复现；现在保留可恢复状态，只有明确 signed_out 才要求人工登录。

没有取得截图所对应客户的原始运行事件，不能断言其具体 HTTP 状态或重试次数；以上是当前产品代码中实际复现、可产生相同中断的缺口。

## 修复后的行为

- 续期 401 保留同一个账号的刷新凭据，停止使用被拒绝的旧访问令牌，按退避等待恢复；初次失败后最多十次恢复，成功清零连续失败计数。
- 模型调用的网络/认证恢复继续共享原来的十次恢复机会和 15 分钟恢复窗口，不为每一层套十次模型请求；调用方取消、截止时间优先。
- 同一时刻的刷新仍合并给账号工作线程。最终失效清理凭据；明确 410 失效不盲目重试。退出、切换账号仍取消旧账号的任务，不能借新账号继续执行旧请求。
- 重试仍在原任务中，不要求点击“继续”；不重跑已完成工具，不向会话追加临时最终错误。
- 纯流式调用已经交付数据、回调明确拒绝时，仍按既有边界处理，不能保证无条件重放。

## 验证

全部使用本机回环合成账号与模型，不调用生产模型，不保存真实密钥。

- `test_account_recovery_runtime.py`：新增发布门禁入口，运行下列五组测试，防止专项测试再次漏出发布检查。
- 授权适配器 18 场景：续期、二次失效、共享预算、403/login_required、取令牌与 ready 竞态、十次耗尽、成功重置、业务拒绝、取消、截止、流式输出、钩子拒绝。
- 实际账号工作线程 11 场景：后台恢复、初始等待、临时故障、退出与账号切换隔离、截止时间、明确 410 撤销。
- 实际工具型 Agent：503 恢复、连续两次续期 401 后恢复、持续续期 401 最终耗尽；前两种均完成两轮任务且工具结果只有一份，无人工继续请求。
- 持续 401：账号续期合计 11 次（初次加十次恢复）；任务有十次等待/再试事件对，最终仅一个错误。
- 原生 xadmin 账号回归：加密/临时凭据、离线重启、丢失续期响应、登录/退出/切换、PKCE、搜索等待。
- 模型重试运行回归、模型契约检查、三次登录启动恢复回归均通过。

本轮收据位于 `.build/auth-*-after.json`、`.build/auth-worker-exhausted.json` 和对应回归日志。

## 当前会结束运行的路径

以下按可观察行为归并全部已检查的结束边界，重复的底层错误合并列示。每个来源都可能带有不同诊断文本；自定义 C/插件还可以主动返回任意错误。

| 分类 | 条件 | 现有处理与最终结果 |
| --- | --- | --- |
| 账号 | 暂时续期失败、访问令牌失效、暂取不到凭据 | 本次补齐自动恢复；十次机会或时间预算用尽仍会结束当前运行 |
| 账号 | 未登录、刷新凭据最终不可用、明确 410 撤销 | 需要重新登录；不能凭空恢复账号 |
| 账号 | 用户退出或切换账号 | 取消旧账号绑定的正在执行请求，不能自动换身份续跑 |
| 模型连接 | DNS、连接/TLS、代理连接、网络中断、408/504、普通 5xx、429 | 自动退避，通常初次加十次恢复；较长 Retry-After、调用截止或 15 分钟窗口可能先耗尽 |
| 模型输出 | 不完整/无效协议、空回复、只有思考、输出上限截断工具调用 | Agent 可丢弃未提交草稿并修复，最多十次；仍无有效回复则结束 |
| 已交付输出 | 非可重启调用已经返回内容，或回调明确拒绝继续 | 为避免重复交付不盲目重放，可能立即结束；Agent 草稿可重启边界不同 |
| 业务额度 | 余额不足、每日 Token/消费上限、账户请求/消费配额 | 明确业务拒绝不进行网络式重试，需要资金/额度变化或换模型 |
| 供应商 | 上游配额用尽、上游凭据/套餐/权限无效、会员不包含模型、账户受限 | 明确业务错误结束，不能通过刷新 mdo 账号修复 |
| 请求配置 | API Key/secret_ref 不可用、协议/地址/代理配置错误、系统代理解析失败、CA 文件不可读 | 请求发出前或 400/422 拒绝后结束；当前不自动改配置或绕过代理/证书 |
| 能力配置 | 模型删除/不可用、思考档不支持、图片不支持、输出/上下文声明不合法 | 结束并要求调整配置；404 不当作短暂网络错误无限重试 |
| 业务竞态 | 请求已存在/收据待定、价格或模型配置改变 | 不盲目重放已接收请求、不擅自接受新价格，需核对收据/更新配置 |
| 输入容量 | 单条输入/附件挤爆上下文、HTTP 413、服务端 context_length_exceeded | 请求结束；客户端预压缩不能保证处理供应商不同的计算方式或请求字节上限 |
| 自动压缩 | 没有安全可压缩前缀、摘要请求最终失败/超时、摘要质量十次修复后仍不合格、提交压缩失败 | 保留原历史，结束当前运行，避免丢失上下文 |
| 上下文预算 | 扩展反复要求压缩后仍无法构造合规请求、预算读取/请求构造失败 | 结束；不截断必要工具结果强行调用 |
| 普通工具 | 文件不存在、编辑未匹配、命令失败、单个工具本身超时、普通 MCP 错误、输出过大/无效编码 | 通常转为工具结果交给模型自纠；连续十个工具失败后结束，成功清零；同一批已完成结果先记录 |
| 工具关键错误 | 工具返回 CONTEXT、OUT_OF_MEMORY、RECOVERY_REQUIRED、取消，或任务总截止已过 | 关键上下文/资源/执行收据问题可立即结束，不遵守普通工具十次门槛 |
| 重复失败保护 | 无成功结果的相同工具批次反复失败 | 与连续失败保护共同限制；达到当前十次限制后结束 |
| 完成验证 | 自定义 Agent 要求写入后验证，模型反复宣布完成却不验证 | 十次验证纠正后仍不满足则结束；普通默认角色不强制开启此策略 |
| 人为限制 | 配置了最大 Agent 轮数、角色最大模型调用数、任务总超时/子任务超时 | 达到明确限制结束；默认不额外设置全任务截止，max_turns=0 表示不以轮数限停 |
| 自定义 Agent/插件 | 生命周期回调报错/拒绝/取消，角色运行驱动失败，依赖缺失、请求引用不可用工具、权限策略不满足 | 可能立即结束；它们处于 Agent 扩展边界，不能一律当作普通工具失败 |
| MCP 预备/授权 | 动态接入或工具执行前依赖检查报 CONTEXT；需要用户完成 OAuth/授权/配置 | 可以在真正工具执行前结束；普通 MCP 工具调用失败则通常回给模型自纠 |
| 持久化 | 会话/结果/事件保存失败、检查点失败、日志损坏、磁盘满/只读/权限改变、文件被删或外部改写导致校验失败 | 可立即结束，不带着不可持久化或不一致的执行记录继续 |
| 执行收据 | 上次崩溃/中断后工具可能已执行，效果无法确定、恢复快照失效 | 要求恢复决策；不能自动重复有副作用操作 |
| 资源/运行时 | 内存分配、线程/锁/句柄、结果编码/请求构造失败、运行时内部错误、扩展回调破坏上下文 | 可立即结束或进程退出；自动重试不能可靠解决所有此类问题 |
| 主动停止 | 用户停止、插件/SDK 取消、应用退出或服务停止 | 正常取消，保留已完成数据，不应擅自自动恢复被主动停止的任务 |
| 外部终止 | 应用/原生库崩溃、系统杀进程、断电/重启、Android 冻结或回收、更新替换导致进程退出 | 执行停止或冻结；重新启动后需按收据恢复；应用只在前端断线时不一定停止 |
| 正常结束 | 模型不再调用工具而返回最终答案，或者自定义角色正常返回完成 | 会结束这一轮；即使用户认为目标未完成，也未必是系统错误 |

### 不应混为“运行失败”的情形

| 条件 | 实际行为 |
| --- | --- |
| 权限确认 | 等待用户；当前最长五分钟，或更早的调用截止。拒绝/超时一般回给模型工具拒绝结果，未必立即终止；反复失败可能累计到十次 |
| ask 等待回答 | 等待用户；无人回答会回传提示让模型继续，不是直接失败。另发现超时常量 `4u*60u*60u*1000000u` 存在 uint32 溢出，实际约 25 分 15 秒而非声明的四小时；本次未改此独立问题 |
| 子任务失败、超时、深度/并发上限 | 通常作为委派工具结果返回主 Agent；不必然结束主任务；主 Agent 可继续或最终受到连续失败保护 |
| 浏览器/WebView/SSE/远程控制连接中断 | 原生后台存活时任务可以继续；前端可能失去实时显示。原生进程也退出或被冻结时另论 |
| 队列消息等待 | 上一轮未结束、等待授权、正在恢复或同会话忙，不等于消息发送失败 |
| 并发/保留条目上限、会话正在准备/压缩/恢复、项目被移除、会话锁定、强更挡住新请求、附件引用/排队记录保存失败 | 主要属于运行受理/启动阶段的拒绝，不能当作“已经运行一半的模型掉线”；前端保留输入与有界恢复仍可能最后要求人工处理 |

### 仍需改进的无人值守体验

1. MCP 接入前 CONTEXT 错误、插件回调错误、上下文/持久化错误依然可能一次就结束；应按明确错误类型区分可恢复与不可恢复，不能靠统一重跑所有工具解决。
2. 短暂模型异常已重试，但用尽次数、15 分钟恢复窗口、调用方截止仍结束。若以后做长时间等待网络恢复，应保留用户停止和费用边界，另作明确策略，不能悄悄无限重试。
3. 权限确认五分钟到期、ask 实际超时与期望不符，会影响无人值守工作；后者是本次新发现的独立问题。
4. 模型正常结束但工作未完成属于完成判定/角色设计，不是认证重试能解决；可由特定角色配置验证或计划完成策略。

## 主要源码位置

- `app/src/account/session.c`、`model_allowance.inc.c`：账号续期、租约、退出及刷新计数。
- `app/src/models/completion.inc.c`、`online_access.inc.c`：模型错误分类、恢复边界、退避预算、认证接线。
- `app/src/agents/runtime.c`、`program.inc.c`：十次工具/验证/压缩限制、角色预算与回调、MCP 前置检查。
- `app/src/runs/manager.c`：受理、并发上限、附件/排队记录、启动/停止和总截止。
- `app/src/approvals/manager.c`、`app/src/asks/manager.c`：权限及问答等待。
- 固定 SDK `lib/xwork/src/xwork_agent.c`：工具失败与关键错误分流、压缩、验证、持久化和最终结束。
