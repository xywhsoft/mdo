## 会话排序

会话仍采用文件存储。`meta.json` 新增可选的 `last_activated_at_us`，列表接口返回
`last_activated_at`，单位均为 Unix 微秒。旧会话缺少字段时，以原更新时间作为初始值。
新会话和分叉以创建时间初始化，用户打开、切换会话时更新；只读 GET、后台输出和标题等
元数据修改不改变激活时间。重复保存同一选择保持幂等。

激活记录独立于内容/模型配置修订号，避免切换会话使正在进行的配置保存失效；旧运行句柄
提交元数据时合并最新激活时间。置顶与分组保留，组内会话按最近激活倒序，历史手动行顺序
不再覆盖它。自定义分组中的会话遵循同一规则。侧栏、搜索和时间分组使用一致的时间来源，
并修正时间分组原先把微秒当秒的换算。

## MCP 接入

- 模型请求的 `mcp.instructions` 默认包含实际启用服务的 ID、说明、连接/发现状态及
  有界的缓存使用说明。无相关工具的角色默认不注入；配置式与 C Agent 可以显式覆盖或关闭。
- 旧会话保留原系统上下文和聊天历史，仅增加可替换的动态能力片段；每次请求更新，重启不会
  不断累积旧片段。服务停用后，下一次上下文不再宣称其可用。
- 主 Agent 在空闲边界尝试预加载服务说明中引用的入口工具定义，无 Computer Use 名称或
  可执行程序特判。自动加载最多占四个 MCP 工具槽，参数与说明合计预算 24 KiB；已有显式
  加载保留并计入自动预算，剩余工具继续通过 `tools`、`load` 按需使用。
- 预加载只准备参数定义，不执行远端操作或打开授权流程。实际调用继续执行角色、项目、
  信任、工具允许/拒绝及权限检查。停用后，已预加载的工具也不能继续调用。

详细开发约定见 [MCP 格式说明](../mcp-format.md)。
