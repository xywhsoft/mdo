# 引导消息交接、恢复误报与文件变更

本轮检查的是运行中发送引导消息，以及队列中的“引导”操作。新输入仍使用持久化队列和同一提交 ID，不另起并行会话，不重复提交模型请求。

## 确认的问题与修复

1. 取消旧运行后、下一条输入启动前，恢复接口仍可打开运行时并返回“上次回复未完成”。恢复按钮甚至能够启动旧任务，与已保存的引导消息争抢执行权。现在未暂停的托管队列拥有下一条输入；恢复读取返回忙碌，过期的继续/结束请求被拒绝。读取过程中收到新消息时也不发布旧恢复状态。队列暂停、用户主动停止或真实故障仍保留恢复流程。
2. 界面保留了过期的恢复结果，运行或交接期间仍可弹出恢复卡片。现在运行状态和托管队列状态共同决定是否展示；队列更新立即同步卡片，旧按钮的延迟点击不会发出请求。引导准备显示“正在应用新指令…”，不再描述为等待旧回复自然结束。
3. 非 Git 目录的运行前快照为空，收尾却把空字符串当作有效快照再次捕获，覆盖“不是 Git 仓库”的状态，生成虚假的变更错误。现在只对有效快照捕获结束状态，并准确区分非仓库与真正的 Git 错误。旧错误收据只在当前目录确认仍非仓库时归类为无变更视图，不改写历史或伪造快照。
4. 变更读取遇到临时故障立即显示错误；完成事件早于收据落盘时，原等待期限也可能不足。现在只重试只读检查，临时故障最多重试 3 次；近期收据发布最多等待约 30 秒，离开后取消等待。永久错误保留明确的手动重试入口及错误详情，旧消息不补造变更。

## 验证

- 原生离线回归确定性留出“旧运行已经取消、队列尚未调度”的窗口。修复前恢复读取返回 200/需要恢复，继续操作返回 202 并启动旧任务；修复后读取和过期操作均返回 409，新输入只执行一次。取消前后的两份变更仍可读取，主动停止仍返回真正的恢复状态。
- 同一原生回归验证非 Git 目录，以及旧版错误收据的只读识别；全程复用现有 xs/SDK，在项目内测试，不调用真实供应商或用户数据。
- 原有四轮变更回归通过，覆盖提交、已有脏文件、增删及 Unicode 文件、历史比较不可变、空变更和捕获超限不影响任务。
- 浏览器回归覆盖中/英/俄、桌面/窄屏的交接卡片、延迟恢复结果、旧按钮点击、真正停止；另覆盖变更临时读取、收据发布、非 Git、永久失败和离开取消。
- 队列原有排序、拖动、提取、引导、焦点、滚动、首条消息和待发送去重的 10 组浏览器场景通过。
