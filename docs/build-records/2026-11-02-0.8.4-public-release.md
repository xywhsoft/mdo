1. 六个最终可执行产物分别通过九项打包运行与扩展依赖合同，共 54 项；包含全新 Home
   启动、依赖闭包、启停事务、冲突拒绝、重启恢复。官方发布准备器校验八个最终文件。
2. 严格 C11 `-Wall -Wextra -Werror` 检查通过；修正了两处具有误导性的 C 缩进。
   Chat、Responses、Anthropic 模型序列化与能力所有权回归通过。
3. 两个 APK 通过 CRC、内部版本与安装序号、原生库映射、依赖、16 KiB ZIP 和 ELF
   对齐检查；Android 运行路径别名九项回归通过。两版均使用原正式签名，证书 SHA-256 为
   `94b1947b60f3ce0852b19d9c37a47cc4a084fe9d601692c6a1f6b204c2174e84`。
4. 发布后通过公共 HTTPS 完整下载八项官网文件和八项更新对象，大小与 SHA-256 全部一致。
   检查旧版请求、仅安装序号的请求、忽略版本编码最高字节、同版本较新安装序号等更新响应。
5. 独立 Windows 客户端校验八项更新响应、八项官网 HEAD、Windows 图形版与 Android
   精简版的完整更新对象哈希，全部通过。
6. 官网三种语言同步静态版本、安装序号、文件体积、八项工具清单及 24 处哈希提示。
   收尾发现旧工具说明和哈希 `title` 未随正文更新，已以文件哈希保护方式修正并再次从公共
   HTTPS 验证十个文本文件，未改动程序文件或更新目录。

本轮没有执行 Android 真机、真实模型付费调用、双设备或 Linux 桌面手动验收；

### 构建过程中的未解决事项

- 新编译的 Windows 图形宿主两次未在测试启动期限内提供 HTTP 服务，原因尚未确认。
  该宿主未发布，保留在私有证据目录。最终 Windows 图形版使用先前已通过验收、同一
  XS/SDK 锁定版本的宿主前缀，重新打包本次最新应用；最终文件通过九项运行合同。
  构建清单明确标记 `native_baseline_reused`，不将复用宿主描述为已修复新宿主问题。
- 在 WSL 的 `/mnt/d`（Windows DrvFS）目录运行 Linux 安装事务测试时，文件系统不提供
  所需的原子 no-replace 目录重命名；改在 Linux 原生文件系统测试后通过。
  这不是对 DrvFS 兼容性问题的修复。失败证据已保留。
- Linux 首次构建完成后正常卸载临时绑定目录遇到 busy；最终已正常卸载，没有强制卸载、
  关闭 WSL 或中断其他任务。

## 签名材料与生产现场

原 Android 私钥并未丢失，仍存在于旧的 `E:\software\mdo-signing`。
按用户要求将其迁至 `D:\GIT\mdo\.private\android-signing`，验证可读取且证书一致后，
移除原项目外副本。项目内目录设有访问权限并由 Git 忽略，不能作为 `.build` 缓存清理。
详细保管规则见 [Android 正式签名身份](../android-release-signing.md)。

没有关闭证书校验、替换账户库或回滚在线用户数据。

临时管理凭据清除，原管理员凭据未变。官网目录 inode 保留，发布前备份仍在服务器私有目录。
