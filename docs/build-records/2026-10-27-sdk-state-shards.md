# SDK 状态命名空间分片

完整 Mohists 回归在新建任务组时触发 sdk_state_limit。实际目录只有约 1.3 MB，但旧实现将整个 Home 的状态命名空间限制在 256 个文件；任务组、成员和其他扩展共用它，历史记录累计后正常业务也无法继续。

新命名空间改用 SHA-256 前两位划分的 256 个目录。每个分片仍有 256 文件和 16 MiB 的实际文件容量限制；原单命名空间及记录预算不变。扫描有界，保存前在原状态互斥下检查，原子提交与校验不变。旧平面文件保持原位，持久成员的逻辑路径和目录标识也不变，没有进行批量数据搬迁或清除旧记录。

同一命名空间两种位置同时存在时返回 sdk_state_ambiguous，不以错误的优先级掩盖分歧。状态读取不因分片已满而失败；容量允许的现有文件更新仍可进行。

在唯一开发 Home 运行 D:/GIT/mohists/tests/test_state_scale.py：

- 新建并读取 257 个独立命名空间，原有平面记录逐文件哈希不变。
- 用真实 SDK 写满一个分片，第 257 个文件被拒绝，现有文件仍能更新。
- 测试自有的临时容量填充触发 16 MiB 限额，拒绝后没有发布新文件。
- 制造两份相同命名空间文件后，读取明确拒绝且两份文件均未被覆盖。
- 受控旧布局成员的身份、完整可见历史以及重启后状态保持一致。一次本地模型调用用于建立成员样例，无供应商调用。

规模测试结束后只删除精确校验、由本测试创建的填充文件，原数据和旧布局成员样例保留；没有复制运行时或创建第二个 Home。此前失败的后台调度回归已重新通过。全量回归仍需在最终源码基线上运行。
