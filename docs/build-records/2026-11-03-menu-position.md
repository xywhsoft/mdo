# 2026-11-03 菜单锚点与可见区域修复

## 原因和范围

侧栏在 render 中清空并重建列表。菜单创建时就计算位置，此时按钮可能仍在未挂载的项目/分组中，且列表的 scrollTop 尚未恢复。后续滚动事件有时重新定位，但仍会使用中间布局，所以出现回收站按钮在中间、菜单落到底部的现象。

修复提交 `6279b1ce04845ee8359e1fc6caac8fd8710331a5`：完整树挂载、列表滚动及焦点恢复后再定位菜单，并在菜单可用高度确定后恢复其内部阅读位置。普通/归档/回收站会话、项目、自定义分组、列表选项共享这条路径。

同时检查各页面手写弹出菜单，替换扩展页面固定 240px 高度估算、工作台没有最大高度的定位和输入框加号只允许上弹的定位。公共工具根据实际菜单尺寸和 visualViewport 选择上下方向、限制最大宽高并保留菜单滚动位置。扩展菜单跟随滚动/窗口变化，关闭或从列表移除后释放监听；工作台忽略菜单内部滚动，避免反复定位干扰阅读。会话顶部菜单、桌面/移动端项目切换器的原定位保留。
