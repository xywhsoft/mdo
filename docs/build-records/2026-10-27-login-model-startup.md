# 登录模型的启动等待

修复记住账号后启动时，旧会话先于登录恢复及线上模型目录加载，错误显示“所选模型已不在模型列表中”的问题。
本轮是 Windows 本地开发修复，版本配置保持 `0.7.0 / 05000700`，没有发布官网安装包或自动更新。

## 行为

- 原生模型信息增加 `RequiresLogin`，模型目录 API 对应 `requires_login`。
- 账号与目录就绪状态分别识别为 `pending`、`signed_out`、`unavailable`、`ready`，不借用额度请求状态。
- 会话保留原模型身份；登录恢复及目录等待期间，发送、快捷发送、队列和自动继续均受门控，草稿仍可编辑。
- 原生创建会话、模型 profile、客户端及 Agent 解析也执行相同门控。等待和目录暂不可用返回明确的 503；
  只有成功加载的目录仍缺少模型，才返回原来的模型不存在错误。
- 账号状态变化即使没有增加模型 generation，也会刷新模型目录；目录就绪后重新读取会话及恢复状态。
- 目录快照自身保留是否加载过账号目录，避免旧快照在账号刚就绪时误判删除。
- `mdo-online.*` 的旧会话身份无需持久化线上目录即可识别。明确的同名个人模型配置优先，个人供应商模型不等待账号。
- 中文、英文和俄文均补充等待、需登录及目录失败提示。

## 验证

- `test_login_model_startup.py`：真实 xs/TCC、原生账号 worker 和本地 HTTP 服务通过。覆盖首次延迟登录、
  延迟目录、记住账号后重启、目录 503、确认移除及退出登录；三次重启，等待期间零模型请求，就绪后一次模型请求成功。
- 同一回归的 `--packed` 检查最终 Windows 可执行文件：独立 Home 启动、登录标识、未登录准入拒绝和打包前端均通过。
- 前端相关 67 项通过：账号状态、模型选择、运行准入、模型错误与语言包、profile 恢复及读取期限。
- 模型、Agent 和前端契约共 31 项通过；234 个前端模块语法、导入和可达性检查通过；`git diff --check` 通过。
- GCC 完整 unity 语法检查通过。原样的 `-Wall -Wextra -Werror` 被既有代码的 misleading-indentation 以及
  `MdoSessionUseAgent` 的未使用 Error 参数阻断；验证中禁用前者并将后者保留为警告，没有修改无关实现。
  本轮未运行完整发布门禁或 Android/Linux 成品验收。
