版本仍为 0.8.5。这是当前工作目录的本地 Windows GUI 构建，未发布线上程序或更新清单，未替换 `E:\software\mdo` 中的用户程序。

## 原因和修复

两张截图对应两个独立问题：

- `Agent definition unavailable: agent.mohists`：会话元数据保留了被卸载或停用的插件 Agent。经用户确认删除过墨者，且当时运行实例的角色列表只剩默认 Agent 和通用子 Agent。缺失定义不能通过重试压缩恢复。
- `session already has an active runtime`：后台恢复检查和压缩命令都调用 `MdoSessionOpen`，需要独占执行环境。恢复检查、发起回复和配置切换已有页面级队列，而会话命令没有接入。命令通过子进程异步启动，只等待提交响应也无法解决冲突。

`requires_session: true` 的命令现在接入已有的会话操作队列，等待上一项结束，并持有队列直到最终命令回执。取消尚未提交的等待项不会发出 POST，不会提前放行后继操作。不同会话与不依赖会话的 `/stop` 不受阻塞。目标设备变化后不会执行旧的排队命令。

压缩遇到缺失 Agent 返回 `agent_unavailable`。Worker 直接传播 SDK 失败时保留其错误码，界面提供中、英、俄三种语言的恢复提示：切换可用 Agent，或恢复原 Agent / 插件。被命令自行改写或处理的错误不会误继承旧错误码。不自动替换 Agent，也不会在缺失定义时调用摘要模型。

提交：`34bb892c`（会话队列）、`39f5f872`（结构化错误与恢复提示）。
