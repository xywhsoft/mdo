## 已通过

1. 独立 APK 实际加载 JNI、六扩展宿主和内置 TCC；调用了导出的 `xrtRudpOperationInit` 并核验初始化结果。Android 凭据保护实际可用。
2. ARM64 原生 Future 测试在手机上执行 IPv4/IPv6 × Select/Epoll 四项，均退出 0。覆盖字节/消息、取消、超时、额度、关闭顺序、并发取消和 Engine 停止等原测试中的断言。它以 Android shell UID 执行；不能将它描述为四项都在 APK 的 JNI 线程内执行。
3. Windows 控制手机、手机控制 Windows 两个方向，均通过直连、仅目标设备发生一次写入、实时订阅、只读拒绝、取消后的中继收据查询及注销。关闭后两端原生传输数归零。
4. 实际 UID 冻结后再回到前台，两方向均通过同一 Android 进程恢复、重新会合直连、原收据权限保留与写入不重复。冻结超过 60 秒后重新建立连接，未要求已失效的旧连接继续可用。
5. 用户解除冻结并允许后台运行后，普通 QA 包在两个方向各持续后台空闲 65 秒，随后业务读取、实时订阅及取消恢复均通过。同一 Android 进程保持运行，结束时父 UID 的 `cgroup.freeze=0`；没有添加临时电池豁免，关闭后原生传输数归零，注销和测试进程清理通过。

首轮冻结恢复尝试的正向已通过；反向在旧控制连接刚关闭时取得 409。测试端随后按已有浏览器回归的做法，在三秒内等待控制名额释放，仅重跑反向并通过。原失败收据保留，未将整次失败尝试改成成功；该调整没有修改产品协议。

## 后台超时的直接原因

第一次长后台空闲请求超时后，实测发现：

```text
/sys/fs/cgroup/apps/uid_<测试包 UID>/cgroup.freeze = 1
/sys/fs/cgroup/apps/uid_<测试包 UID>/cgroup.events: frozen 1
子进程自身 cgroup.freeze = 0，但 cgroup.events 仍为 frozen 1
```

父 UID 控制组冻结了整个测试包。ActivityManager 的进程记录仍显示前台服务、`isFrozen=false`，因此只看它不足以排除祖先控制组冻结。前台服务和 PARTIAL_WAKE_LOCK 均已实际建立；临时 Android 电池豁免也未防止该冻结。记录未确认是谁写入冻结状态，不将其归因于某个特定厂商组件或第三方工具。

用户已为测试包解除冻结并允许后台运行。该条件下两方向各 65 秒持续后台运行复验已通过，收据为 `device-background-user-unfrozen-receipt.json`。本轮未发现需要修改 XRUDP 协议或运行时的已确认缺陷；持续后台运行和冻结后的恢复分别保留独立证据。

ADB 的默认端口先前连到了 WSL 服务；本轮改用独立 Windows 端口 5038。诊断中还比较了 Windows USB 后端，采用 `ADB_USB_LEGACY=1` 后明确由 Windows NATIVE 后端连接；后台冻结在该后端仍可复现，不能归因于一次 ADB 后端切换。

## 独立移动网络与中继回退

用户将手机切换到移动数据后，确认默认网络为 CELLULAR。两个控制方向均交换了不同的公网 IPv4 映射，但未完成直连握手；反向明确记录为原生网关约 9.8 秒后关闭，没有选择成功的路径。这些失败收据原样保留，不能将其计为双 NAT 直连成功。

另用同一个 UDP 套接字向同一公网诊断服务器的两个端口依次发送 A/B/A 三次探测。手机在 A 上两次映射一致，在 B 上获得不同映射；Windows 在该探测中映射不变。该结果支持端口依赖映射导致打洞受限的判断，但探测以 Android shell UID 执行，不能把它单独作为 APK UID 的完整 NAT 行为证明。临时服务器只处理六个匹配随机探测标记的包，正常退出并关闭套接字；手机原生诊断程序已删除并另行核验。

随后使用正式 `remote-transport.js` 和 `connector.js`，保留原始候选地址和真实原生网关，验证自动尝试 XRUDP、LAN 后继续使用中继：

| 方向 | 实际前端 | 结果 |
| --- | --- | --- |
| Windows 控制 Android | Edge | 约 11.7 秒完成两级尝试并保持中继；两次写入各执行一次，65 秒后台空闲后读取通过 |
| Android 控制 Windows | 手机内实际 WebView，经 CDP 驱动 | 约 10.6 秒完成两级尝试并保持中继；两次写入各执行一次，65 秒后台空闲后读取通过 |

两项都验证了独立只读观察连接仍能读取、关闭后两端原生传输数归零，以及注销和进程清理。测试只提供最小 QA HTML；生产传输脚本与原生协议未改写。控制和私有账号信令仍通过 ADB，UDP 探测实际经过设备网络，不能据此宣称公网账号站点链路也完成了这一组测试。

首轮浏览器驱动阻塞等待子进程，没有处理独立观察连接的 ping，导致该观察连接超时。校正驱动后完整重跑通过；原失败收据未改写。这不是已确认的产品运行时缺陷。本轮仍未证明两个独立 NAT 之间的正向直连成功。

## Android Doze 策略与恢复

切回 Wi-Fi 后，两个方向分别建立真实原生直连，再将 Android DeviceIdleController 强制进入 deep `IDLE` 并保持 65 秒。期间既有直连读取仍成功；退出后同一 Android 进程重新会合直连，原写入的完成收据可查询，项目仍恰好存在一份，关闭后原生传输数归零。

测试包在用户允许后台运行后，已处于设备的永久 idle 白名单。本轮只读取该策略，没有增加或移除永久、临时白名单。每项开始和结束均核验 `deep=ACTIVE`、`force=false`；强制阶段明确核验 `deep=IDLE`、`force=true`，最后恢复原值。设置了有期限的独立退出保护，并删除保护标记。没有模拟拔电池、修改充电状态或熄屏。

本项证明真实手机上的强制 Doze 策略及退出恢复。手机保持亮屏和 USB 供电，电源状态为 `Awake`，不能把它描述为物理 SoC 挂起、自然熄屏 Doze 或系统整机休眠已通过。
