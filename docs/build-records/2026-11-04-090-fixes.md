# mdo 0.9.0 预检问题修复

版本保持 `0.9.0 / 05000900`，安装编号保持 `70000184`～`70000191`。本轮没有发布线上更新，没有修改用户安装目录、账号或会话。

原始失败记录保留在 [首次预检报告](2026-11-04-090-preflight.md)。修复与复查证据位于 `.build/fix-090-20261104/`。

## 产品修复

1. **Linux 启动失败**：将 PID 和磁盘剩余空间查询改为明确的宿主接口 `xsCurrentProcessId`、`xsDiskAvailableBytes`。应用的 TCC 代码不再包含缺失的 `unistd.h`，也不再猜测 `statvfs` 结构或动态查找 libc。Windows、Linux、Android 的 SDK 导出和宿主实现同步更新；失败查询清空输出值。
2. **默认推理档位不适配模型**：只对隐式继承的全局偏好执行模型能力适配。不支持该偏好时使用模型默认档位；调用方和角色显式指定的不支持档位仍然拒绝。
3. **离线报告漏读事件**：会话检查器接受当前第 10 版事件格式，保留对未知未来格式的拒绝和告警。专项单元检查 8 项通过。
4. **会话变更视图误报上下文变化**：Git 在 Windows 输出正斜杠，便携记录恢复为本机路径后，原来的字符串比较会把同一目录判为不同目录。现在比较规范化目录；仍校验会话、项目和原始基线身份，保留原基线及用户 Git 索引。
5. **MCP 忙碌被误报为不存在**：原生 MCP 状态查询采用非阻塞客户端锁，握手或请求占用该锁时会返回不可用。管理层现在保留目录中已确认的存在性和启用状态，并在同一目录代次内保留最近一次原生状态；新代次重新观察。后台连接成功后刷新观察值，避免执行工具时闪回未连接。新增真实 stdio 慢请求检查，要求请求期间查询保持存在、启用、连接和工具数量，且不等待慢请求结束。

6. **浏览器授权流程被自动重连覆盖**：尚无令牌的连接请求可以返回授权不足，但不再覆盖正在发现或等待浏览器确认的 OAuth 状态。真实 PKCE 夹具额外验证等待浏览器期间的刷新失败仍保留原授权链接，以及重启、刷新令牌、401、临时上游错误和撤销。
7. **过期消息编辑仍重建模型日志**：普通守卫编辑与携带幂等 ID 的新编辑，都先只读检查原消息是否仍存在；明确失效时不打开 Agent。锁内的权威事件/序号验证保留。回归继续比较元数据、快照、UI 事件、todo 以及日志的原始字节和不存在状态。
8. **恢复上下文累积 MCP 提示词**：旧上下文在 MCP 块之后还有其他来源时，旧的末尾匹配漏掉了完整 MCP 块。现在移除所有完整的自有块后重建实时内容，保留其他固定文本和无法确认的标记；专项覆盖中间、末尾、多次累积及重复恢复。

9. **精简运行时的请求头校验声明缺失**：将 `strpbrk` 改为运行时已提供的 `strchr`，保持对 CR/LF 和保留请求头的拒绝。

## 门禁维护

- 共享夹具显式提供个人测试供应商和能力声明；历史模拟模型的 wire ID 不再意味着内置模型或会员鉴权绕过。
- Agent、SubAgent、命令和 C 工具夹具使用独立目录及 `extension.json`。涉及完整应用依赖的夹具编译实际 unity 源码；不通过产品侧重新接入旧目录来适配测试。
- 已淘汰的整体工具包、平铺扩展文件和 JSON 内嵌文件分发测试，替换为当前的 ZIP、九类目录、任务、依赖、商店归属和插件生命周期原生检查，并接入正式运行时门禁。
- 当前工具目录检查增加坏 C 源码和错误 ABI 的拒绝、保留已发布目录代次、修复后重新加载验证。
- 只读检查捕获到后台更新缓存写入 `data/cache/extension-updates.json`。源代码夹具关闭无关的后台更新检查；打包 WebSocket 检查单独排除可重建缓存，继续比较账号、配置、会话等数据，并在异常时列出变化文件。首次预检没有保存具体变化清单，无法证明首次间歇失败也一定来自同一文件。
- 下载失败原因检查使用用户可见下载中心的持久化记录，而不是用于断点恢复的接收归档记录。独立重试场景不再误用上一场景已下载完毕的归档。
- 备份只对非阻塞捕获锁返回的明确读冲突执行有界重试；格式、校验和容量错误仍须返回原来的具体错误。
- 浏览器夹具同步到合并后的发送/停止按钮。首个会话创建的客户端等待上限与冷启动编译路径匹配；普通查询仍保留短超时。WebSocket 心跳检查仍验证无人回应连接的有界回收。
- 下载和 Agent 回合上限夹具不再往产品 `app/` 写入临时测试源码，避免测试过程污染打包输入。

- Linux 下载的初次额外检查把 Home 放在 WSL 的 Windows 挂载盘，目录原子不覆盖重命名被该文件系统拒绝，程序没有退化为覆盖写入。保留失败证据 `linux-download-drvfs-failure.log`；下载夹具使用小型 Linux 原生文件系统 Home，源码和宿主仍复用项目目录。该检查不表示支持缺少此原子能力的文件系统。

## 构建稳定性

Linux 基线构建完成后，曾遇到子进程退出期间挂载点短暂繁忙，导致清理命令失败。现在只对本次构建拥有的挂载点、且错误明确为 busy 时，最多等待 2 秒进行普通卸载重试；其他错误立即失败，持续繁忙仍然失败，不强制或延迟卸载，不结束其他进程。3 项新单元检查和真实忙挂载释放检查通过，四个版本的完整构建及清理复跑通过。首次失败日志保留为 `linux-cleanup-failure.log`。
