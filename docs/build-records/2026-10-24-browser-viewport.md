# Windows 侧栏网页内容空白修复

用户使用 0.5.0 测试程序，百度和 xs.xywhsoft.com 的标签标题已更新，但侧栏内容为空白。
本机 E:/software/mdo/mdo.exe 与上一轮交付程序 SHA256 完全相同，排除运行旧包的解释。

原实现用 webview_get_window() 返回的外层框架作为网页控制器的父窗口；上游 webview
实际把主界面控制器嵌入全客户区的 m_widget。内容可以完成导航、取标题和内部截图，
却不在主界面的正确子层，可能被完整的主界面控件盖住。原测试只核对控制器可见标志和
网页内部截图，没有证明网页实际处于侧栏的可显示层。

修复从主控制器 get_ParentWindow() 获取实际 UI 控件，给每个内容视图创建独立 STATIC
子窗口；该窗口按侧栏矩形摆放，内容控制器在其中使用从 (0,0) 开始的局部坐标。
SetWindowPos(HWND_TOP, SWP_NOACTIVATE) 保持网页在主界面之上而不抢焦点；控制器和
承载窗口同步显隐，关闭时先释放控制器再销毁承载窗口。未改变网页隔离、TLS 或账号数据。

state 新增 viewport_attached、viewport_topmost、controller_bounds；诊断复制入口包含
这些字段。它们分别检查控制器/承载窗口的父子关系、父控件内中心点实际命中，以及
控制器局部矩形。viewport_topmost 只检查该父控件内的层级，不表示窗口在整个桌面最上方。

回归新增 --display：完整原生应用加载独立绿色固定页面，核对 DOM 侧栏矩形、原生
承载层级、子控件命中与局部坐标。固定环境返回 479×810 的侧栏视口、局部 (0,0)，
附着和层级均为 true；网页状态 ready、无导航错误。其他原生用例补充相同层级断言。
证据 .build/browser-viewport-20261024/after-display/native-result.json。
