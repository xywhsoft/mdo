# 新消息准备期间的会话误报警告

已复现：新会话创建目录后，Agent、工具等初始化尚未完成，此时 `meta.json` 尚未发布；后台目录扫描将目录存在但元数据缺失当作损坏会话，通过诊断接口汇总到通知区。初始化完成后写入元数据，下一次检查警告消失。新建分叉和失败回滚也存在同样窗口。

修复在创建目录的同一管理器锁范围内登记一次短期发布操作。目录扫描暂时跳过明确由本进程创建/分叉的未发布目录，操作成功发布或完成回滚后解除登记。登记跟随调用栈，不分配额外堆对象、不写新边车文件、不引入等待和诊断延迟，也不把耗时初始化放进目录锁。

只有明确在执行中的创建操作得到这一处理；其他目录缺失或损坏的元数据继续报告。即使会话有活动运行时，也不掩盖它的元数据损坏。回滚保留异常文件而留下不完整目录时，操作结束后仍会报警。同 ID 的其他项目不受影响。

新增原生回归通过真实创建、分叉、所有者保留/释放及工作区准备/回滚回调，在元数据尚未发布的时刻直接扫描目录。修复前可确定性观测到额外 1 项误报，修复后不再出现；同时验证真实损坏、孤立目录、不同项目同 ID、活动会话损坏、创建失败后重试和回滚残留均保持正确行为。

验证通过：严格 C11 编译；上述原生回归；会话创建/恢复/分叉/生命周期检查；消息排序、结果与重启回归；恢复协调器/目标预留 HTTP/TLS 回归；5 项统一警告前端检查。没有改成隐藏警告或延迟展示真实故障。

本轮保持 0.9.2，按用户上一轮的本地验收流程重新生成 Windows 与 Android 精简版测试包，安装编号递增，沿用 Android 原正式签名；未发布官网或更新。重新构建的文件与检查结果另存于对应的本地测试包记录。
