# 对话期间的账号恢复与模型续期重试

版本保持 0.9.3。本轮修复客户端代码，不修改线上服务、账号数据或发布目录。

## 根因

用户描述对应 `profile_login_pending`。账号后台刷新令牌时，模型登录状态会变成 pending；Agent 每次模型调用之前还要通过 `MdoModelCatalogProfile` 检查。原检查直接返回配置错误，发生在模型重试循环以外，因此已有对话也会失败并要求手动继续。

另外两个恢复缺口：线上模型遇到 401 仅允许一次认证恢复；获取令牌失败被一概归为需要登录，初始获取甚至不进入重试循环。只按实际 HTTP 请求次数限制循环，也无法准确约束没有发出模型 HTTP 请求的恢复尝试。

使用已发布提交 `6ff77e6c` 的模型边界源码，注入后台续期故障，能够稳定触发 `Background renewal interrupted the Agent`。没有读取或上传用户提示词、密钥、令牌或计费数据。

## 修复

- 已有线上模型快照的结构检查允许暂时续期或目录读取不可用；实际请求仍必须获取有效账号令牌。未登录及缺失模型的校验继续保留。
- 在获取令牌前固定账号身份与取消信号。退出、切换账号及手动停止可中止整个等待和重试，旧任务不能在恢复过程中改用新账号。
- 临时令牌获取失败和确定的模型 401，统一进入现有模型退避循环。初始尝试之外最多自动重试 10 次，与网络失败共享计数，避免嵌套两套模型重试。
- 沿用指数退避、正向抖动、Retry-After、取消及截止时间，并保留原有恢复总时限。没有真正发起模型 HTTP 请求的等待不计入模型调用统计，但仍消耗恢复次数。
- 一次账号获取只等待一轮续期结果，失败交回统一恢复循环，不在内部隐藏重复续期。后台共享账号工作线程继续使用原有退避和成功清零规则。
- 每个模型调用成功结束后不保留失败计数；下一次调用重新开始。额度、余额、权限等明确业务拒绝和已撤销的续期凭据不盲目重试，已经交付内容的认证失败也不重放。
- 等待期间发出已有的模型恢复进度事件，不发布最终错误，不重复用户消息或已经执行的工具。

## 验证

全部使用本机合成身份、回环 HTTP 和临时测试目录，不调用真实付费模型。

- Windows、Linux：16 项模型边界场景通过，包括连续 401、网络与认证混合失败共享 10 次重试、零模型请求的等待耗尽、临时状态恢复、下一次调用清零、取消、截止、部分输出保护与业务拒绝。
- Windows、Linux：11 项真实账号工作线程场景通过，包括后台续期期间的模型配置检查、连续两次 503 后恢复、初始没有有效 bearer、等待期间退出/切换账号、凭据撤销。获取者均归零，续期成功后失败计数为零。
- 完整 Windows 原生 Agent：第一轮执行一次 ls 工具后，注入后台续期和连续两次 503，仍完成同一运行；下一条消息同样完成，没有新增续期或重试事件。共 4 次模型 HTTP 请求、3 次续期、一个已完成工具结果，零继续接口调用。
- 原有 39 项模型重试回归通过；模型重试进度、事件重放、取消和旧事件兼容回归通过。
- 账号启动恢复回归通过：重启 3 次，缺少模型目录时仍等待目录，未提前调用模型。
