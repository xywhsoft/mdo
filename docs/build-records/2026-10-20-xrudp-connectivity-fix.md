# 2026-10-20 XRUDP 移动网络连通性修复

本次落实 2026-10-19 真机诊断中的产品修复：认证连通性检查、实际回复来源候选、底层握手方向协商，以及固定的总启动时限。所有提交在 master；未包含工作区其他任务的改动。

XRT 的 `e9d4d05` 增加 opt-in 的 XRC1 检查和独立回归，`0c46aca` 修复检查期限必须从 Bind 受理起计算。检查不分配 Peer/半开连接，不绕过 Noise 身份与地址校验；每次最多八个候选、每候选五次请求、八项待发消息，认证输入每秒最多 64 次，共用至少 50 ms 的辅助发送间隔。取消和关闭清除检查凭据及待发内容。

XS 的 `4da6a90` 接入并提供按库导出已提交源码的同步方式，`c2d5cdf` 为独立 STUN 服务增加分别报告 XS/XRUDP/core 修订的版本信息，`585214b` 纳入固定期限修复。mdo SDK 固定到 `5cdc54e`，XRUDP 扩展固定到 `0c46aca`；核心仍使用 `3d55ec4`，保持既有产品伴生库兼容性。更新 deps.lock 和离线 bundle，未夹带 XRT 工作区未提交的其他核心修改。

mdo 将信令控制角色与原生拨号角色分离。双方都运行检查；控制端优先使用经过挑战回复验证的地址，或在有源 cookie 确认的反方向选择目标拨号。新版 offer 和 authority context 为 v2，`rudp_dial` 的五字段、身份、族和不可变方向均校验；选路和业务权限仍由原认证链决定。真机浏览器回归另发现连接器的版本校验尚停留在 v1，现已与原生和传输选择器一起更新，并增加真实连接器准入/旧版拒绝回归。

自动化验证已通过：固定核心的 Linux GCC ASan/UBSan/泄漏检查，模块与单文件实现各九项认证检查案例（IPv4/IPv6、两种原生方向、端口依赖映射、错误 MAC/上下文/cookie、反射与重放、延迟 Open）；mdo Linux ASan 反向协商；Windows 六扩展完整导出与兼容性、双向选择、30 对映射/取消/关闭、双族 NAT、分别屏蔽 IPv4/IPv6 的完整业务，以及前端协商/连接器/账号刷新回归。
