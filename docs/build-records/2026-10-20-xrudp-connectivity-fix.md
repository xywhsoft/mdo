## 真机结果

Android 16 ARM64 与 Windows 的 Wi-Fi 两个方向原生直连通过：目标端只写入一次、实时订阅、独立只读连接、取消后中继查询原写入收据、注销以及原生传输数归零。最终前端修复后的 Windows Edge 与实际 Android WebView 还分别通过 Wi-Fi 的自动 XRUDP 选择：协商期间的写入走中继，选定后的写入走 XRUDP，两次写入各执行一次。

手机使用移动数据，与公网 Linux 的两个方向原生直连均通过。公网 Linux 控制手机时自动协商为手机发起 Noise，约 1704 ms；手机控制公网 Linux 时约 515 ms。身份、权限和业务方向未反转，完整业务及注销/收据/关闭回归均通过，远端测试原生进程已核验退出。

手机与当前电脑两个独立网络仍未直连成功，不能据此声称解决所有双 NAT 环境。最终真实 Edge 与 Android WebView 自动回退均通过：XRUDP 在约 10.0 秒终止，LAN 尝试随后在约 12.5 秒终止，业务继续使用中继；两次写入各执行一次，独立只读连接继续可用，两端原生传输数归零。该路径没有确定具体丢包设备，不新增未经证实的网络根因。

这些是本次修复的短时功能验证，不代替物理睡眠/恢复、完整独立协议互操作、模糊测试或 72 小时长稳验收。
