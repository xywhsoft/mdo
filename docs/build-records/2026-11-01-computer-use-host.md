# Computer Use 宿主修复

主线固定 SDK 缺少 Computer Use 仓库已验证的四项通用修复：Responses 多段工具结果和图片输出、超过 1 MiB 的 MCP 图片、执行回调与工具描述视图的目录生命周期，以及已有持久化产物的长文本预算。

本轮将这些修复迁入主线 SDK overlay，保留所有现有产品修改、公开 ABI 与持久化格式。未知工具上下文也避免解引用空指针。Responses 明确输出工具的 strict 值；产品已有的供应商请求适配继续保留。没有修改 Cua 二进制、提示词、权限或取消机制。

补丁与依赖树摘要已同步至 deps.lock，完整补丁在同一 SDK 目录逆向检查、还原、重新检查和应用通过；复用现有 SDK 和构建对象，没有创建工作树或新的运行时副本。

当前 Windows 0.8.3 新构建已启动，并通过 `tests/test_computer_use_host_native.py` 的四项真实 XS/TCC 原生回归（Responses 文本/图文/纯图/多段输出及 strict、动态目录所有权、持久化文本预算、大图）。严格 C11 检查通过。Windows 官方 Cua 0.38.0 六个原始文件的目录 ZIP 已通过当前产品安装、63 工具发现、连接中相同版本更新以及两个授权方案预览。

这是原生和确定性验收，不等同于新的真实模型自主任务验收。Computer Use 的完整发布和模型验收证据保存在其独立仓库。

真实模型验收发现第五项宿主问题：MCP 发现列表按字节压缩说明时，可能截断中文或其他多字节字符，整份工具结果因此成为无效 UTF-8。修复在字符边界截断，保持原有 512/4096 字节预算。新增二、三、四字节字符和服务说明边界的原生回归，与前四项一起通过；测试对端采用 JSON Unicode 转义，避免 Windows Python 标准输出本地编码干扰协议。

## 正式商店链路发现的下载重试缺陷

首轮 Windows 构建 70000126/70000127 与 MCP ZIP 已发布。四个 Windows 官网/更新下载地址均通过完整 SHA-256；其余六个渠道及强更标记保持原值。正式商店的后台安装在下载过程中遭遇连接失败，不能将这次安装计为通过。

随后以真实 XS fetch 复现：总超时的错误链为 `xs.fetch(timeout) → xrt.http.client(timeout) → xrt.tls(cancelled) → xrt.net(cancelled)`。旧逻辑遇到内部取消即拒绝重试，将明确超时错误误判成了用户取消。本轮允许超时之后的内部取消进入原有重试路径，实际请求取消、证书失败及其他确定性错误仍立即停止，整项操作仍最多重试五次。

安装文件每块最大 1 MiB。仅二进制 GET 的总超时调整为 120 秒、无进展超时 30 秒；普通元数据和写请求保持原预算。连接错误展示底层原因，避免仅显示通用的 bounded HTTP request failed。

后续正式下载还遇到可重试的 HTTP/1 连接中断。原重试入口重启整个下载并丢弃前缀，导致大包反复从零开始。改为在同一任务、同一版本和同一偏移处重试读取，保留已下载的分块和其他依赖已封存的下载。元数据、各分块和整组依赖共享一个五次预算；不重放提交、安装或信任确认，最终仍核对完整 ZIP 哈希。新增的较后分块五次重试成功、六次失败停止及不重读前缀合同通过；服务合同共 35 项、五依赖整体服务合同共 9 项通过。

新增超时/内部取消、五次重试上限、真实取消及证书错误的回归，原生服务合同共 33 项通过。真实本机 HTTP 对端连续传输 1 MiB，耗时 32.884 秒（超过原 30 秒总预算），新产品函数完成读取。版本仍为 0.8.3，Windows 构建改为 70000134/70000135；其他平台只预留新编号，本轮不发布其产物。

## 最终发布结果

最终 Windows 构建 70000134/70000135 已在官网与自动更新发布，保持强制更新，目录修订为 34。MCP 商店完整 ZIP 已通过真实后台下载、哈希校验、安装、私有连接、63 工具发现及整目录卸载，账号状态保留。两个更新文件的完整 HTTPS 哈希通过，官网对象哈希与 HTTPS HEAD 通过。其余六渠道、通知和 MCP 包内容未改变，数据库完整性正常。

真实模型验收分别完成 Windows 桌面任务（Ornith，156.27 秒）和浏览器任务（GLM-5.3-Flash，495.38 秒）。Ornith 的完整浏览器任务超时失败，保留该限制。详细公开汇总在同目录 `2026-11-01-computer-use-publication.json`，原始历史和私有证据留在原 Home 与构建目录。根目录八平台汇总仍是旧批次，不能把本次 Windows 两个平台重打包视为八个平台全部发布。
