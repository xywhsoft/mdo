# Computer Use 宿主修复

主线固定 SDK 缺少 Computer Use 仓库已验证的四项通用修复：Responses 多段工具结果和图片输出、超过 1 MiB 的 MCP 图片、执行回调与工具描述视图的目录生命周期，以及已有持久化产物的长文本预算。

本轮将这些修复迁入主线 SDK overlay，保留所有现有产品修改、公开 ABI 与持久化格式。未知工具上下文也避免解引用空指针。Responses 明确输出工具的 strict 值；产品已有的供应商请求适配继续保留。没有修改 Cua 二进制、提示词、权限或取消机制。

补丁与依赖树摘要已同步至 deps.lock，完整补丁在同一 SDK 目录逆向检查、还原、重新检查和应用通过；复用现有 SDK 和构建对象，没有创建工作树或新的运行时副本。

当前 Windows 0.8.3 新构建已启动，并通过 `tests/test_computer_use_host_native.py` 的四项真实 XS/TCC 原生回归（Responses 文本/图文/纯图/多段输出及 strict、动态目录所有权、持久化文本预算、大图）。严格 C11 检查通过。Windows 官方 Cua 0.38.0 六个原始文件的目录 ZIP 已通过当前产品安装、63 工具发现、连接中相同版本更新以及两个授权方案预览。

这是原生和确定性验收，不等同于新的真实模型自主任务验收。Computer Use 的完整发布和模型验收证据保存在其独立仓库。

真实模型验收发现第五项宿主问题：MCP 发现列表按字节压缩说明时，可能截断中文或其他多字节字符，整份工具结果因此成为无效 UTF-8。修复在字符边界截断，保持原有 512/4096 字节预算。新增二、三、四字节字符和服务说明边界的原生回归，与前四项一起通过；测试对端采用 JSON Unicode 转义，避免 Windows Python 标准输出本地编码干扰协议。
