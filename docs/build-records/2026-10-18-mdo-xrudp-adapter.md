# mdo 内嵌 xrudp 消息传输适配

本轮接通进程内原生传输及现有 `MdoRemoteSocket` 接口。端点不依赖 xs 的外部 `class: xrudp` 服务。现有桥接器尚未通过此适配层建立公网直连，不能把这一阶段当成打洞功能已交付。

## 实现

- `remote/rudp.inc.c` 为每个传输创建一个私有、单 worker 的 XRT Engine。原生回调只搬运数据，业务消息回调只由所有者线程的 `Poll` 执行。销毁先关闭端点，再等待 Engine 停止和销毁成功，之后才释放 TCC 回调上下文。
- 双向固定 Noise 公钥、非零 scope 和会合绑定均为必填。绑定以 `mdo.remote.xrudp.v1` 域分隔后参与握手；候选地址及 STUN 结果不能授予身份或账号权限。私钥在端点复制后擦除。
- 默认可靠字节流采用 8 字节消息头：大端 32 位长度、文本/二进制类型、三个零保留字节。文本必须是合法 UTF-8；允许空消息。单消息最多 262123 字节。后续桥接器必须按此上限分块，不能直接发送原 WS 接口允许的 2 MiB 消息。
- 每个方向队列最多 8 条、512 KiB，包含记录元数据；接收暂存另有一个消息大小的上限。队列满时通过原生流控背压，发送等待不超过 2 秒，并响应取消。成功表示本地入队，不表示远端执行完成，不会跨路径重放写操作。
- 每个 TCC 代最多 8 个传输；每端点最多一个 peer/half-open、4 次每秒握手、单 IP 每秒 2 次，原生端点预留上限 4 MiB。Engine 队列、缓冲缓存及内核 UDP 缓冲有各自限制，4 MiB 不是整个进程内存上限。
- 错误保留协议关闭码与原生原因：格式错误 1002、UTF-8 错误 1007、大小超限 1009、本地回调拒绝 1008。未确认的错误握手不杀死监听端点；本地拒绝不会伪装成远端撤销授权。

## 验证

- Windows/Linux 真实 xs/TCC 原生回环：IPv4/IPv6，双向有序文本、二进制、空及最大消息；19 组端点生命周期，错误身份/绑定，独立分帧生产者的畸形及截断输入，干净 FIN，取消、接收背压、全局准入和反复销毁。
- Linux GCC 对实际适配层、当前 XRT 及全部 20 个 xrudp 源文件启用 ASan/UBSan 和泄漏检查，复用上述 19 组生命周期及异常输入；检查通过，未报告内存错误。
- 实际启用 xrudp 的 Windows mdo 宿主完成构建，收据和打包通过，同一宿主中的新增传输回归通过。
- 同一宿主的原 WS/WSS（证书/主机名验证、取消、控制帧和消息边界）、HTTP 回环路由，以及 LAN TLS/单次授权/只读范围/收据路由/撤销/中继回退通过。
- 已修复升级后残留的 LAN TLS 握手超时单位：2000000 毫秒改为 2000 毫秒。真实四个静默连接在限时内释放名额；修复前该回归确实超时。
- 构建导出收据 6 项及 mdo SDK 检查 2 项通过。构建合同 16 项中 15 项通过；现有另一个任务的 7 个 `src/transfers/*.c` 导致精确源文件列表断言失败，本轮不覆盖该工作。

诊断日志在 `.build/rudp-adapter-*.log`，候选包在 `.build/xrudp-adapter/mdo-server.exe`。候选包包含当前工作区其他任务的产品改动，尚未上线或替换安装；Android 实机和打洞矩阵未验证。

## 同端口探测与非阻塞建立

新增 `MdoRudpStart` / `MdoRudpDial`，分别异步绑定 UDP 和发起带 pin 的握手；调用方观察 `Opened`、`Confirmed`、`Closed`，无需在中继 owner 线程等待网络建立。原来的阻塞便利函数沿用相同状态。

`MdoRudpDiscover` 使用本地可信策略指定的数字 STUN 地址，从当前业务端口发现映射；`MdoRudpWarmup` 只向经过认证的会合信息给出的 1..8 个不同单播地址预热过滤器。每类最多一个固定存储任务，只在完成后重用；复用原生端点的节流和内存预算。结果只由快照读取，工作线程不运行应用回调，也不从 UDP 来源学习或扩大授权目标。映射与打洞不改变双方 pin、scope 或绑定。

绑定、拨号和探测共享一个私有截止定时器。探测的绝对期限从应用受理起计算，命令队列排队、恶意响应和重复轮询都不能续期。上层不轮询时仍按期限结束；排队期间已经过期的探测不会发送 UDP。取消操作保留原生已经完成的结果，确认真实 peer 后取消尚未完成的辅助探测。单独的 STUN 错误或探测超时不关闭可用端点。

新增测试使用独立 Python UDP/STUN 编码器，覆盖错误事务、错误来源、坏 fingerprint、超时后重试、双候选节流、任务取消、满命令队列恢复与过期、异步绑定失败和反复关闭。双 UDP 映射转发器模拟地址/端口过滤并重写来源：监听端不预热时拨号超时，预热后固定 pin 的 Noise 握手和加密双向消息成功；预热报文本身全部丢弃，不把收到它当成连通或认证证明。

该模拟覆盖 IPv4/IPv6，未经过公网或真实 NAT 路由器；会合交换、业务路由接线、Android 和完整生产验收仍未完成。

最终 Windows/Linux 真实 TCC 各通过 23 组端点场景；同一源码在 Linux ASan/UBSan 与泄漏检查下通过。另验证了账号取消时，已经本地入队但尚未发送的应用帧会在工作线程停止发送，不依赖发送者继续调用 API。

测试器曾因 Windows 将旧 UDP 接收端关闭后的 ICMP 报为 `ConnectionResetError(10054)` 而退出，导致后续映射测试误超时。已按逐报文错误处理；产品 XRT 原生非连接 UDP 已配置关闭这类 connreset 报告。修正后的 Windows NAT 场景连续 6 轮通过，相关原始及最终日志保存在 `.build/rudp-probes-*.log`。
