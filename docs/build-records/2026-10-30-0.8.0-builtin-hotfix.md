# mdo 0.8.0 内置扩展升级修订发布

0.8.0 修订版已上线官网下载和自动更新，保持显示版本 `0.8.0`、语义编码 `05000800` 和八渠道强制更新；内部安装构建号改为 **70000073–70000080**，线上目录修订为 **31**。原 0.8.0 用户同样能收到这次更新。

## 修复

原版启动保留了缺少逻辑 ID 的旧内置目录，默认 Agent 无法载入，创建会话却误报模型/思考/权限配置无效。现在按安装收据自动升级未修改的内置 Agent、命令和 Skill，保留停用、卸载、个人修改和非内置来源。安装事务再次检查预期目录修订。

修改过或无法验证的内置目录保留并显示集中警告；初次启动隔离未批准的定义，设置页面仍可用，避免再误报整个启动分配失败。运行中重新加载失败会保留原活动定义集合。Agent 不可用返回独立的 `agent_unavailable`，创建、打开、运行和恢复路径保持一致，界面提供“检查 Agent”入口；新任务恢复文字不再笼统要求更换模型参数。

实现提交 `255f1ffc`，POSIX 回归适配提交 `dc973268`；官网提交 `1c6587c8`。规则见 [内置扩展升级](../builtin-upgrades.md)。

## 验证

- 用真实 0.7.0 内置归档和安装收据，在原 0.8.0 发行物上重现错误；新版本启动自动升级 14 项内置内容，并通过真实会话创建 API。测试模型端点指向未使用的本地地址，没有付费模型调用。
- Windows 桌面/服务版、Linux glibc/musl 服务版分别通过 8 项历史升级合同：正常升级创建、Agent/模型错误区分、幂等重启、旧版及当前版本修改保护、停用/卸载保留和管理警告。POSIX 夹具只调整原生文件元数据摘要，历史文件和归档哈希保持不变。
- 三组相关产品原生回归、Python 196/202（6 条条件跳过）、前端 1,208/1,210（2 条条件跳过）、236 模块解析通过。最终 Windows 两版和 Linux 四版各通过 9 项打包依赖合同，Android 两版自动分发校验通过。
- Android 使用原正式证书，CRC、依赖闭包及 16 KiB 对齐通过。进一步解出最终 APK 的共同应用归档，逐字节核对内置升级、模块加载、错误处理和界面提示源码，确认两版包含本次修复。
- 原 0.8.0 Windows 客户端实测：目标仍为 `05000800`，构建 70000073，`available=true`、`required=true`、`blocked=true`。修订版实测 `available=false`、`blocked=false`，不会循环要求同一更新。
- 线上真实 HTTPS 完整下载八个更新对象和八个官网下载文件，大小和 SHA-256 均一致；Windows 公网另外完整核验七个较小文件和完整版 APK 的 HEAD 大小。三个语言下载页、版本事实及发布说明同步核验。商店下载/安装/运行 jq 与停用流程仍通过。

## 生产现场与边界

`xs.service` 保持运行，未重启；服务程序和配置哈希不变。账号、会话、计费数据库没有替换。网站原目录保留，只原子替换已核对文件；原管理员凭据不变，临时发布管理员已登出并删除。备份和收据保留在私有发布目录。

发布后一次只读目录查询遇到 TLS 连接重置；发布写入已成功，未重放发布或回滚。随后独立完成全部 HTTPS 和状态校验，私有收据保留原错误及恢复证据。

保留其他任务的工作区改动，涉及共同修改文件时按本次变更分块提交；没有提交其他扩展核心改造。发行物仍包含此前工作区中的身份/依赖改造，以准确源码指纹验证构建输入。内置初始化及相应旧测试的相关过渡逻辑随本次修复共同提交。

本轮未重跑 Android 真机、Linux GUI 目视或长时测试；此前完整发布门禁的历史夹具缺口仍按原报告保留，不宣称已全部解决。源码下载继续暂停。
