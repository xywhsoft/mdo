# 停止后编辑重发与消息立即上屏

对应流程：发送消息 → 停止 → 编辑原消息 → 保存并重新发送。

## 原因与修复

- 停止控制器原本已经等待运行终止；终止后的恢复检查仍可能短暂打开独占运行时。历史读取、截断此前未加入同一运行时调度，竞争时被归为普通会话冲突。现在共用调度，对明确的运行时暂忙返回 `session_runtime_busy`，有界等待后继续；实际历史冲突仍直接拒绝。
- 历史编辑此前使用整个会话的 revision，标题等元数据变化也会使重发失败。历史接口新增 `history_token`，包含事件日志 epoch、最新事件 ID、最后序列与会话创建时间。新客户端按历史令牌和原消息事件 ID 校验；旧客户端继续按原 ETag 严格校验。
- 编辑窗口打开时读取历史基线。编辑期间若另一窗口新增/替换历史，保留编辑内容并提示核对，避免刷新基线后直接覆盖新历史。相同编辑 ID 的成功截断可确认重试；已有新历史时旧回执失效，不再次截断。
- 重发按钮点击后立即显示编辑后的消息，以及等待、准备、更新、提交状态。等待与准备阶段提供“取消重发”，取消后恢复编辑内容。历史开始更新后隐藏取消入口。
- 截断确认后接入普通发送的持久化草稿/队列流程，沿用同一提交 ID。正式历史接管后移除临时消息，避免重复气泡、重复启动；失败时保留内容。普通发送和不同原消息的编辑不会仅因文字相同而共用标识。
- 新提示覆盖简体中文、英语、俄语。

## 验证

193 项相关前端回归通过，覆盖编辑、停止、提交/队列、草稿、恢复、会话参数与多语言。前端模块图 267 个模块解析并连通，`git diff --check` 通过。

新增 `tests/test_stopped_message_edit.py`，直接运行当前 app 中的原生服务和真实 Edge 页面，使用离线模型回调，不依赖模型账号：

1. 原模型进入执行后停止，回调刻意延迟 500ms 退出，立即编辑并重发。
2. 人为阻塞截断请求：编辑后的消息先显示，编辑框暂时让位，取消等待可恢复输入。
3. 阻塞期间修改标题：新客户端继续成功；旧客户端的过期 ETag 仍返回 412。
4. 拒绝畸形/伪造的历史令牌。
5. 服务端成功截断后主动丢弃响应：同一编辑 ID 安全确认重试，仅启动一次替代任务，最终只有一条正式用户消息。
6. 替代任务产生新历史后重放旧截断：拒绝，不覆盖新历史。
7. 再次编辑期间模拟另一窗口发送消息：保留编辑内容、展示明确冲突，已有两条用户消息保持完整。
8. 总计恰好三次原生模型调用（被取消的原任务、替代任务、另一窗口的任务），页面无未处理脚本异常。

运行方式（需要现有原生 host、生成的应用 SDK、Edge 与 Playwright；Playwright 可通过 `MDO_PLAYWRIGHT_PATH` 指定）：

```powershell
python -X utf8 tests/test_stopped_message_edit.py
```
