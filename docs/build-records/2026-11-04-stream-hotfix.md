# 0.9.0 会话历史紧急补丁

最终 Windows 桌面内部编号 **70000194**，服务编号 **70000195**；显示版本仍为 0.9.0、语义编码 `05000900`。本轮未上传官网下载或自动更新。先行补丁 70000192/70000193 只解决新日志膨胀，最终补丁还包含旧大日志加载、传输边界和自动重试上限修复；转发时使用 `final` 目录产物。

## 根因与存储规则

原 UI 日志将每个模型流式回调单独保存，重复整套事件元数据并同步写入。一份客户日志有 840477 条思考片段，思考正文合计约 2.56 MB，但 UI 日志达到 512954107 字节。两份客户原始 JSONL、原生上下文恢复与校验均正常；故障来自显示投影的严重膨胀、逐行完整 JSON 对象解析超过前端等待时限，以及长期自动重试继续累积片段。

按用户最终要求，进行中的模型思考/回复只保留于内存，WebSocket 发布替换式实时预览；**不按时间、片段或字数落盘**。模型完成、工具调用、重试、错误、取消等语义结束边界提交对应内容。超长完成内容按单条 JSONL 安全上限分段，但分段也只发生在事件结束后。进程崩溃允许丢失当前未结束事件。子智能体独立缓冲；正常结束提交，异常销毁所有者时丢弃未完成尾部，不制造完成记录。

内存设单事件 16 MiB、会话共 32 MiB 和 64 个并行流上限；超限失败，不截断正文或改为流式写盘。保留现有工具、控制事件记录与原生上下文存储。

## 实时传输与旧日志读取

历史 schema 提升为 11，旧版 1–10 继续读取。预览和完成内容携带明确替换范围；客户端统一处理 WebSocket 和回放，切换、断开时不缓存易失游标。根运行重新开始会移除遗留预览；进程内保留未完成事件的编号高水位，避免运行时重新打开后复用编号。正常关闭时释放高水位缓存。

WebSocket 使用 `mdo.live.v2` 协商替换式预览，旧 `v1` 客户端只收到完成文本。内存环形缓存合并过期预览，完成内容保持独立。实时响应预算独立设为 4 MiB，保留完成记录的文本上限；普通 `/events` 批量接口维持原有短预览上限，完整正文经会话投影或单事件接口读取。

JSONL 读取使用有界块缓存；导航索引只解析所需标量与短文本，原生思考记录走完整 JSON 校验的快速路径，避免每片段创建完整对象。增加 8 项进程内导航缓存，按文件身份、大小、修改时间和查询参数失效；不引入第二份持久化索引。单账本与队列启动判定也改为有界扫描，避免整份超大日志分配。

首屏仅有思考/重试尾部时，查找并加入真实的用户输入事件，保留其原始编号。前端单次会话请求等待上限 15 秒、导航索引 30 秒，总恢复预算仍为 60 秒。原始日志不裁剪、不迁移，长执行仍按页继续读取。

单次模型请求的自动恢复限制为初次尝试加最多 10 次恢复，总预算 15 分钟；恢复尝试自身也受剩余预算约束。保留供应商 Retry-After，若等待将超预算则结束恢复；用户取消和更早的调用期限仍优先。耗尽后保留上下文，返回错误供用户明确重试，避免无限退避积累十几个小时。
