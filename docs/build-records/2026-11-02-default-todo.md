# 默认 Todo 工具恢复

用户确认旧名输入有误，将 `mdo.todo` 更名为 `todo`，恢复到当前主线默认工具。
版本仍为 0.8.4 / `05000804`；本轮只生成本地 Windows 测试程序，未发布线上。

## 实现

- `app/default-home/tools/todo/` 为独立 C Agent 工具目录，随产品 ZIP 内置扩展机制自动安装。
  模型只看到 `todo`，无需用户从商店另行安装；已明确停用、卸载或同名自定义目录仍遵循现有保留规则。
- 保留原有完整计划更新协议：`items` 中最多 24 项，每项 `text` 为 1–240 个 Unicode 字符，
  `done` 为布尔值；空数组清空。使用公共 Application SDK 解析和验证参数，不操作项目文件。
- 参数错误返回失败结果和纠正示例，模型可以继续执行；成功结果才参与主会话投影。
- 待办投影、历史截断恢复、备份关系校验和前端事件刷新均接受 `todo` 与历史 `mdo.todo`。
  不重写旧会话。旧名白名单转换为新名；保留旧记录的回归用例。
- 源码范例指向默认工具目录，移除旧 `examples/tools/todo.c`，避免维护两份实现。
- 打包模型回归发现并修复已有运行阻断：CONTEXT 回调在运行中重复设置 MCP 范围，
  被 xwork 拒绝并报 `MCP scope cannot change during a run`。范围继续由根 Agent 创建、
  运行前准备及子 Agent 创建阶段设置；上下文刷新不更改活动中的范围。

- 原生 Todo：12 项契约通过，包括参数纠错、Unicode 边界、24 项上限、旧名备份识别。
- 打包程序：12 项端到端契约通过，包括默认加载、模型实际调用、失败纠正后继续、
  待办清空、重启恢复、卸载保留历史及卸载不被启动恢复。
- 默认扩展目录原生回归：8 项通过，覆盖停用、卸载、已有修改及身份迁移。
- 通用 SubAgent 打包回归通过：前台、后台、只读、失败、取消、上下文隔离和默认目录管理。
- 队列中断恢复打包回归通过：3 次回环模型请求，恢复、显式续跑及后续排队输入均成功，无重复执行。
- 前端：1,298 通过、1 跳过、0 失败；248 个模块解析与依赖检查通过。
- 静态合同回归：127 通过。修改的 Python 回归脚本编译检查通过。

全部模型验证使用本机回环服务，无真实供应商请求；用户现有安装和数据未修改。
测试进程、临时 Home 和程序副本由测试脚本退出时清理。
