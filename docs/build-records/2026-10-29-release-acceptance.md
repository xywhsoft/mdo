## 本轮确认并修复的问题

1. **严格编译被阻断。** 初次检查出现 38 条诊断，主要是相邻语句引发的 misleading-indentation，以及一个未使用变量；继续编译又暴露后续同类位置。拆开语句并移除未使用变量后严格编译通过。涉及另一任务扩展依赖代码的修正留在其现有工作区中，没有整体提交其他任务的功能改动。
2. **官方工具打包器 `StopIteration`。** 商店定义包含尚未进入某个平台内置目录的可选工具，打包器却按全部定义查找本地目录。改为按实际平台目录清单打包，并拒绝重复或缺少官方元数据的条目。
3. **生成的工具 ZIP 缺少正确的逻辑 ID。** 统一生成 `external-tool:mdo.<alias>`，允许显式保留有效逻辑 ID；发布检查器同时保留该 ID。9 个 Windows ZIP 经真实安装回归，Android full 中 13 个 ZIP 也完成包内验证。
4. **同一产品不能确定性重建。** 转发器回执指纹纳入了编译命令的绝对输出路径，路径变化会改变内嵌回执及最终发行文件。指纹改用稳定输出占位符；实际编译路径不变。真实转发器双目录构建及两份完整产品均相同。
5. **离线会话统计漏记当前事件。** `inspect_session.py` 把 UI schema 8/9 的数字事件识别为未知事件，漏记模型用量及工具统计。补齐已知版本，继续把未来 schema 当作未知；Windows 打包版生成的真实会话、完整 Python 单元及 Linux 分析器单元回归通过。
6. **部分当前测试夹具失效。** 对齐逻辑 ID、角色继承依赖、项目 Skill 选择键和 MCP 审批摘要；进程 SDK 测试改用独立的小型 HTTP 配置，等待 bootstrap 真正 ready，避免误开 GUI 后出现 WebView2 清理失败；Linux 临时 Home 使用支持事务语义的原生文件系统。新版任务返回值按 JSON 读取。当前 29 个原生场景及相关补测通过。

## 尚未修复的 SDK 回归

**SDK-ARTIFACT-PATH：传统制品接口返回绝对路径，违反公开契约。**

复现：`tests/test_artifact_publication_runtime.py` 使用当前锁定宿主及真实 xwork 制品写入接口，`xwork_artifact_info.sPath` 返回 `D:\...\workspace\artifacts\run-...\...-read.txt`。公开 `xwork.h` 仍声明该字段为工作区相对路径，因此用例正确拒绝此结果。

根因位于当前 SDK 的 `lib/xwork/src/xwork_core.c:1017` 附近：进程输出目录初始化把 `pAgent->sArtifactDirectory` 改成绝对路径；`xwork_observability.c:420` 之后仍把它拼成的路径视为 `sRunRelative`，并在约 473 行赋给公开的 `sPath`。这是共享目录字段的语义发生变化，不能仅把断言改成接受绝对路径来消除失败。

建议修复：分开进程日志的原生存储目录与传统制品的公开定位符。保留传统相对路径语义，内部文件访问继续使用独立的绝对路径；如使用独立 ArtifactStore，则明确采用该存储的定位符。补测无 Store/有 Store、父子 Agent、重启和目录迁移，再更新 SDK 锁定回执、重建受影响发行物并重跑门禁。

本轮未修改 SDK/依赖锁来掩盖该失败，也未声称修复完成。
