# 会话完成状态与按消息排序

侧栏会话在原运行转圈的位置显示最近一轮的结果：成功为绿点，失败、超时或队列启动前阻塞为红点；手动停止保持中性。运行中的准备、执行和停止状态继续使用原有提示，新运行优先于旧结果。结果同时提供悬停说明和屏幕阅读器文本，适配浅色、深色主题；聚焦、悬停和打开菜单不会再隐藏状态点。未读结果不会另画一个与运行结果冲突的绿点。

新增独立的最后消息时间，只由已接收的用户消息和完成的根回复更新。后端目录排序、侧栏列表、项目最近活动和时间线统一使用它；查看会话、重命名、配置、标题生成和其他元数据编辑不改变消息顺序。置顶和分组规则保留。重复发送同一队列 ID 不重复更新时间。激活时间仍用于记住上次打开的会话，与排序分离。

最后消息时间和运行结果保存在小型 `meta.json` 中，不依赖有保留上限的运行列表。新运行开始时清除旧结果，最终结果在运行销毁及插件结算完成之后保存。队列在创建运行前失败也保存失败状态。入队只更新时间，不清除结果，避免极快完成的运行被迟到的入队确认覆盖。读取失败的运行轮询不推断完成；显式设备重置会清除旧设备的临时状态。

旧元数据没有消息时钟或结果时，以原 `updated_at_us` 作为一次性基线，不使用激活时间，也不扫描可能很大的会话事件日志；下一次元数据写入即固定基线。历史结果未知时不补造成功状态。保留旧格式读取能力。活动字段不改变内容修订号，普通元数据写入合并最新活动，避免旧运行句柄覆盖它们。

完成回复才更新排序元数据，思考、流式碎片和子 Agent 的增量不产生排序写入。120,000 个碎片的原生测试验证了正文和排序元数据在事件过程中都不落盘；子 Agent 完成不移动根会话，根回复完成后才更新时间。可选状态保存失败不会中断模型回复或工具执行。

验证结果：

- GCC C11 `-Wall -Wextra -Werror -fsyntax-only` 通过，复用既有固定 SDK 与 xs 主机。
- 109 项相关前端回归通过；最终侧栏定向检查 24 项通过；264 个前端模块解析并连通。
- Chromium 1280px、360px 各 8 组真实 DOM 检查通过，包含状态、主题、焦点、设备重置、排序、回收站和分页行为。
- 新增真实 API 回归通过：只按消息排序、查看和改名不排序、回复更新时间、入队及重放、成功、失败、停止、模型启动前阻塞、重启保留、旧元数据基线稳定；仅使用本机模拟模型。
- 会话创建/恢复/导出/分叉、运行管理、完成/关闭屏障、队列顺序/幂等/提取/引导/停止恢复/重启，以及完成事件持久化回归通过。原会话测试仍断言事件格式 10，已同步到本轮之前主线已经使用的格式 11。
