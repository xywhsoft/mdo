# 2026-10-11 模型连接故障与持续重连

## 线上故障证据

日用客户端的 GLM-5.3 请求于北京时间 03:18:37 开始，03:20:40 结束，
实际尝试两次、约 122 秒，无模型内容事件，最终 HTTP 状态为 0。后续两次
恢复各尝试六次，最终为 HTTP 502。

以只读 SQLite 查询核对 ai.xywhsoft.com 的对应账号、模型和时间段。
服务器时钟实测比客户端快约 17.6 秒，对齐后这两次请求分别对应：

- 首次约 50 毫秒结束，`stream_interrupted`、无上游 HTTP 状态，收据为
  `released`。网关仅在拨号完成后调用 `on_send`；这种未发送即释放的记录
  将故障定位在向智谱建立连接阶段，不能由此区分 DNS、TCP 或 TLS。
- 第二次约 119.8 秒结束，已发送但没有有效上游 HTTP 响应，收据为
  `pending`。时间与客户端首次失败后的两分钟恢复预算截止相符。
- 随后多次 502 的收据同样在约 40–70 毫秒内中断，无有效上游 HTTP 状态。
  这些记录没有余额或额度不足的业务错误。

渠道为 `open.bigmodel.cn/api/coding/paas/v4/chat/completions`，单次总时限
十分钟，首个响应和空闲阶段时限均为两分钟。当前服务器 curl 无凭据请求
返回 HTTP 401，证明检查时能完成 DNS/TCP/TLS 并收到 HTTP 响应；没有提交
收费模型生成。历史记录未保留具体拨号错误，不能将中断进一步断言为供应商
故障、证书错误或某个 TCP 错误。未改变线上配置、密钥、收据或服务进程。

私有服务端摘录及客户端诊断只放在忽略的 `.build/model-reconnect-20261011/`。

## 修复行为

取消临时模型连接故障的六次尝试上限与两分钟总恢复预算。网络中断、超时、
临时限流、服务异常、无明确业务原因的上游错误，以及可安全替换的不完整
回复，持续恢复到成功、主动取消或调用方明确期限。

退避基数为一秒，指数增长并加入少量正向抖动，常规上限五分钟。遵守更长的
服务端 Retry-After，连续故障期间不会缩短间隔。一次完整回复成功后，下次
模型调用从首次尝试和最短间隔重新开始。诊断中的实际请求计数仍保留；
`uMaxAttempts=0` 表示该连接恢复策略没有固定次数上限。

明确的余额、额度、身份、权限和配置错误停止并准确报告。退出/切换账号、
取消和明确期限继续生效。不能替换的已交付回复不重放；未完成草稿的工具
不会执行；明确的格式和输出上限错误仍最多修复六次。
