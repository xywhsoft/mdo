# mdo 原生直连的实际时钟长稳

`tests/test_remote_soak.py` 使用隔离的网站副本、测试账号和 Home，执行真正的账号、中继、双族原生网关、HTTP、实时订阅和二进制传输。没有生产账号、模型或外部服务负载。每次测试要求新的收据路径，不续用中断后的时钟。完整验收至少连续 259,200 秒；短测永远不能产生 72h 通过记录。

默认每五秒读取原生直连会话，每十分钟修改标题并经仍在线的中继查询同一请求收据，然后往返传输约 328 KiB 的有效 PNG，消费者逐块延迟确认。每半小时保留七十秒无业务请求，仅处理真实 WebSocket 控制帧与实时通知，检验原生保活。每小时关闭旧连接、观察控制席位释放后，经实际原生账号管理器申请和消费新的单次票据，重新建立原生直连。不会重放结果不明的写操作。

会话修改遵守现有 ETag 前置条件。最初短测没有附带该前置条件，正确得到拒绝；补齐后通过。另一处短测直接关闭 TCP 即刻请求新控制票据，服务端尚未异步释放旧席位而正确返回 409。测试现完成 WebSocket 关闭，并通过真实设备列表观察席位释放，未放宽单控制端限制、重试写入或绕过授权。

原生账号会话必须在整个时钟期间自行保持有效。`refreshing` 表示短访问令牌已到期但仍有刷新凭据，不能仅因这个状态判定退出。测试同时检查实际 `MdoAccountHasSession()`、公开的刷新凭据可用性，以及每小时新控制票据与结束时真实设备列表请求能自行完成原生续期。测试代码不代办原生登录或安装令牌。只有独立观察者的短期 bearer 在测试结束后重新获取，用于随后执行原有撤权、热重载、原生 Unit 和退出回归，不作为账号存活的证据。

收据记录真实 PID、源快照与二进制 SHA256、宿主构建收据版本、读写/收据/二进制/事件/重连计数、内存和句柄。每分钟原子保存状态及进度；所有结果均不得包含票据或令牌。执行间隔超过十五秒、墙钟/单调时钟偏差超过五秒、进程退出、资源超限或断言失败均取消 72h 通过资格。Windows 长测临时阻止系统休眠，退出时释放，不修改持久化系统设置。旁置 `stop` 文件可取消测试。

短测 `.build/xrudp-soak/smoke-05/state.json` 和 `smoke-06/state.json` 通过：前者 35 秒，13 次读取、6 次写入和跨路径收据、5 次大文件往返、2 次重连；后者 25 秒，10 次读取、5 次写入/收据、4 次大文件往返、2 次重连。两轮随后均通过完整网站/原生管理器生命周期回归。收据时长还包含收尾检查，不能将其当作额外稳定传输时间。

Windows 稳定宿主的构建版本为 `c806e08`，核心和 xrudp 源字节已证明与当前 `13cc17b6` 一致；SDK `7edc866` 仅更新三项来源文字。按实际选定宿主记录 SHA 和版本，不把旧二进制伪称为新提交构建。长测将验证这组已构建运行时代码，不能代替 Android 实机、两个独立公网 NAT、完整独立协议控制帧/模糊测试，也不能代替原生多流/消息/游戏长期测试。

长测启动与通过结果另行记录；本提交只声明测试驱动和短测已完成。

首次实际长测在 902 秒因原先只允许 `signed_in` 的测试断言停止；停止前仍成功完成直连读取，累计 176 次读、2 次写入/收据/大文件往返，原生传输计数保持二，没有时钟间断或资源超限。保存的设备凭据也没有被清除。账号源码表明无活动界面时短令牌到期可进入 `refreshing`，但会话仍有效，原生服务调用才按需续期。因此该轮不记为长稳通过，也不据此声称账号失效。

第二轮真实长测已跨过十五分钟，`refreshing` 状态下继续完成直连读取及标题/收据/二进制往返，
没有安装令牌或加速期限。随后复查观察进程，发现 Windows 资源采样每次创建的新 ctypes
类型被指针缓存保留：十次采样增加十个类型。该轮因观察器自身的增长而主动取消，不记长稳通过。
修复后结构和系统函数只初始化一次，五百次采样类型数量不增长，并将观察器自己的 PID
纳入内存、句柄及增长上限。`tests/test_remote_soak_monitor.py` 和真实二十五秒到期/重连/
二进制/收据/生命周期短测通过（`.build/remote-soak-monitor-windows.log`、
`xrudp-soak-smoke-observer-fixed.log`）。后续以新提交、新收据重新起算完整时长。

第三轮实际长测从 `c125bfc1` 起算，使用新 SDK `7edc866` 的已核验 Windows 宿主，
未启用到期加速。`.build/xrudp-soak/mdo-72h-20261019-r3/state.json` 已终止失败：
3603.703 秒、684 次读取、6 次写入/收据/大文件往返、一次七十秒空闲检查。

消息、游戏与 UDP 故障长测，独立运行；本次账号错误不重置它们的时钟。

## 整点重连的账号续期竞态

根因是远程后台任务调用了非阻塞 `MdoAccountAcquireService`：访问令牌到期时它仅排队
续期并立即返回 false，任务把“续期尚未完成”误报为 `remote_login_required`。
短测通过真正的隔离账号续期请求增加 300 ms 延迟，稳定复现：
`.build/xrudp-soak/refresh-failure-repro-02/state.json` 在约 11.093 秒失败，
公开状态仍为 `refreshing` 且 `refresh_available:true`。故障发生于新票据前的设备列表，
不是 xrudp 丢包、打洞或服务端拒绝登录。第一次延迟实验未匹配实际刷新 URL，
其通过结果不作为复现证据。

新增 `MdoAccountAcquireServiceWait` 供后台任务使用：最多等待二十秒，复用已有
账号刷新工作和条件变量，不注册交互式登录等待项。调用取消最多百毫秒感知；
退出、账号 ID、登录 epoch 和持有引用的会话取消根共同约束，禁止等待跨越注销、
登录尝试或会话替换。失败清理部分凭据及引用，账号 Unit 等待 acquisition 归零。
本地关闭远程控制仍走原有即时路径；有会话但服务暂不可用时使用现有
`remote_service_unavailable`，只有确实无会话才报需要登录。

验证证据：

- `.build/xrudp-soak/refresh-wait-fixed-01/state.json`：40 秒真实传输、强制访问令牌
  到期及 300 ms 真续期延迟，三次真实重连成功，管理器完整收尾通过；不是长稳通过。
- `.build/remote-service-lease-windows-r2.log`：真正的网站/原生账号检查新鲜凭据、
  一秒延迟续期、40 ms 超时、取消、登录 epoch 变更、零交互等待项、注销引用排空；
  原有撤权、账号切换、禁用、原生 Unit/restore 和网站热重载也通过。
- `.build/service-lease-native-{windows,linux}-r3.log`：两系统执行从真实源码提取的
  lease/wait/release 函数，验证实际单调时钟、条件唤醒、线程、取消引用、相同 epoch
  下会话替换和停止排空。周围 HTTP worker 是受控状态夹具，真实续期由上一项覆盖。
  首次夹具缺少 XS 服务名，随后 Windows 缺少 stdio 声明，修正测试后均通过；
  未将这些夹具错误当作产品缺陷。

续期延迟和强制到期选项只适用于短测，一小时以上测试禁止开启。产品未添加调试路由。
账号文件中的其他任务修改原样保留，本修复只提交新增等待函数及其必要调用/测试。
后续第四轮使用新提交和新收据重新起算，最终仍需连续实际 72 小时和完整收尾。
