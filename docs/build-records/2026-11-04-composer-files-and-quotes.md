# 文件附件输入与聊天选区引用

## 改动

- 主输入框的文件选择、拖放和文件粘贴共用导入器。PNG/JPEG/WebP 保留原视觉附件流程，普通文件不再被图片类型检查拒绝。
- 48 KiB 内且能解码的文本、JSON 和代码文件保存为上下文快照，支持 UTF-8 与带 BOM 的 UTF-16。超出提示词剩余空间、较大文本和二进制文件保存原始字节，引用路径为 `@uploads/<随机标识>.<扩展名>`。
- 原文件位于 `mdo-home/sessions/<project>/<session>/uploads/`。用户提示词和草稿只保存别名，不保存机器绝对路径，不使用 Base64 封装原文件。运行时为文件工具挂载当前会话目录，并向进程工具说明实际目录。
- 每个原文件最大 8 MiB，每会话最多 32 个原文件、合计 64 MiB。文件随会话保留；移除输入框引用不删除可能被历史消息使用的原文件。会话分叉、备份、导入恢复均包含 uploads。
- 原文件上传采用有稳定标识的 PUT；相同内容重复确认，不同内容返回冲突且不覆盖，允许网络临时故障时有界重试。
- 聊天正文拖选后显示“添加到对话”，支持跨消息和 selectionchange/键盘选区。跨消息引用过滤时间戳、操作栏、用量统计，保存正文快照与源会话/事件身份。超出已有上下文预算时明确提示，不截断内容。
- 附件行在内容、权限、来源和语言未变时保留 DOM，避免后台轮询重绘打断移除、预览和焦点。
- 增加中文、英文、俄文文本与上传 API 的 Application SDK 契约。未增加依赖。

## 验证

1. 49 项 Node 回归通过，涵盖文件分类、完整文本、UTF-16、二进制与大文本回退、上下文容量、跨会话取消、晚到上传结果、稳定附件按钮，以及既有图片、草稿提交与队列规则。
2. 实际打包 EXE + 本地模型桩通过：原字节上传/同内容重放/不同内容冲突；只读权限下 read 读取 `@uploads/`；分叉文件逐字节相同；包含非 JSON 内容的 `.json` 与二进制 `.bin` 经生产备份、预检、恢复后完整保留。只调用本地模型桩两次。
3. 浏览器完整页面通过：JSON 拖入与文件粘贴、PDF 原文件、无会话时自动创建、新任务混合 JSON/PNG、跨消息正文引用、键盘选区入口、真实指针拖选、点击引用、移除引用和持久草稿恢复。390×844 无横向溢出。最终独立验收页面无控制台错误。

剪贴板文件链路使用浏览器 ClipboardEvent/FileList 回归。本轮资源管理器真实 Ctrl+C/Ctrl+V 验收未完成：独立 Windows 窗口的首次测试配置没有装入嵌入 VFS，桌面自动化也未能稳定定位输入；测试进程已停止。不能将浏览器文件事件通过表述为该原生操作已通过。未修改 E:\software\mdo 的程序、账号和会话。
