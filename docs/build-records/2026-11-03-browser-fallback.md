# Windows WebView 启动失败自动打开浏览器

默认通过实际 WebView Loader 尝试创建窗口，兼容应用自带 Fixed Version 运行时。初始化失败后保留服务，等待 Ready 和实际绑定端口，再通过 ShellExecuteW 打开系统默认浏览器。请求原子去重；再次运行程序会唤起原进程并重新打开页面。显式 headless 和独立服务版不弹浏览器，正常关窗继续停止服务。浏览器调用失败时提供中文/英文手动访问地址提示。

实现位于 mdo 锁定的 xs SDK 补丁；未修改独立 xserver checkout。补丁生成器现在按管理文件替换，保留其后的其他 SDK 修复。现有 SDK 原地更新，没有建立额外工作树或完整副本。

验证：

- 原生状态机测试通过，包含并发、就绪顺序、重复通知、显式 headless、正常窗口、装配失败、关闭和浏览器调用失败。
- 实际 xs 的缺少运行时、创建失败、headless、装配失败、正常窗口五组验收全部通过。前两组 HTTP 页面可访问且服务保留；零端口分配、显式端口覆盖和二次启动唤起均通过。
- Windows xs/xsw 和根目录 mdo.exe 重新构建通过；完整 mdo 也已通过真实浏览器回退启动并给出监听地址。
- 浏览器视觉验收因 Computer Use 无法可靠识别 Windows 当前 URL 被工具终止，没有声称视觉验收通过。
- 测试服务 PID 11400 已于后续工作中核对程序路径及测试 Home 后停止。
