# 2026-10-30 OpenAI 正式对话工具定义兼容修复

用户在 0.8.1 删除并重新添加 OpenAI 供应商后，三个模型均显示已验证，正式对话仍失败。本次先核对日用 Home 的失败事件，再读取原生运行时工具定义，使用现有账号密钥做有界对照请求。

## 原因与证据

失败会话 `51db53e3db1c3f05808f4aebd0c7c731` 的最后失败事件为 HTTP 400、`invalid_request`，请求已到达上游。此前 HTTP 0 的本地能力校验错误与本次问题不同。

对 `gpt-6.1-terra` 的真实请求返回 `invalid_function_parameters`：`skill` 工具声明 `strict:true`，但 `required` 没有包含可选属性 `action`。这是正式工具定义的严格模式声明不兼容。旧验证仅携带 `strict:false` 的空参数探针，没有覆盖正式工具目录，所以产生了基础测试通过、正式对话失败的漏检。

对照结果（同一账号、同一模型）：

| 请求 | 结果 |
| --- | --- |
| 13 个原始工具定义，流式请求 | HTTP 400，缺少 `skill.action` 的 required 声明 |
| 相同 13 个定义，经过修复适配，流式请求 | 成功返回可见回复 |
| 13 个定义加指定连接探针，流式请求 | 成功返回合法探针调用 |

所有真实请求仅解析模型响应，没有执行工具。密钥由现有加密凭据在原生进程内解封、用后清零；未写入源码、日志或验收文件。

## 改动

- `54b3cff2`：在 SDK 的公开请求正文回调中适配不兼容的严格声明。保留兼容的 `strict:true`，为具有可选参数等约束的函数使用非严格模式；原 schema、工具名及执行权限不改。请求级回调继续转发，测试覆盖回调上下文与缓冲区所有权。
- `a6bc7ebb`：验证发送流式请求，并携带 SDK 内置文件/进程工具以及本机注册的 skill/web/MCP 桥接定义；强制选择不执行的命名探针。记录升级到 schema 2、`runtime-tools-stream-v2`，旧探针记录失效；工具定义也纳入指纹。
- `d599b32c`：增加独立运行内嵌应用的打包程序验收，并保持不存在的调用方回调为空。
- `38c9386a`：保留 Chat Completions 原有非严格默认；回归夹具使用三种协议各自的 SSE 事件。

验证使用固定的 SDK 定义获取工具元数据，不启动用户 Agent 生命周期、不读取会话历史、不执行工具。它覆盖本机内置工具的传输格式，不代表任意自定义角色、按需加载的第三方工具或完整上下文极限已验证。
