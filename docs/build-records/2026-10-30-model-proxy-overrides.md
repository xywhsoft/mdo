# 供应商及模型独立代理（2026-10-30）

模型管理的供应商创建向导、供应商编辑页、模型新增/编辑页加入可展开的高级网络配置。供应商及模型默认直接跟随全局设置；模型还可明确选择跟随供应商。可独立选择直连、系统代理、HTTP CONNECT 或 SOCKS5，并管理主机、端口、用户名、密码引用及绕过规则。已有只读内置条目的参数保护保持不变。配置语义及示例见 [配置说明](../configuration.md)。

代理覆盖替换整组参数，未填写的凭据不会从其他层级混入。系统代理按实际目标重新解析；全局 CA 设置保留。获取模型列表使用供应商策略，连接测试和生成使用模型策略。编辑期间的草稿、保存回读、冲突检查和表单重基线沿用现有机制。

## 已验证

- 12 组实际本地 TLS 场景通过，覆盖默认/显式全局、供应商继承、模型覆盖、直连、系统代理、绕过及密码隔离；失败凭据未发送请求。
- 最终程序的目录获取通过 HTTP CONNECT、SOCKS5 和直连验证，依据代理服务器实际连接次数确认路由；非法配置及不可读密码在联网前失败。
- 设置保存、凭据加密、重启恢复、模型三个协议及既有全局代理回归通过。
- Windows/Linux 的实际 Agent 路由测试通过，包括全局关闭而模型单独选择系统代理，以及共享客户端生命周期。
- 前端 1214 通过、2 项原有跳过；237 个模块图检查通过；模型、配置及 SDK 构建契约共 14 项通过。
- Windows 原生宿主及程序编译通过；Android ARM64 原生宿主重新编译，独立 APK 的 v2/v3 签名、对齐、原生库哈希及系统代理 Java 类检查通过。

所有模型请求均使用本地夹具，没有调用线上计费模型。其他扩展依赖改动未覆盖、未混入提交。

## 同时修复的宿主缺口

目录获取通道曾配置 `Config.Proxy`，但宿主未选择 `HTTP_CLIENT_PROXY`，也未编译对应源文件，导致请求成功却没有经过代理。新增端到端测试复现了这个行为。现在同时补齐模块选择、源文件注册、导出及生成的声明，并在创建客户端后核对保留的代理对象，防止能力缺失时静默直连。Windows、Android 的宿主均已重建，SDK overlay 和构建回执已核对。
