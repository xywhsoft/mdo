# mdo 基础 Agent 优先级

2026-10-03 用户调整后的当前实施方向。本文优先于旧实施计划中的功能
完备度、治理和追溯细化要求；保留已经可用的能力，但不以它们作为日常
开发的主线。mdo 回到前端驱动、类似 pi 的轻量 Agent：少量配合良好的
工具，顺手的聊天，清楚的项目与会话，容易配置的模型与扩展。

## 接下来按实际使用闭环推进

1. **模型与对话可用**：内建默认模型改为 `ornith-1.5-35b`。真实打包程序
   验证普通/流式回复、工具调用、停止、用量和图片输入。旧 Ling 会话、
   项目默认值和草稿仍可引用旧 ID；新的运行使用 Ornith。
2. **工具闭环**：阅读、搜索、编辑和命令执行贯通；清楚展示结果和错误，
   支持取消和后台任务。联网搜索、Skill 和自定义工具按需加载，减少
   空任务上下文占用。先检查现有实现的实用缺口，再补必要能力。
3. **核心聊天手感**：输入区切模型/思考/权限，流式显示，停止/继续、
   排队，复制/重试/分叉，待办、审批和询问。草稿、附件和项目切换要
   自然，重点检查正在操作时的焦点、滚动和响应。
4. **项目与会话**：快速新建、选择目录、切换、搜索、重命名、归档和
   删除；恢复上次会话。整理入口和默认值，减少操作步骤。
5. **设置与轻量扩展**：模型连接、基本偏好、权限、联网、Agent/子 Agent、
   Skill、自定义 C 工具及 MCP。先让常用配置容易完成，复杂选项渐进展开。

暂缓继续扩展备份恢复的持久提醒/确认细节、治理面板、审计与追溯、
回执和各种极端恢复情形。已经实现的文件格式和基本数据保护继续维护，
遇到实际阻断使用的问题再修；不因“生产级”一词不断扩大产品范围。

## 开发节奏

每个增量要能指明用户少了哪个障碍，并提供可以直接试用的 `mdo.exe`。
完成一个功能或阶段就提交 Git。验证以改动相关的有界功能检查、真实
打包交互和必要的跨平台回归为主；不做压力或高负载测试，也不在无关
功能上反复增加验收层级。正式发布继续使用现有完整发布门禁。

便携布局和原生 HTML/CSS/JS 保持：`mdo.exe` 加 `mdo-home/`；原生窗口的
WebView2 数据写在 Home 的 `data/cache/webview2/`。外部文件优先，单个
程序仍使用内置资源。构建不依赖前端 npm 工具链。
