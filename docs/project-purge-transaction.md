# 项目彻底清除的事务边界

旧版项目把会话和定义放在同一数据桶中。新版 Home 已拆分存储，因此项目设置中的“取消注册”只删除 `projects/<id>.json`，不能冒充彻底清除。本文件给出恢复旧版清除入口前必须满足的实施条件。项目设置可查看并刷新 `GET /api/v1/projects/{project}/purge-preview` 的瞬时清单；`advisory: true` 明确表示其结果不能授权删除。

## 清除范围

一次项目清除须覆盖以下 Home 路径，扫描和搬迁均以经过验证的项目或计划 ID 构造路径，不接受客户端提供的文件名：

| 数据 | Home 路径 | 备注 |
| --- | --- | --- |
| 项目定义 | `projects/<id>.json` 及 `.bak` | ETag 必须与执行时 revision 一致 |
| 会话 | `sessions/<id>/` | 包含元数据、账本、UI 事件、草稿、队列、反馈、图片、产物、待办及各自备份 |
| 项目记忆 | `memory/projects/<id>.json` 及 `.bak` | 必须阻止 Agent 记忆工具并发写入 |
| 关联计划 | 各 `schedules/<schedule-id>.json`、`.bak` 及 `schedules/history/<schedule-id>.jsonl` | 由有效计划定义的 `project_id` 关联；无效定义使事务拒绝开始，不能猜测归属 |
| 旧版迁移提示 | `migration/session-prompts/<id>/` | 属于项目的历史迁移侧车 |

`memory/audit.jsonl`、`schedules/audit.jsonl` 与 `migration/report.json` 是跨项目记录，不能直接搬走；执行前必须确定保留、裁剪或脱敏策略，并在确认界面准确说明。全局新任务草稿与启动偏好也不是项目数据桶，若当前选中项目被清除，应重置其中的引用而不删除其他项目的内容。

## 并发与持久化契约

1. 现有 `MdoHomeMountLocked` 已通过 `.mdo.lock` 持有整个外部 Home 的跨进程独占锁；`tests/test_packed_home_lease.py` 验证第二个打包进程无法同时挂载，故当前单进程 Home 架构不需要另加一把项目级跨进程文件锁。仍须引入**进程内项目生命周期读写门**：项目定义、会话创建/打开/分叉与生命周期、运行启动、附件和 UI 侧车写入、项目记忆、计划创建/修改/触发都须在进入各自管理器锁之前取得共享门；清除取得独占门。活动运行及持有会话运行态的对象必须在整个存活期持有共享门。统一锁顺序为“项目门 → 管理器锁 → Home 操作”。若将来允许多个进程共享同一 Home，此门须升级为真正的跨进程租约并重新验证所有写入路径。
2. 独占后重新读取项目 ETag，重扫全部目标并检查任何会话运行态、交互运行、计划执行、未识别目录或无效计划。预览生成值仅用于展示，不能替代这一步。不能完整枚举或不能锁住时返回冲突/不可用，不移动任何数据。
3. 在 Home 内创建带唯一事务 ID 的清除暂存目录与清单。清单列出每个源路径、目标路径、类型和状态，发布前刷盘。逐项同卷无覆盖搬迁，每次更新并刷盘清单；全部成功后写入提交标记。提交前任何失败按清单逆序搬回，回滚失败则保留清单并禁止继续对该项目写入，等待恢复。
4. 启动时在项目、会话、计划、记忆管理器初始化之前恢复未完成清单：提交前回滚，提交后保持项目不可见并提供可审计的暂存清理流程。恢复同样取得独占租约。不得在服务已接受新请求或计划执行后才开始恢复。
5. 搬迁必须由 Home 锚定路径接口执行，拒绝符号链接、穿越路径和现存目标；xrt `6040abda` 已提供 `xrtRootRenameNoReplace`，xs `5f1e31a` 已同步宿主快照，mdo 的 `MdoHomeRenameNoReplace` 只接受经过验证的 Home 相对路径，不创建 Home 或目标父目录。该原语尚未组成清除事务；不能用 `xrtPathJoin` 加普通 `xrtPathRename` 来处理可由用户修改的项目目录。

## 可验收条件

- 预览与执行均覆盖空项目、有会话/附件/待发队列/记忆/计划的项目；只读预览在纯单文件启动时零落盘。关联计划被停用也必须搬迁，其他项目数据逐字节不变。
- 活动会话、运行中计划、并发创建及过期 ETag 被拒绝，事务前目标无移动；模拟每个搬迁节点失败和进程中断后，重启自动恢复且不出现半清除项目。
- Windows、Linux、macOS 均验证同卷搬迁、大小写规则、拒绝符号链接与不可用文件句柄。验证结果与仓库常规有界测试一起运行，不做压力或高负载测试。
- 界面展示预览范围、不能清除的原因和共享记录处理方式；确认后以服务端最终事务结果更新项目/会话导航，失败时保留当前选择和可追溯错误。

当前只读预览已补报项目定义与项目记忆的 `.bak`、会话目录和旧版会话提示侧车是否存在；这些存在性字段不代表清单已具备执行权限，也不替代事务中的锁内完整遍历。

## 生命周期门接入进度

`project_lifecycle.h` / `src/projects/lifecycle.c` 已提供进程内共享/独占租约。取得租约不等待其他拥有者；冲突返回 `XWORK_ERROR_CONTEXT`。服务由 bootstrap 在 Home 后、各管理器前初始化，关闭后停止新取得；尚存的租约持有旧注册表直到最后一个引用释放，因此重新初始化不会使旧释放错误地解锁新注册表。空闲键及时回收，不写入磁盘。

门键保守地折叠 ASCII 大小写并去掉尾随点，覆盖 Windows 和默认不区分大小写文件系统的路径别名；持久化 ID 和路径不改写。Linux 上不同大小写或尾随点的 ID 仍分别存储，但共享排他范围。

| 写入边界 | 当前状态 | 后续要求 |
| --- | --- | --- |
| 会话创建、打开、加载、分叉及基于句柄的生命周期/元数据/账本操作 | 已接入 | 初次文件操作和管理器锁之前取得共享租约，准备与失败回滚全程持有；分叉继承源租约 |
| 会话事件桥、运行态和 Agent 回调拥有者 | 已接入 | 事件桥持有同一租约直到其最终释放；只关闭会话句柄不能允许清除 |
| 项目定义写入 | 未接入 | Create/Replace/Unregister 在项目 writer 锁之前取得共享租约；清除内部读取保持在独占范围 |
| 草稿、队列、反馈、图片、待办等直接侧车 API | 未全量接入 | 不依赖 HTTP 调用恰好加载会话句柄，逐项核对独立写入入口 |
| 记忆管理器写入及跨项目导入 | 未接入 | 项目记忆在记忆锁之前取得租约；导入在任何发布之前覆盖全部关联项目 |
| 计划定义、claim、finish 与计划运行 | 未接入 | 定义、执行准备和持有运行对象的整个生命周期均覆盖；还须复核全局设置重载 |
| 旧版迁移发布 | 未接入 | 覆盖其涉及的项目及回滚，不能与清除并发发布同一目录 |
| 清除与崩溃恢复 | 未实现 | 完成所有写入入口后，再接入独占、失败隔离、暂存清单、回滚与启动恢复 |

`tests/test_session_runtime.py` 的有界 TCC 探针验证共享引用保持、不同项目独占、大小写/尾随点别名、跨线程拒绝、服务关闭/重新初始化后的旧引用释放；还验证独占期间会话创建/打开/加载拒绝且无新目录、加载句柄与保留 AgentSession 阻止独占，以及失败创建回滚后的租约释放。当前覆盖不能证明整个项目已可清除，清除入口继续保持未开放。
