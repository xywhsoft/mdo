# 项目彻底清除的事务边界

旧版项目把会话和定义放在同一数据桶中。新版 Home 已拆分存储，因此项目设置中的“取消注册”只删除 `projects/<id>.json`，不能冒充彻底清除。本文件给出恢复旧版清除入口前必须满足的实施条件。项目设置可查看并刷新 `GET /api/v1/projects/{project}/purge-preview` 的瞬时清单；`advisory: true` 明确表示其结果不能授权删除。

## 清除范围

一次项目清除须覆盖以下 Home 路径，扫描和搬迁均以经过验证的项目或计划 ID 构造路径，不接受客户端提供的文件名：

| 数据 | Home 路径 | 备注 |
| --- | --- | --- |
| 项目定义 | `projects/<id>.json` 及 `.bak` | ETag 必须与执行时 revision 一致 |
| 项目新任务草稿 | `data/project-drafts/<id>.json` 及存在的备份 | 独立于会话目录；不能遗漏尚未创建会话的输入 |
| 会话 | `sessions/<id>/` | 包含元数据、账本、UI 事件、草稿、队列、反馈、图片、产物、待办及各自备份 |
| 项目记忆 | `memory/projects/<id>.json` 及 `.bak` | 必须阻止 Agent 记忆工具并发写入 |
| 关联计划 | 各 `schedules/<schedule-id>.json`、`.bak` 及 `schedules/history/<schedule-id>.jsonl` | 由有效计划定义的 `project_id` 关联；无效定义使事务拒绝开始，不能猜测归属 |
| 旧版迁移提示 | `migration/session-prompts/<id>/` | 属于项目的历史迁移侧车 |

`memory/audit.jsonl`、`schedules/audit.jsonl` 与 `migration/report.json` 是跨项目记录，本方案保留原记录，预览界面明确说明不随单个项目清除；工作区源文件也保留原位。全局新任务草稿与启动偏好不是项目数据桶，若当前记录指向待清除项目，应把该记录作为条件目标纳入同一事务；其他项目和无明确项目归属的草稿保留。引用保护器已实现，业务执行入口尚须组合使用。

## 已实现：只读候选清单

`project_purge.h` / `src/projects/purge_inventory.c` 提供独立、可复用的只读清单。
服务端构造上表八个固定根和当前有效计划的定义、备份、历史路径；遍历完整项目
会话桶和迁移侧车，统计文件、目录及字节数，并记录每个候选根的 no-follow 文件
身份。计划备份/历史属于当前有效定义的命名空间，即使备份记录的是计划改派前
的项目，也随当前定义归属。不能从孤立备份或历史文件猜测项目归属。

扫描检查目录身份、真实类型和便携 UTF-8 文件名；拒绝链接、孤立/未知计划项、
计划诊断、磁盘定义与缓存归属/revision 不符、扫描期间计划 generation 变化及
读入失败。上限为 1024 个候选根、8192 个遍历节点、16 层目录、每个计划文件
256 KiB；超过上限直接失败，不返回部分清单。共享预览仍可与普通写入并发，
文件身份记录不等于未来搬迁授权，更不能证明外部程序没有同时修改文件。

HTTP 预览整个 handler 保留共享项目租约。直接 C 调用可自行取得共享租约，
或接收调用者拥有的当前独占租约在排他范围内重扫；错误项目、共享及旧注册表
租约不能充当执行拥有者。界面列出所有返回的候选路径、草稿/备份、计划备份/
历史和数量，读取失败清空旧清单。没有发布删除令牌或新增清除执行入口。

`tests/test_api_runtime.py` 经真实 xs/TCC 验证完整路径和物理统计、GET/HEAD
零数据写入、独占内重扫及错误拥有者拒绝、备份改派归属、孤立计划、缓存归属
不一致、深度和节点上限、Windows junction 拒绝及外部哨兵保留。节点上限用复制
源的四节点限额验证，不生成大量文件。测试在旧数据成功导入后重启隔离的空
测试 Home，避免把要求重启的旧 manager 与导入后磁盘代混用。

## 已实现：全局引用保护

`src/api/project_references.h` 的 `MdoApiProjectReferencesBegin` 只接受当前独占
项目租约；保护器独立保留其引用，按“选择锁 → 草稿锁”的顺序解析两个全局
记录，读取前后核对 no-follow 文件身份、类型和大小。全局草稿复用完整 schema
解析，只在 `new_task.project_id` 精确匹配时加入；上次会话选择按 `project_id`
匹配。损坏或变化的任意记录使整个保护器失败，不返回部分目标，也不改动数据。
无项目归属的旧草稿、其他项目记录和历史全局备份保留。

调用者须在同一线程持有保护器直到 Home 事务提交或补偿结束，把其目标与新扫
项目清单合并排序后一次搬迁。不得取得 Home/计划管理器锁后再申请保护器。
释放顺序为草稿锁、选择锁、租约引用。HTTP 的选择读取/写入使用同一选择锁，
PUT 继续保留会话租约到最终写入。全局草稿 PUT 在最终草稿锁前保护引入/保留
的项目；部分更新先读取归属、放锁取得租约，再检查 revision 和归属，无法保护
时拒绝发布。显式解除 `new_task` 或无归属输入只需要草稿锁。首次默认工作区及
已有会话/计划派生的未注册项目仍可用；无法核实归属时保留输入并报错。

`tests/test_project_references_runtime.py` 使用隔离 Home 的真实 xs/TCC HTTP
请求验证无 Home 零落盘、错误拥有者拒绝、默认/未注册项目输入、两个条件目标、
畸形记录拒绝且锁可再次取得、全局草稿实际写入点始终持有租约、另一项目的草稿
与选择 writer 确实等待锁并在释放后保存。两种 writer 分别与一个本机保护线程
交错，不运行负载测试。复制源的提交前失败使项目和全局记录一起回滚；成功后
只移除当前关联引用，另一个项目和无归属输入逐字节保留。迟到的已清除项目
引用被拒绝。故障控制仅存在于测试副本，正式应用没有测试路由。

这项已组合到下面的 C 业务协调器，尚未接到清除 HTTP 执行入口、预览范围或
前端结果恢复。持久请求/结果凭据仍缺；不能把租约与草稿 revision 校验当作
跨重启的清除幂等协议。

## 已实现：业务协调器与计划缓存收敛

`MdoProjectPurgeExecute(ProjectId, ExpectedRevision, Result, Error)` 取得目标项目
独占租约，重查定义 revision、完整会话目录诊断、会话运行态和未结束的产品 Run；
随后在排他范围重新扫描数据，锁住当前全局引用，再取得计划缓存保护器。
任何预检失败均不创建清除日志、不移动数据。错误参数、缺少定义、过期版本、
项目忙和不可用分别返回状态；可省略 `Error`，`Result` 始终初始化。

计划保护器固定新清单的 generation，核对全部关联计划的缓存、原生注册、
enabled、定义代和活动执行数；已停用计划也要核对和撤下。不能只检查原生
`GetInfo`，因为 xwork 会保留已取消注册的稳定记录；实际注册集由有界枚举确认。
保护器独立保留项目租约并在同一线程持有计划锁，直到存储提交或补偿结束。

存储报告 `Committed=true` 后，即使清理返回失败，也必须撤下全部关联原生计划
和 mdo 缓存，推进计划 generation，并通知受影响的会话/记忆目录代。缓存提交
重复调用返回同一结果，不重复推进代；此前取得的不可变快照仍可读取。
单个计划撤下失败仍继续处理其余项，尝试停用残余原生记录，冻结 Home 和 mdo
计划认领，并把独占租约留到 manager 关闭。未完成的提交前补偿也采取冻结与
隔离，保留原缓存元数据和日志，重启先恢复存储再重新装载管理器。

“已提交但须重启”和“尚未提交、须重启恢复”都返回 `RESTART_REQUIRED`，
由 `Result.Committed` 区分；不得因一个错误码自动重试。正常补偿完成返回
`ABORTED`，原数据和缓存代保持。第一次提交后清理失败、第二次恢复成功时，
以最终提交/恢复事实返回成功，不把已清除数据误报成未提交。

`tests/test_project_purge_runtime.py` 在十个隔离 Home 运行真实 xs/TCC 应用，
验证过期版本、会话租约、无 mdo 租约的原生计划运行、错误拥有者/缓存代、
计划取消注册和配置不一致、全局 JSON 损坏的零移动拒绝；正常补偿、无会话/
记忆/计划的定义清除、条件引用保留、全部计划撤下、三类目录代更新及旧快照
保持。另覆盖未完成补偿、第二个原生撤下失败、提交后持续/一次性清理失败、
存储提交后缓存同步前的进程退出和重启收敛。工作区、其他项目、共享审计/
报告及浏览器缓存逐字节保留；迟到全局引用写入被拒绝。故障控制仅在测试副本，
没有对日常 Home 执行清除，没有联网或压力/高负载测试。

该协调器尚无持久客户端请求与结果凭据，**不能直接开放 HTTP 删除入口**。
下一阶段须把请求 ID、项目/版本和终态结果与存储提交/恢复协议结合，再接入
预览条件引用、前端两步确认、响应丢失核对及清除后的选择/导航恢复。

## 并发与持久化契约

缓存 Home 的旧数据导入已实现独立的全 Home 写入冻结与启动恢复，见 [Home 导入事务](home-import-transaction.md)。其固定数据根、只能向空用户数据 Home 发布的边界不能用于项目清除。候选清单、保留策略、[项目 Home 存储事务](home-purge-transaction.md)和上述 C 业务协调器已实现；持久请求/结果及前端确认/导航恢复仍须接入。以下列出当前协议和剩余产品边界，不能把内部协调器通过记作产品清除完成。

1. `MdoHomeMountLocked` 通过 `.mdo.lock` 持有整个外部 Home 的跨进程独占锁；`tests/test_packed_home_lease.py` 验证第二个打包进程无法同时挂载。进程内项目生命周期读写门已接入下表全部写入者和活动拥有者；清除取得独占门。业务清除的锁顺序为“项目门 → 选择锁 → 草稿锁 → 计划锁 → Home 操作”，会话/记忆目录代通知在 Home 操作返回后执行。若将来允许多个进程共享同一 Home，此门须升级为真正的跨进程租约并重新验证所有写入路径。
2. 独占后重新读取项目 ETag，重扫全部目标并检查任何会话运行态、交互运行、计划执行、未识别目录或无效计划。预览生成值仅用于展示，不能替代这一步。不能完整枚举或不能锁住时返回冲突/不可用，不移动任何数据。
3. Home 内使用保留的 `.mdo-purge` 与 `.mdo-purge-cleanup`，同一 Home 一次只能有一个存储事务。不可变清单记录项目、日志/payload 目录身份及每个源根的路径、类型、身份和大小；发布前刷新。搬迁无覆盖并核对前后身份，全部成功后刷新并发布不可变提交标记。提交前失败先验证全部源/槽位位置，再按逆序搬回；提交后只退役清理。歧义不猜测，补偿失败保留日志并冻结 Home。当前尚缺独立的持久客户端请求 ID/结果协议。
4. 启动在取得整个 Home 跨进程租约后、业务管理器初始化之前恢复未完成清单：提交前回滚，提交后清理并保持项目不可见。这时尚未建立业务项目注册表，不能要求一个不存在的进程内租约；运行中协调器则必须持有已建立的项目独占。不得在服务已接受新请求或计划执行后才开始恢复。
5. 搬迁必须由 Home 锚定路径接口执行，拒绝符号链接、穿越路径和现存目标；xrt `6040abda` 已提供 `xrtRootRenameNoReplace`，xs `5f1e31a` 已同步宿主快照，mdo 的 `MdoHomeRenameNoReplace` 只接受经过验证的 Home 相对路径，不创建 Home 或目标父目录。Home 存储事务已使用此原语并核对移动前后身份；业务调用仍须持有项目独占并提供锁内新清单。不能用 `xrtPathJoin` 加普通 `xrtPathRename` 来处理可由用户修改的项目目录。

## 可验收条件

- 预览与执行均覆盖空项目、有会话/附件/待发队列/记忆/计划的项目；只读预览在纯单文件启动时零落盘。关联计划被停用也必须搬迁，其他项目数据逐字节不变。
- 活动会话、运行中计划、并发创建及过期 ETag 被拒绝，事务前目标无移动；模拟每个搬迁节点失败和进程中断后，重启自动恢复且不出现半清除项目。
- Windows、Linux、macOS 均验证同卷搬迁、大小写规则、拒绝符号链接与不可用文件句柄。验证结果与仓库常规有界测试一起运行，不做压力或高负载测试。
- 界面展示预览范围、不能清除的原因和共享记录处理方式；确认后以服务端最终事务结果更新项目/会话导航，失败时保留当前选择和可追溯错误。

当前只读预览已列出完整候选根并遍历统计内容；实际清除仍须在独占范围内重扫、校验 ETag 和运行态，逐项核对身份后搬迁，提交后同步计划缓存及运行目录。不能凭当前预览直接执行，也不能在搬走计划文件后继续使用旧 manager 缓存。

## 生命周期门接入进度

`project_lifecycle.h` / `src/projects/lifecycle.c` 已提供进程内共享/独占租约。取得租约不等待其他拥有者；冲突返回 `XWORK_ERROR_CONTEXT`。服务由 bootstrap 在 Home 后、各管理器前初始化，关闭后停止新取得；尚存的租约持有旧注册表直到最后一个引用释放，因此重新初始化不会使旧释放错误地解锁新注册表。空闲键及时回收，不写入磁盘。

门键保守地折叠 ASCII 大小写并去掉尾随点，覆盖 Windows 和默认不区分大小写文件系统的路径别名；持久化 ID 和路径不改写。Linux 上不同大小写或尾随点的 ID 仍分别存储，但共享排他范围。

`tests/test_session_runtime.py` 的有界 TCC 探针验证共享引用保持、不同项目独占、大小写/尾随点别名、跨线程拒绝、服务关闭/重新初始化后的旧引用释放；还验证独占期间会话创建/打开/加载拒绝且无新目录、加载句柄与保留 AgentSession 阻止独占，以及失败创建回滚后的租约释放。当前覆盖不能证明整个项目已可清除，清除入口继续保持未开放。

`tests/test_api_runtime.py` 在复制的应用中加入测试专用租约控制和检查点，正式应用不含这些控制。真实 HTTP/TCC 探针验证独占期间侧车、项目记忆及关联操作返回 `409 project_busy`，目标文件逐字节、目录清单不变，纯单文件 Home 不创建；直接项目写入（含空 Error 输出）、反馈修补与待办/图片/队列/过期清理助手也被拒绝。图片回滚没有删除预置附件，图片复制取得目标失败后可重新独占源项目。草稿检查点位于会话句柄释放之后，项目定义检查点位于发布之前，两处均无法取得独占。正常保存、无效正文和版本冲突后重新取得独占成功；直接 C writer 的重复创建和已取得租约后的过期 revision 修改/取消注册也验证了释放。

`tests/test_memory_runtime.py` 验证项目写入和公开目录导入的独占拒绝、全部项目取得前无 Home 写入、部分租约取得失败后的清理，以及在实际 store 发布点始终保留全部项目。受控最后一次发布失败后，已发布 store 被既有回滚删除，generation 不推进，全部租约可再次独占。Agent 解绑后 retained 工具目录继续阻止独占，目录释放后独占成功；全局记忆保持独立。测试发布检查点只存在于复制源。当前证据不覆盖清除事务、计划、旧版迁移或新增的记忆导入崩溃恢复。

`tests/test_schedule_runtime.py` 验证定义创建的零落盘拒绝、启停/删除/跨项目替换的独占拒绝、定义和审计字节保持、其他项目仍可独立写入，以及目标冲突后源租约释放。复制源检查点插入真实跨项目 Replace 和 catalog Create，验证解析后的归属/generation 二次校验；受控发布失败后的原定义补偿仍保留两个项目，批量启停更新与回滚失败后的兜底停用仍保留完整集合。所有失败清理后可重新取得独占，未改动开关的重载保持只读。上述证据覆盖定义和全局重载，尚不证明计划认领、完成和运行对象的整个生命周期已隔离。

同一探针的执行阶段验证一次认领实际推进 Beta 的 misfire 游标并认领 Alpha，所有发布点均保留两个项目；任一项目被独占时认领/立即运行不改动定义或审计，尚未到期的读取保持空闲。返回 claim 后、Agent 尚未创建时 Alpha 仍不可独占；历史发布后释放，重复完成不追加记录。统一任务已经 cancelled 时历史记录保持 cancelled。第二个定义发布被受控失败后，第一个已经发布，两个项目仍被隔离；历史写入失败后对应项目仍被隔离，manager 关闭后释放。这是进程内失败隔离，尚未提供新的跨重启修复协议。
