# 项目彻底清除的事务边界

旧版项目把会话和定义放在同一数据桶中。新版 Home 已拆分存储，因此项目设置中的“取消注册”只删除 `projects/<id>.json`，不能冒充彻底清除。本文件给出恢复旧版清除入口前必须满足的实施条件。项目设置可查看并刷新 `GET /api/v1/projects/{project}/purge-preview` 的瞬时清单；`advisory: true` 明确表示其结果不能授权删除。

## 清除范围

一次项目清除须覆盖以下 Home 路径，扫描和搬迁均以经过验证的项目或计划 ID 构造路径，不接受客户端提供的文件名：

| 数据 | Home 路径 | 备注 |
| --- | --- | --- |
| 项目定义 | `projects/<id>.json` 及 `.bak` | ETag 必须与执行时 revision 一致 |
| 项目新任务草稿 | `data/project-drafts/<id>.json` 及存在的备份 | 独立于会话目录；不能遗漏尚未创建会话的输入 |
| 会话 | `sessions/<id>/` | 包含元数据、账本、UI 事件、草稿、队列、反馈、图片、产物、待办及各自备份 |
| 项目记忆 | `memory/projects/<id>.json` 及 `.bak` | 必须阻止 Agent 记忆工具并发写入 |
| 关联计划 | 各 `schedules/<schedule-id>.json`、`.bak` 及 `schedules/history/<schedule-id>.jsonl` | 由有效计划定义的 `project_id` 关联；无效定义使事务拒绝开始，不能猜测归属 |
| 旧版迁移提示 | `migration/session-prompts/<id>/` | 属于项目的历史迁移侧车 |

`memory/audit.jsonl`、`schedules/audit.jsonl` 与 `migration/report.json` 是跨项目记录，不能直接搬走；执行前必须确定保留、裁剪或脱敏策略，并在确认界面准确说明。全局新任务草稿与启动偏好也不是项目数据桶，若当前选中项目被清除，应重置其中的引用而不删除其他项目的内容。

## 并发与持久化契约

缓存 Home 的旧数据导入已实现独立的全 Home 写入冻结与启动恢复，见 [Home 导入事务](home-import-transaction.md)。其固定数据根、只能向空用户数据 Home 发布的边界不能用于项目清除；下列项目清单、共享审计策略及恢复步骤仍须实现。

1. 现有 `MdoHomeMountLocked` 已通过 `.mdo.lock` 持有整个外部 Home 的跨进程独占锁；`tests/test_packed_home_lease.py` 验证第二个打包进程无法同时挂载，故当前单进程 Home 架构不需要另加一把项目级跨进程文件锁。仍须引入**进程内项目生命周期读写门**：项目定义、会话创建/打开/分叉与生命周期、运行启动、附件和 UI 侧车写入、项目记忆、计划创建/修改/触发都须在进入各自管理器锁之前取得共享门；清除取得独占门。活动运行及持有会话运行态的对象必须在整个存活期持有共享门。统一锁顺序为“项目门 → 管理器锁 → Home 操作”。若将来允许多个进程共享同一 Home，此门须升级为真正的跨进程租约并重新验证所有写入路径。
2. 独占后重新读取项目 ETag，重扫全部目标并检查任何会话运行态、交互运行、计划执行、未识别目录或无效计划。预览生成值仅用于展示，不能替代这一步。不能完整枚举或不能锁住时返回冲突/不可用，不移动任何数据。
3. 在 Home 内创建带唯一事务 ID 的清除暂存目录与清单。清单列出每个源路径、目标路径、类型和状态，发布前刷盘。逐项同卷无覆盖搬迁，每次更新并刷盘清单；全部成功后写入提交标记。提交前任何失败按清单逆序搬回，回滚失败则保留清单并禁止继续对该项目写入，等待恢复。
4. 启动时在项目、会话、计划、记忆管理器初始化之前恢复未完成清单：提交前回滚，提交后保持项目不可见并提供可审计的暂存清理流程。恢复同样取得独占租约。不得在服务已接受新请求或计划执行后才开始恢复。
5. 搬迁必须由 Home 锚定路径接口执行，拒绝符号链接、穿越路径和现存目标；xrt `6040abda` 已提供 `xrtRootRenameNoReplace`，xs `5f1e31a` 已同步宿主快照，mdo 的 `MdoHomeRenameNoReplace` 只接受经过验证的 Home 相对路径，不创建 Home 或目标父目录。该原语尚未组成清除事务；不能用 `xrtPathJoin` 加普通 `xrtPathRename` 来处理可由用户修改的项目目录。

## 可验收条件

- 预览与执行均覆盖空项目、有会话/附件/待发队列/记忆/计划的项目；只读预览在纯单文件启动时零落盘。关联计划被停用也必须搬迁，其他项目数据逐字节不变。
- 活动会话、运行中计划、并发创建及过期 ETag 被拒绝，事务前目标无移动；模拟每个搬迁节点失败和进程中断后，重启自动恢复且不出现半清除项目。
- Windows、Linux、macOS 均验证同卷搬迁、大小写规则、拒绝符号链接与不可用文件句柄。验证结果与仓库常规有界测试一起运行，不做压力或高负载测试。
- 界面展示预览范围、不能清除的原因和共享记录处理方式；确认后以服务端最终事务结果更新项目/会话导航，失败时保留当前选择和可追溯错误。

当前只读预览已补报项目定义与项目记忆的 `.bak`、会话目录和旧版会话提示侧车是否存在；这些存在性字段不代表清单已具备执行权限，也不替代事务中的锁内完整遍历。

## 生命周期门接入进度

`project_lifecycle.h` / `src/projects/lifecycle.c` 已提供进程内共享/独占租约。取得租约不等待其他拥有者；冲突返回 `XWORK_ERROR_CONTEXT`。服务由 bootstrap 在 Home 后、各管理器前初始化，关闭后停止新取得；尚存的租约持有旧注册表直到最后一个引用释放，因此重新初始化不会使旧释放错误地解锁新注册表。空闲键及时回收，不写入磁盘。

门键保守地折叠 ASCII 大小写并去掉尾随点，覆盖 Windows 和默认不区分大小写文件系统的路径别名；持久化 ID 和路径不改写。Linux 上不同大小写或尾随点的 ID 仍分别存储，但共享排他范围。

| 写入边界 | 当前状态 | 后续要求 |
| --- | --- | --- |
| 会话创建、打开、加载、分叉及基于句柄的生命周期/元数据/账本操作 | 已接入 | 初次文件操作和管理器锁之前取得共享租约，准备与失败回滚全程持有；分叉继承源租约 |
| 会话事件桥、运行态和 Agent 回调拥有者 | 已接入 | 事件桥持有同一租约直到其最终释放；只关闭会话句柄不能允许清除 |
| 项目定义写入 | 已接入 | Create/Replace/Unregister 在首次 Home 操作及项目 writer 锁之前取得共享租约；失败与成功都在清理后释放；清除内部读取保持在独占范围 |
| 草稿、队列、反馈、图片、待办等侧车 HTTP API | 已接入请求范围 | 路由显式声明项目范围，在调用 handler 前取得、handler 全部清理后释放；涵盖项目草稿、会话草稿/提交意图、队列、反馈、图片和待办读取及关联会话操作；无效 ID 保留原校验，OPTIONS/405 不取得租约 |
| 独立反馈修补 | 已接入 | 全局反馈列表不经过项目路由；Reconcile 自行在反馈锁前取得租约，拒绝独占期间的修补写入 |
| 图片/待办/队列等底层直接助手 | 已接入写入边界 | 待办投影/重置、图片事件写入/修剪/回滚、队列凭据及准备/认领/绑定、可修补凭据的附件引用查询和上传过期清理自行取得租约；跨项目图片复制保留源与目标，完整分叉事务由调用者继续持有租约 |
| 记忆管理器写入及跨项目导入 | 已接入 | 项目记忆在记忆锁之前取得租约；导入在 writer 文件锁、审计及任何发布之前取得全部关联项目的租约，保持到发布或既有回滚完成；项目记忆 HTTP 请求也覆盖整个 handler |
| Agent 记忆工具绑定与工具目录引用 | 已接入 | 工具绑定在更换 Agent 工具之前取得项目租约；解绑不释放仍被工具目录保留的引用，最后一个工具拥有者释放后才能取得独占 |
| 计划定义与全局启停重载 | 已接入 | 创建保护项目；替换同时保护原与目标项目；启停/删除/替换在只读解析后取得租约，再在写入锁内核对归属。全局开关变化保留完整 catalog 的项目集合并核对 generation，直到更新/回滚/兜底停用完成 |
| 计划 claim、finish 与运行拥有者 | 已接入 | 到期/显式认领在同步游标前保留完整 catalog 并核对 generation；成功 claim 转移项目租约到 manager，直到结果历史发布。Agent 回调拥有者独立持有项目租约，关闭记忆工具也覆盖最终 runtime 引用释放；关闭时销毁 Run 后、结果写入前由 claim 租约覆盖 |
| 计划持久化失败隔离 | 已接入进程内 | 游标同步失败保留整个关联项目集合，历史写入失败保留其 claim，直到 manager 关闭；不能将进程内隔离误记为新增的跨重启恢复事务 |
| 旧版迁移发布 | 已接入 | 只读构造完整 ID 映射（含默认 tasks 和哈希桶），首次暂存写入前取得全部共享租约，保持到发布或失败清理结束；部分取得失败无落盘且释放已取得租约 |
| 清除与崩溃恢复 | 未实现 | 完成所有写入入口后，再接入独占、失败隔离、暂存清单、回滚与启动恢复 |

`tests/test_session_runtime.py` 的有界 TCC 探针验证共享引用保持、不同项目独占、大小写/尾随点别名、跨线程拒绝、服务关闭/重新初始化后的旧引用释放；还验证独占期间会话创建/打开/加载拒绝且无新目录、加载句柄与保留 AgentSession 阻止独占，以及失败创建回滚后的租约释放。当前覆盖不能证明整个项目已可清除，清除入口继续保持未开放。

`tests/test_api_runtime.py` 在复制的应用中加入测试专用租约控制和检查点，正式应用不含这些控制。真实 HTTP/TCC 探针验证独占期间侧车、项目记忆及关联操作返回 `409 project_busy`，目标文件逐字节、目录清单不变，纯单文件 Home 不创建；直接项目写入（含空 Error 输出）、反馈修补与待办/图片/队列/过期清理助手也被拒绝。图片回滚没有删除预置附件，图片复制取得目标失败后可重新独占源项目。草稿检查点位于会话句柄释放之后，项目定义检查点位于发布之前，两处均无法取得独占。正常保存、无效正文和版本冲突后重新取得独占成功；直接 C writer 的重复创建和已取得租约后的过期 revision 修改/取消注册也验证了释放。

`tests/test_memory_runtime.py` 验证项目写入和公开目录导入的独占拒绝、全部项目取得前无 Home 写入、部分租约取得失败后的清理，以及在实际 store 发布点始终保留全部项目。受控最后一次发布失败后，已发布 store 被既有回滚删除，generation 不推进，全部租约可再次独占。Agent 解绑后 retained 工具目录继续阻止独占，目录释放后独占成功；全局记忆保持独立。测试发布检查点只存在于复制源。当前证据不覆盖清除事务、计划、旧版迁移或新增的记忆导入崩溃恢复。

`tests/test_schedule_runtime.py` 验证定义创建的零落盘拒绝、启停/删除/跨项目替换的独占拒绝、定义和审计字节保持、其他项目仍可独立写入，以及目标冲突后源租约释放。复制源检查点插入真实跨项目 Replace 和 catalog Create，验证解析后的归属/generation 二次校验；受控发布失败后的原定义补偿仍保留两个项目，批量启停更新与回滚失败后的兜底停用仍保留完整集合。所有失败清理后可重新取得独占，未改动开关的重载保持只读。上述证据覆盖定义和全局重载，尚不证明计划认领、完成和运行对象的整个生命周期已隔离。

同一探针的执行阶段验证一次认领实际推进 Beta 的 misfire 游标并认领 Alpha，所有发布点均保留两个项目；任一项目被独占时认领/立即运行不改动定义或审计，尚未到期的读取保持空闲。返回 claim 后、Agent 尚未创建时 Alpha 仍不可独占；历史发布后释放，重复完成不追加记录。统一任务已经 cancelled 时历史记录保持 cancelled。第二个定义发布被受控失败后，第一个已经发布，两个项目仍被隔离；历史写入失败后对应项目仍被隔离，manager 关闭后释放。这是进程内失败隔离，尚未提供新的跨重启修复协议。

`tests/test_schedule_executor_runtime.py` 在关闭记忆工具的隔离配置中验证 Agent 创建冲突且 Home 未落盘、失败创建/启动清理、模型回调期间的排他阻挡、执行器回收后直接保留的未启动 `xwork_run` 仍阻止独占、其最终销毁后释放。关闭检查点位于 Agent Run 销毁之后、FinishTask 之前，外部回调拥有者已释放但项目仍由 claim 保护；随后 cancelled 历史落盘，项目可独占。检查点仅存在于复制的测试源。任务面板取消计划 Agent 的停止链已接通，Windows 的真实 HTTP 与打包页验证见前端迁移记录；Linux 新增链路仍待恢复环境后复验。

旧版迁移的 HTTP/TCC 探针独占大小写/尾随点别名、默认 tasks 和哈希项目，验证 `409 migration_conflict`、源字节不变、没有 Home 或暂存目录，空 Error 的直接 C 入口同样拒绝。取得后续租约失败时，前面的项目可重新独占。报告写入与最终 rename 的受控失败验证整个清理期间保留全部租约，随后释放；成功发布也验证释放。检查点只注入复制的应用。此证据只覆盖进程内迁移生命周期，不证明项目清除、启动恢复、跨进程迁移发布或便携 GUI 的既有缓存 Home 导入已完成。
