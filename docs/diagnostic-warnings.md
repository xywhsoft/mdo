# 统一警告入口

非致命的配置、目录和能力检查问题统一进入通知区域的黄色警告图标。多个来源只占用一个图标，标题显示当前警告数量，点击使用公共 Layer 弹窗逐项显示原因、路径和处理建议。

正文滚动，底部“重新检查 / 关闭”固定。关闭详情保留未解决问题的图标；检查恢复正常后，相应条目自动移除，所有问题解决后隐藏图标。不会自动弹出阻塞窗口，也不把同一个问题重复追加为通知历史。

设置中的“诊断与存储”页面已移除。原页面仍有效的诊断进入此入口：Skill、MCP、C 模块、插件、扩展、知识库、会话、计划任务以及存储安全状态。存储仅在使用临时存储或一致性恢复要求重启时警告；正常的延迟创建 Home 不产生警告。存储、会话等没有对应设置页的条目直接显示原因和处理建议，不提供失效的页面链接。

旧版 `.mdo` 数据导入、导入事务及其预览/确认界面已经退役，`/api/v1/migrations/legacy` 和旧页面专用 `/api/v1/storage` 返回 404。删除的是转换程序，已有目录与用户数据不会因此被删除。当前 Home 的进程租约、原子写入、会话恢复和项目安全删除事务继续保留。

知识库根目录、启停配置、各启用知识库的元数据和索引可读取性纳入当前检查。未安装知识库、用户主动停用或正常关闭提示词注入，不构成警告。目录被普通文件占用时保留原文件，跳过知识库能力，普通任务可继续。内存分配和运行时内部错误仍按错误处理，不伪装成检查成功。

## 后续模块接入范式

- 检查器提供当前状态快照，使用 `app/include/mdo/diagnostics.h` 的 `MdoDiagnosticWarning` 生成标准条目：`domain / code / subject_id / path / message / remedy / settings_section`。
- 将来源快照接入已有 `/api/v1/diagnostics` 汇总；SDK 同步通过 `product.diagnostics.get` 读取。前端会自动聚合，模块无需再创建自己的警告按钮、提示条或弹窗。
- 稳定的 `domain + code + subject_id + path` 标识同一问题；恢复后不再上报。历史诊断没有 code 时按原有阶段及消息区分，保留同一文件内不同的故障。
- 返回结构化原因和处理建议，禁止包含密钥、访问令牌、原始服务响应或文档正文。前端以纯文本渲染。
- 统一入口也包含现有 Skill、MCP、插件、会话和计划任务诊断，以及后台发布的 warning 通知。后台通知仍可逐项“稍后提醒”，仅本次运行隐藏；本机未解决的检查问题不会被这个操作隐藏。更新和普通消息保留原入口行为。

知识库检查在请求诊断快照时只读执行；其他来源采用各管理器当前的诊断快照，不在通知轮询中执行插件代码或连接 MCP 服务。诊断独立于在线通知和更新检查，每 30 秒刷新；前台恢复、状态变更或点击“重新检查”时也刷新。每次请求最多等待 8 秒，不自动重试；状态获取失败或响应结构无效时保留上次结果，并明确显示检查暂不可用，避免把连接失败当作问题已解决。慢速更新检查不会阻止警告展示和重新检查。

状态按当前设备隔离。切换设备或服务运行代次后关闭旧弹窗，旧请求和旧按钮不能操作新设备。警告原文不写入浏览器偏好存储，已读状态仅保存内容指纹。
