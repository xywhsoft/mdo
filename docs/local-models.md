# 本地模型客户端

当前已包含商店查询、安装和资源管理、部署配置、llama.cpp 服务启停、模型接入及验证。Windows CPU 和 AMD Vulkan 已完成真实模型闭环；Linux、macOS、CUDA 仍待实机验收。

开发与测试使用单线程、当前项目原目录及已有宿主，不复制 app / SDK。真实验收只下载固定的小模型与 CPU/Vulkan 两份运行库，权重约 610 MiB。

## 已恢复的服务端合同

第十类为 `local-models`，逻辑 ID 前缀为 `local-model:`。固定版本配方为 `mdo.local-model.v1`，部署计划为 `mdo.local-model-plan.v1`。公开商店及后台已经由服务端实现，详见 `D:/GIT/home/docs/local-model-store.md`。

客户端使用相同的配方验证规则。ZIP 中只允许小型 JSON、Markdown、文本、Jinja 资料，不接受权重或程序。部署计划在本机再次校验所选配置、权重文件、总大小、固定运行时版本和摘要、平台及整体 fingerprint；不能只相信一个匹配的 fingerprint。

## 本轮安装结构

配方与运行库沿用既有扩展事务安装。模型权重单独保存为资源目录中的 `blobs/<SHA-256>`，未完成文件位于 `partial/`。资源目录可以选择其他磁盘，临时文件和最终文件位于同一资源目录，以根内改名发布，不在完成后复制一遍权重。

资源目录有独立所有权标记，属于当前 Home；切换默认目录只影响新安装，现有安装继续使用原资源目录。复制导入和下载的文件受管，引用导入的原文件不由 mdo 删除。

安装收据独立于下载历史，记录固定配方、运行时计划和所选文件。依赖安装完成后、权重下载前持有固定运行时租约；下载失败或中断后仍保留保护，阻止普通扩展操作覆盖或删除构建。配方不含程序，每个安装保留经验证的完整冻结计划，因此允许更新展示配方，旧部署仍使用原计划和资源。多个安装可以共用同一构建。现有扩展身份不支持同一逻辑 ID 的多个版本共存，冲突构建会拒绝覆盖，需要发布不同构建身份或先移除依赖，不能声称已实现任意版本并存。大型运行库附件仍属后续阶段，本轮复用现有外部工具 ZIP 限制。

模型文件的下载、暂停、恢复和校验复用下载中心。受控外部来源与独立磁盘的模型下载使用内置流式引擎，保留全局代理、CA、受控 HTTPS 跳转、Range 和 SHA-256；不会为使用 aria2 放宽跳转或目标文件归属约束。既有扩展和应用更新的 aria2 选择规则不变。

收据位于 `data/local-models/state.json`，检查计划位于 `data/local-models/plans/`。资源目录记录 Home 身份并持有独占文件锁；另一个 Home 不能同时管理同一资源目录。登记最多 128 个安装和资源目录，收据上限 16 MiB。无法解析或语义无效的原收据保持不变，管理器进入只读状态，不影响普通会话加载。

同一安装计划重复提交返回同一安装。退出或崩溃后不会自动恢复大文件流量，用户在本地模型页重试或在下载中心恢复。任务由同一个资源写入器执行；清除下载记录不会删除已安装文件。下载内容先验证完整大小及 SHA-256，再根内改名发布；校验失败不会得到“文件已安装”状态。共享受管文件校验失败时拒绝覆盖，提示先卸载相关安装并清理文件。

复制导入先计算摘要，已有相同受管文件时直接共享；新文件复制时再次核对摘要。引用导入保持原路径，卸载始终保留原文件，即使它恰好位于另一个受管资源目录。导入接受 GGUF v2/v3 文件头并计算完整摘要；完整模型结构与运行兼容性由启动时的运行库验证。

卸载可选择保留文件作为复用缓存。删除文件时只处理当前安装独占的受管摘要文件，不删除其他安装引用的资源，不跨资源目录。最后一个安装卸载后移除对应配方；共享外部运行库保留在外部工具列表，并释放使用租约，可在那里正常卸载。

## 客户端入口与接口

**设置 → 扩展能力 → 本地模型** 提供“本机模型”和“模型商店”。包括商店搜索与分页、量化体积和标签、部署要求、固定版本安装计划检查、运行库代码批准、导入、资源目录、重试、取消、卸载。名称、说明、标签和参数说明按语言选择；界面语言包采用既有扁平键结构，已提供中文、英文和俄文。

本地 API 为 `GET /api/v1/local-models`（收据快照及当前平台）和 `POST /api/v1/local-models`。POST 的封闭输入合同支持：

| action | 输入与行为 |
| --- | --- |
| `catalog`, `detail` | 查询第一方商店；不接受任意服务地址 |
| `plan` | `version`、`profile`；验证响应与请求版本、平台、方案一致，并保存本机检查计划 |
| `discard_plan` | `plan_id`、`revision`；丢弃尚未被安装使用的检查计划 |
| `install` | `plan_id`、`revision`、`trust_code:true`；只使用本机保存的计划，后台安装 |
| `storage` | 资源 `path`；空值选择默认目录，仅影响新安装 |
| `import` | 目标设备绝对 `path`、可选 `name`、`mode:copy/reference`；后台计算摘要和导入 |
| `retry`, `cancel` | 安装 `id`；显式控制资源任务 |
| `uninstall` | 安装 `id`、`delete_files`；执行共享与归属检查 |

安装和导入请求接受后立即返回收据，前端轮询状态。耗时商店请求使用既有 API 后台任务池，避免网络工作线程阻塞自身 HTTP 调用。页面切换目标设备时中止请求并关闭原设备窗口，旧响应不得写入新目标。

## 受管服务与模型接入（2026-11-18）

安装收据新增独立 `deployments`，旧收据缺少该字段时按空集合兼容。每份部署保存固定运行库、实际上下文、并发、输出预算、思考模式与行为选项；同一安装可以建立多份配置，共享权重。配置修改保留一份可回滚版本，按 revision 防止覆盖。

本地模型稳定身份为 `local-model.<部署XID>`。服务停止后仍在模型列表，临时端口和密钥不写入供应商配置。请求沿用现有 xllm 流式与重试链路；请求前检查实例身份并持有请求租约。首次使用启动、随应用启动、空闲停止默认关闭。停止先拒绝新请求并等在途请求结束，强制停止取消在途调用。

服务由附带的原生 model-supervisor 托管：Windows Job、POSIX 进程组与父进程管道生命线。不凭旧 PID 接管进程。默认回环监听，环境变量传递临时 API Key，日志脱敏，单次磁盘日志最多 4 MiB。启动检查文件大小和完整 SHA-256、固定运行库身份，再检查健康、模型随机别名、有效每槽上下文和并发数。

新增操作：`hardware`、`deployment_options`、`deployment_create/update/delete/rollback`、`start/stop`、`logs`、`verify`、`web_access`。编辑与删除使用 `deployment_revision`；`web_access` 仅在用户明确打开运行时网页时经受保护的 POST 返回本次运行凭据，不出现在 GET 快照。

硬件检测区分可用内存和 GPU 标称容量；目前不声称能精确读取可用显存。GPU 或检测不完整时，需明确启用允许尝试启动。目录要求是预设参考值，改变上下文/并发后须重新评估。多分片 GGUF 使用同盘硬链接视图，不复制权重。

`verify` 通过真实产品调用链检查流式回复及工具声明→结果→继续回复，不执行模型提议的实际工具；验证指纹绑定权重、运行库、模板、能力和有效参数，临时端口变化不使其失效。

本机 Windows CPU 与 AMD RX 5700 Vulkan 已使用官方 llama.cpp b12477、Qwen3-0.6B Q8_0（639,446,688 字节）完成真实安装、流式及工具往返、网页、停止重启和卸载。证据在 `.build/local-model-real/acceptance-*.json`。Linux/macOS/CUDA 只有接口及实现，待实机验收；Strata 尚未接入。大型运行库附件与同逻辑 ID 多版本并存不在当前实现中。

## 配置、更新与资源清理

本机模型下可以创建多份部署、复制配置、编辑、验证、查看日志、在 mdo 中新建对应模型会话。运行时网页只监听目标设备本机，按钮按需取得临时密钥供用户复制，在 llama.cpp 设置中填写。远程控制时“打开网页”在目标设备打开浏览器；尚未实现将完整 llama.cpp 网页转发到控制端。

“检查更新”查询服务器当前发布头，再检查新版本的完整安装计划并批准运行库代码。新版作为独立安装保存；未改变的权重摘要共享，不覆盖旧文件。“切换已安装版本”要求服务已停止，只接受同一模型作品的安装，保持稳定模型 ID；旧配置及旧资源受回滚引用保护。失败可回滚，旧会话无须更换模型。共享运行库采用构建独立逻辑 ID，不进行同 ID 的任意版本覆盖。每次只保留上一份配置，后续编辑会替换这一回滚点。

“本机资源”显示可用 RAM、CPU 指令集和可检测的 GPU 信息。“清理模型缓存”只清理选中受管目录内无安装引用的摘要文件及下载片段；保留已安装、待恢复及回滚引用的资源，跳过未知文件和链接。

更新验证覆盖 403 项 HTTPS/代理、租约、请求排空、幂等停止、首次使用启动、空闲停止、随应用启动、配方新旧共存、稳定身份切换、回滚和重启检查。资源管理另有 78 项检查。中英俄的实际浏览器验收包括 390px 窄屏、参数失败保留、配置、启停、验证、临时凭据及回滚。

真实模型还完成了实际 Agent 工具执行：专用只读 Agent 用明确工具指令读取未知临时文件，再返回文件内容。0.6B 模型只用于部署和工具链体验；这不是复杂编程任务或自主工具选择可靠性的评估。Vulkan 日志确认 29/29 层卸载。测试入口为 `tests/test_local_models_real.py --backend cpu/vulkan`，只使用本机临时 HTTPS 商店，不向生产发布测试作品。
