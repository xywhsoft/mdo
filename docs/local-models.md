# 本地模型客户端

本轮接续已交付的线上商店，仅完成客户端安装与资源管理。模型进程、硬件判断、运行时网页、mdo 推理接入和真实模型效果验收属于下一阶段。

开发仍使用单线程、当前项目原目录、小型合成文件及已有宿主，不复制 app / SDK，不下载大模型，不部署生产服务。

## 已恢复的服务端合同

第十类为 `local-models`，逻辑 ID 前缀为 `local-model:`。固定版本配方为 `mdo.local-model.v1`，部署计划为 `mdo.local-model-plan.v1`。公开商店及后台已经由服务端实现，详见 `D:/GIT/home/docs/local-model-store.md`。

客户端使用相同的配方验证规则。ZIP 中只允许小型 JSON、Markdown、文本、Jinja 资料，不接受权重或程序。部署计划在本机再次校验所选配置、权重文件、总大小、固定运行时版本和摘要、平台及整体 fingerprint；不能只相信一个匹配的 fingerprint。

## 本轮安装结构

配方与运行库沿用既有扩展事务安装。模型权重单独保存为资源目录中的 `blobs/<SHA-256>`，未完成文件位于 `partial/`。资源目录可以选择其他磁盘，临时文件和最终文件位于同一资源目录，以根内改名发布，不在完成后复制一遍权重。

资源目录有独立所有权标记，属于当前 Home；切换默认目录只影响新安装，现有安装继续使用原资源目录。复制导入和下载的文件受管，引用导入的原文件不由 mdo 删除。

安装收据独立于下载历史，记录固定配方、运行时计划和所选文件。安装后持有配方与运行时租约，阻止普通扩展操作覆盖或删除其构建；多个已安装模型可以共用同一构建。现有扩展身份不支持同一逻辑 ID 的多个版本共存，冲突构建会拒绝覆盖，需要发布不同构建身份或先移除依赖，不能声称已实现任意版本并存。

模型文件的下载、暂停、恢复和校验复用下载中心。受控外部来源与独立磁盘的模型下载使用内置流式引擎，保留全局代理、CA、受控 HTTPS 跳转、Range 和 SHA-256；不会为使用 aria2 放宽跳转或目标文件归属约束。既有扩展和应用更新的 aria2 选择规则不变。

## 验证

`python tests/test_local_model_format.py` 在原目录编译实际客户端验证器，15 项合成计划与 ZIP 检查通过。覆盖连同 fingerprint 一起伪造的配置、权重、运行时版本及摘要、大小、平台、输出预算和带凭据来源，以及向配方包嵌入权重或程序的拒绝。

后续运行时及浏览器验收结果在本文件继续记录。大模型吞吐、显存判断和真实推理不在本轮验收范围。
