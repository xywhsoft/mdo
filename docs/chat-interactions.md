# 对话输入、引用与交互

## 上下文输入（2026-10-23）

输入框的 `＋` 统一提供图片、文本文件、工作区引用、会话引用、命令和 Skill。
`@` 可以检索工作区文件或文件夹，选择后显示路径卡片；引用路径供 Agent 读取，
不会在选择时自动读取整个目录。`#` 检索当前设备的其他会话，选择后保存可读对话快照，
后续源会话更新不会改变已经添加的上下文。快照只包含用户与 AI 正文；受读取范围限制时
明确标注不完整，不把工具日志自动带入新任务。

在回复、代码或工具结果中划选文字，可点击“添加到当前任务”。选段保存原文和来源会话、
事件标识。输入区用紧凑卡片展示引用；点击查看全文，点击 `×` 移除。文本以纯文本预览，
不执行其中的 HTML 或脚本。

粘贴至少 2000 字符或 30 行的文本会自动折叠为卡片，替换当前选区。文本文件支持 UTF-8，
单文件不超过 48 KiB；图片继续走已有上传流程。其他二进制文档暂未增加解析器，工作区内
的文件可用 `@` 引用。每条消息最多 16 项上下文，连同 JSON 转义后的正文总量不超过
65535 字节；添加超限时保留现有输入并提示，绝不截断内容。过大的粘贴保留普通文本粘贴。

上下文使用严格的 `mdo-context:v1` 消息尾部封装，随既有草稿、提交日志和队列落盘，
以完整用户消息进入模型。输入框、对话、队列、复制和 Markdown 导出分别显示可读内容，
不把内部封装当作正文展示。Token 估算计算完整封装，包含卡片中的文本。刷新、重启、队列
撤回与历史编辑沿用原有保存和结果确认机制；异步读取和文件选择绑定原设备、原会话。

空输入框按 `↑` 调回最近输入，连续 `↑` / `↓` 浏览；开始修改后恢复普通光标行为。
有草稿、上下文卡片、补全菜单或输入法组合时不抢占方向键。历史按项目保存在
`data/prompt-history/<project>.json`，最多 30 条、正文合计 192 KiB；项目彻底删除时一并清理。
记录使用提交 ID 去重，响应不明时只读取确认，不重新发送消息。

历史用户消息点击编辑后，在原消息位置展开，保留原图片和上下文，可继续选择引用、命令
与 Skill。文本展开类命令先展开为可审阅的输入，需再次发送确认；会话操作类命令仍使用
主输入框。编辑期间锁定主输入框，避免两份草稿互相覆盖。取消恢复原消息，切换页面则将
未发送编辑保留为原会话草稿；编辑失败保留内容供修正。重新发送继续使用带事件身份检查
和保存确认的历史替换事务，不改变原有工具权限。

`tests/test_composer_context_runtime.py` 使用隔离 Home、实际前端和本机模拟模型，覆盖卡片、
文件夹检索、会话引用、划选、文件选择、长粘贴、刷新恢复、会话隔离、编辑取消/重发/导航
以及输入历史。1280px 与 520px 浏览器回归均通过；此轮没有安卓真机回归。

## 侧栏整理（2026-10-23）

侧栏顶部提供工作区／时间线切换和 `＋` 新建分组；“项目”标题旁的更多菜单也能使用，
并提供恢复默认整理。自定义分组可
重命名、删除、拖动排序；项目和会话可从各自菜单移入分组，或拖到目标分组。拖动柄在悬停
或键盘聚焦时出现，触屏常显；聚焦拖动柄后，使用上下方向键也能排序。工作区视图支持
手动排列，时间线视图按今天、昨天、最近七天、更早展示；切换视图不会丢掉原来的整理。

分组仅改变显示位置，项目下的会话仍属于原项目。已置顶会话集中显示，取消置顶后恢复
原分组；归档／回收站筛选沿用会话的真实状态。删除分组或恢复默认整理会保留所有项目、
会话和文件；仍在运行的任务不受影响。大分组按需展开，当前选中的项目／会话保持可见。

布局随便携 Home 保存在 `data/sidebar-layout.json`，独立于安装目录和浏览器存储。内容包括
分组、手动顺序、折叠状态、项目排序及视图，重启后恢复；连接另一台设备时读取该设备的
布局。只读连接可临时展开折叠，但不写入对方的布局。配置未就绪时保留基本侧栏功能。

`GET/HEAD/PUT /api/v1/sidebar-layout` 使用 schema 1、严格字段检查和 revision CAS；读写共享
草稿锁及服务卸载准入。最多 32 个分组、2048 项整理记录、256 个折叠标记，实际序列化布局
不超过 192 KiB，给普通 API 响应信封保留空间。过期写入返回 409，客户端先重新读取，不
重放覆盖；丢失写响应只读回确认。取消、退出和设备切换释放等待，迟到的响应不进入新
设备。损坏文件保持原样，不用默认值覆盖；“恢复默认整理”用于用户主动清除有效布局。

隔离 Home 的原生／打包回归覆盖字段与容量边界、重复 ID、过期写入、重启恢复、损坏文件
保护；1280px／520px 实际页面覆盖创建、移组、拖动、键盘排序、折叠、视图、改名、删除和
重置。测试不调用模型供应商。本轮只处理侧栏，保留原有快捷键，未增加命令中心或文件工作台。

## 确认、提问与未完成回复

输入框上方的交互卡片使用三个明确名称：需要确认、需要回答、上次回复未完成。
原始工具参数放在“查看操作详情”中。前端只展示操作内容，不从命令文本推断安全性。

## 权限确认

默认展示具体命令、文件或资源，以及“拒绝此次操作”和“允许此次操作”。
“本次运行均允许”放在“更多授权选项”内，并说明它覆盖当前运行中的所有后续工具操作，
运行结束后失效，不改变会话默认权限。此按钮沿用后端的 `allow_run`，不是按命令前缀授权。

当前后端仍有等待期限。临近到期时卡片明确说明请求会失效，不会自动放行。
提交中的请求以及已确认但状态同步失败的请求都禁止重复提交。

## Agent 提问

选项和自由回答共用一个卡片。选择选项立即提交，填写自由回答后点击“提交回答”。
继续沿用字节长度校验、中文输入法保护、刷新时保留输入和跨会话隔离。

## 未完成回复

后端明确允许自动继续且只涉及安全的只读调用时，页面可以自动继续一次；等待启动写入
检查和连接就绪期间不耗掉这次尝试。用户主动停止、模型最终失败、结果未知的付费搜索及
其他不符合自动继续条件的中断仍需要点击“继续任务”。默认处理方式由后端元数据决定：

- 工具可用且 `automatic_retry_safe` 明确为 `true`：重新执行只读调用，只展示汇总说明。
- 其他调用：默认 `record_uncertain`，不重复执行，并将结果未知告知 Agent。
- 工具已不可用：不提供重跑按钮。

用户可以为结果未知且仍可用的工具选择“再次执行”。界面明确提示可能重复产生效果。
选择始终绑定会话及恢复令牌；令牌包含账本序列，新状态不会继承重跑授权。已接受的请求
不会被缓存、刷新失败或切换会话重新解锁。只有后端重新成功检查空闲会话，确认上次运行
仍未完成，才允许再次提交；同一状态连续请求模型失败后，也可以再次点击“继续任务”。

未完成回复不阻挡正常输入：用户可以点击“继续任务”，或者直接发送新的消息。
直接发送会在会话的独占运行窗口中结束上一轮，将缺少结果的工具调用记录为
`uncertain / not_retried`，然后追加新消息；不会删除旧内容、撤销文件修改或执行旧工具。
“结束本次回复”采用同样的收尾方式，也适用于仍有未决工具调用的情况。
未完成状态通过卡片提示；只有实际发送被阻止时才显示输入区提示，避免重复警告。

后端实际记录同一输入的继续运行后，旧错误和恢复记录收进已有的“思考与执行过程”，
保留原文和时间；本次执行仍显示真实的运行、停止或失败状态。若继续也失败，对话只展示
本次最终错误；成功后不再突出旧错误。新问题或子智能体完成不能收起其他输入的错误，
原输入已被历史清除、缺少来源或旧格式不明确时也不推定其归属。搜索与导出仍保留诊断。

历史正文与摘要索引共用已知的起点：正文加载到最早记录后，不再显示重复的“更早摘要”
入口。两类读取乱序返回时，已知范围只能向更早推进；跳转已加载的回合不会被旧分页
拉回较新的起点。历史替换会取消旧正文、摘要和跳转读取，立即释放等待；迟到结果只属于
原历史，不能进入新页面。正常取消读取不弹错误，真正的最终读取失败仍可准确提示和重试。

恢复普通聊天不再触发“文件修改后必须运行验证命令”的规则。xwork 从本轮账本和工具效果
判断是否发生过写入；真实写入仍保留验证要求。xllm-session 的会话尾部排除系统消息，更新
AI 回复语言或记忆上下文不会让未完成会话被误判为已完成；稳定的待工具结果状态也允许更新
系统上下文，但模型调用和压缩进行中仍拒绝修改。
