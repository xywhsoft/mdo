# 目录商店部署

当前实施记录：[2026-10-27 整目录改造](build-records/2026-10-27-extension-directory-rebuild.md)。该记录逐阶段区分已验证、暂存、上线与尚未执行的检查。

公开服务与权限、作品/上传/审核流程见 [目录商店](ecosystem-store.md)。本次不迁移旧格式运行时兼容分支。原官方对象使用一次性离线转换工具生成普通 ZIP，逐文件核对原摘要；发布程序默认预览，显式 apply 前备份。旧生态只私有备份，不继续作为公开运行依赖。

平台 SQL 来源为权威 C 存储代码；新库初始化拒绝覆盖既存数据库。源代码替换必须核对现场哈希，存在生产漂移时只添加必要接口，不覆盖网关/身份/计费并行修改。上线前准备回滚清单，重启后验证公开目录、ZIP 下载及匿名权限边界；失败立即恢复自有文件。

客户端八类产物必须记录共同源码指纹、锁定 SDK/宿主指纹、签名及实际字节摘要，公开下载与自动更新应指向同一对象。Android 真机结果与自动编译分开记录。


## 身份与依赖部署

此次实现同时修改 mdo 客户端与 home 仓库的 `host/xywhsoft_ai/plugin/mdo/modules/ecosystem`、`page/extensions`，完整能力需要两端配套。平台服务已于 2026-10-29 更新，见[部署记录](build-records/2026-10-29-platform-dependencies-deployment.md)。本轮按用户要求只更新线上服务，客户端正式发布仍为 0.7.0。

以下是完整发布顺序；本轮只执行平台阶段，未执行客户端发布。

1. 备份平台扩展数据库及这次替换的 C/页面文件，记录现场摘要。平台先部署身份登记、按版本关系索引、resolve/plan 路由及依赖详情跳转。共享校验头需与客户端保持相同字节。
2. 新表由平台初始化迁移建立，已有作品不伪造身份或改写旧 ZIP。作者为旧作品提交含 ID 的同作品新版本，审核成功后才能参与依赖解析。
3. 带依赖/冲突的归档要求 `dependency_protocol=1`，旧客户端会收到明确拒绝；普通无依赖归档保持既有权限和下载行为。客户端安装收到不完整计划时停止，不降级为只装根扩展。
4. 发布已验证的客户端产物。用户启动升级后可显式迁移未修改的内置扩展；本机作者按[离线迁移步骤](extension-dependencies.md#旧数据迁移)预览、应用并保留备份。不要对活动用户 Home 批量补写 ID。
5. 在线验收公开依赖链、作品归属冲突、私有目标不可见、点击跳转、版本固定下载、整组事务及中断重试。设备专项和平台上线结果分别记录，编译通过不能替代真机/生产验收。

回滚平台应恢复其匹配源码、页面与部署前数据库备份；保留部署后新对象供核查，不自动删除用户内容。客户端回滚前保留 Home 和事务日志；已经迁移的身份与选择不应由旧客户端覆写。
