# 搜索结果文件与中断恢复

搜索采用“小型索引 + 完整结果文件 + 按需读取”的流程，没有增加模型工具。
`web_search` 和 `web_open` 的 JSON 索引最多 4096 字节；xwork 的统一状态前缀
另占少量字节。完整内容保存到当前会话的 `artifacts` 目录，索引返回只读的
`@results/...` 路径、文件字节数、行数和 SHA-256。搜索条目含标题、简短摘要、
行范围，以及能放入预算的完整 URL。长标题、URL、摘要仍保留在结果文件中。

模型使用现有 `read` 读取相关条目，例如：

```json
{"path":"@results/run-00000000000000000001/00000000000000000001-web_search.md","start_line":10,"max_lines":20,"max_bytes":4096}
```

文本读取默认限制为 4096 字节，包括显示元数据；`max_bytes` 支持 256～8192。
长单行也会分页。返回的 `offset` 使用原文件字节位置，下一次读取时用它替代
`start_line`，不会在中文、俄文或 emoji 字符中间切开。图片沿用独立大小限制。
结果路径由宿主绑定当前会话的存储目录，不能作为写入路径或跨会话挂载。
临时模式不写文件，只返回明确标注缺失文件的有限摘要。

网络权限、凭据权限和恢复策略各自保留。宿主明确声明 `web_search`、`web_open`
为可恢复的读取操作，因此它们不再显示逐项“重复执行 / 记录不确定结果”的
选择卡。确实会修改文件、执行进程的未知操作仍保留人工决策。

完成结果在工具完成事件和模型历史写入之前保存到 `artifacts/completed`。
收据按会话存储、持久轮次、工具来源、名称、调用 ID 和参数原始字节匹配，
恢复时校验文件大小与摘要，已完成的调用直接复用结果。损坏的记录明确报错，
不会静默再次请求。子任务暂不保存收据，避免不稳定任务身份造成错误复用。

前端对宿主明确允许的中断读取进行一次自动恢复；同一页面中的同一会话轮次
不会因轮询或恢复令牌变化而循环重试。失败时保留一次手动继续入口。主动停止
不会自动恢复。搜索请求已被服务接收、但本地收据尚未保存的断电窗口仍无法
保证只计费一次；当前服务未提供幂等协议，这种不确定的付费请求保留一次
“继续”操作，不自动重发。已记录完成事件持久化失败的调用可以复用其收据。

文件分页降低单次上下文占用；已读取的页面仍会进入模型上下文，现有上下文
压缩机制继续工作。页数应按实际需要控制，避免一次读取所有搜索结果。

验证范围：

- xwork 普通原生测试、UTF-8 截断边界、完整分页还原、运行时与存储重建、
  批处理路径、事件写入失败、损坏收据与写权限拒绝。
- 本地 HTTP 的账号认证、错误响应、空结果、URL 策略、无重定向与次数检查。
- `test_web_result_files_runtime.py`：真实 xs/xwork 执行器、临时模式和结果文件。
  `--recorded <会话目录>` 可只读回放原有结果；不会提交用户数据或联网收费。
- `test_web_result_session_runtime.py`：搜索 → 分段读取 → 模型继续 → 会话日志及
  UI 完成事件的完整流程；所有模型响应和搜索服务均来自本地固定数据。
- 前端自动恢复边界、已有恢复确认协议、打包版停止和恢复确认测试。

核心 xrt 文件系统 ABI 未改变；xwork 保持 ABI 7、事件版本 3，新增两个公开
宿主 API，依赖锁和 xs Git bundle 包含完整源码，换机器可按仓库工具链重建。
