# 对话历史与摘要导航

历史和模型上下文分别管理。`snapshot.json` / `journal.jsonl` 仍由 xllm-session
维护模型上下文，`ui-events.jsonl` 保留聊天展示所需的用户输入、回复、思考、工具
调用和结果。上下文压缩不删除显示历史。

## 交互

- 打开已有任务时先加载最近四轮，按每页 32 条事件读取其完整范围，不从头播放
  整个会话。上滑接近顶部或点击顶部按钮，每次向前加载四轮。
- 读取旧页不会推进 WebSocket 游标；新消息同时到达时按事件 ID 合并，保持滚动
  锚点。历史读取失败保留已有内容并允许重试。切换任务会取消旧请求。
- 运行中展示执行过程，顶层运行结束后自动折叠思考、中间回复、工具和子 Agent
  内容。最终主 Agent 回复、时间与操作按钮保持可见；过程及内部条目可再次展开。
- 左侧横线按用户回合排列，悬停或键盘聚焦显示问题、最终回复的文本摘要；点击
  跳到该轮。触摸点击直接跳转。摘要默认读取最近 64 轮，“⋯”继续读取更早摘要。
- 跳转只读取目标回合，不下载中间全部文本。若当前加载的两个区间之间还有历史，
  明确展示“加载这之间的对话”，可逐步补齐，不把未加载区域假装成连续记录。
- 手机宽度使用较窄导航栏，预览限制在屏幕内；历史内容和过程折叠保留相同逻辑。

## 存储与维护

取消旧版前端的 640 条自动丢弃以及 UI 文件 16 MiB 自动裁剪。对话轮数和文件
没有应用层自动删除上限，仍受可用磁盘空间限制；磁盘写入失败按原合同报错。
单条事件的 64 KiB 文本、96 KiB JSON 和单次 API 的分页上限保留。已加载的轮次
在当前页面保留，离开任务后释放；尚未访问的正文不加载。

历史摘要反向分段扫描 JSONL 并按需二分定位字节位置，不写第二个会话库或索引文件，
不创建额外常驻线程。UI 和 JSONL 使用相同的稳定 event ID。摘要是文本前缀，
不额外调用模型生成，因而没有额外 token 成本。

只有明确清空、编辑或重试才会移除相应范围。原有事务、revision 校验和持久化
范围标记继续生效，迟到的历史请求不会恢复已删除消息或摘要。分叉、编辑等明确
维护操作仍使用原有原子出版流程，可能需要与记录大小相关的临时内存；常规分页、
重连和启动定位只使用有界读取。旧版本已从磁盘裁掉的历史无法重建。

## 代码组织与验证

- `sessions/event_reader.inc.c`：有界 JSONL 前向、反向、二分定位；
- `sessions/conversation_turns.inc.c`：顶层回合摘要和反向分页；
- `chat/conversation-history.js`：纯投影与摘要合并；
- `chat/timeline-store.js`：最近页、旧页、跳转和实时游标；
- `chat/timeline.js`：过程折叠、节点复用及滚动锚点；
- `chat/conversation-navigation.js`：摘要横线、预览和键盘导航。

针对性验证包括：旧页与新消息交错、清空和切换任务时的迟到响应、单轮跳转、
摘要单独分页、模型调用完成与 Agent 回合完成的区别，以及含 70 轮的单个离线
JSONL 文件超过旧阈值后继续读取、追加和重启。浏览器夹具验证自动折叠、展开、
未加载回合跳转及 1280 / 390 像素宽度。未运行压力或高负载测试。
