# 原生成员执行

`instance.step/resume/abandon` 共用一个成员执行租约，负责领取持久消息、固定代码目录与上下文、打开原生 Agent、最终检查点及收据结算。交互式成员路由将复用同一租约，不复制执行引擎。

领取在状态锁内持久化，执行 C、模型和工具时不持有该锁。持久记录与进程内槽共同表示正在执行；进程退出后仅展示需要确认，不自动重放。结果仍保留原生成员历史与短收据的明确边界。

成员取消令牌独立于调用者令牌。上层取消会向执行中的成员传递；取消一个成员不会取消等待收据的 SDK 调用者，调用者仍可完成结算。代码目录、父取消令牌及所有回调上下文由租约持有。

交互式路由只有一个实际 Run，因此成员和主 Run 共用取消令牌。取消/超时后若快照明确没有未决工具，结束被停止的纯模型轮次；有未决工具或无法取得快照时保持恢复状态，不自动重放工具。

空邮箱的 step 继续返回 no_work；其他会话不能执行本会话成员。验收在 Mohists 唯一开发实例完成：多轮执行、取消修订、可见历史、队列、实际宿主重启及未决进程恢复。

## 主会话成员路由

原生 `run.route` 转换 hook 在主会话取得运行预留后、创建 Run 前执行。上下文固定当前项目、会话、Run ID 和真实调用来源；输入包含 run_id、agent_id、prompt、resume。插件若选择成员，返回完整输入副本并加入 `route: {namespace,id,message_id}`。成员必须属于该会话，且当前空闲、没有先前待处理输入。插件负责自己的编排预算和准入；宿主负责原生领取、权限、取消、账本与流式事件。

宿主以原成员的 Agent、模型和原生 ledger 创建实际 Run。协调者的配置、全局默认 Agent 均不改变。主聊天与成员可见历史接收同一批实际事件；主事件 schema 8 的可选 source 包含 namespace/member/agent，旧 schema 1..7 继续读取。模型/工具统计、上下文用量和回复来自实际成员，不用短结果收据转贴主回复。

长主输入以成员私有目录内的校验文件保留，图片保存会话原附件 ID，实际模型消息沿用同一构造函数。领取消息和成员运行状态原子发布；不会为了路由发送第二次模型请求。显式恢复使用原生 token 与决策，并重新进入交互式 Run 管理器，恢复事件仍写入主聊天。已经完成的输入只收取结果，缺少对应完成证据时不拿成员旧回复冒充本轮结果。

`run.finished` hook 在原生成员结算后执行，输入保留 route，并附 started、settled、state、error、member。收到 external_settlement=true 表示已有上层显式恢复调用负责插件任务结算，应避免再次预留预算。完成回调清理取消与期限，以便在 Stop 后保存任务结果；调用来源保持原样。回调不得自行再次运行模型或工具。

idle 只在成员的原生会话、历史写入锁和回调 owner 释放后可见；完成观察者还在执行时，其他调用仍看到 running。资源释放后发出 instance.changed 并调用 instance.released hook，参数为 id/namespace/state/revision。后者可继续调度先前明确请求运行的队列，不能据此创建未请求的新工作。该回调也保留原始来源，同时移除已结束的取消/期限。

确定性验收：原生实例预热 → 长主输入/完整回复 → 图片与真实 read 工具 → 成员取消 → 实际宿主退出 → token 确认恢复并继续主聊天 → 返回协调者。另验证完成观察者持有写入者时不能重入成员，共九次本地模型请求。

## 多账本历史的边界

`session.execution` 是只读的当前执行投影，返回实际主讲的 agent_id/model_id/reasoning_effort、可选 target（namespace/id/state/revision）和该成员已提交的 context checkpoint。`session.execution` 转换 hook 可以提供 target；宿主核对所属会话，并从原生成员解析实际绑定，插件不能伪报模型。单会话详情响应包含相同的 execution 字段，配置记录本身不改变。读取不打开模型账本、不发请求、不改变成员 revision；目标错误时详情仍可读取，但 execution.available=false，不静默假定协调者接管。

成员结算保存实际事件中的上下文统计和服务端 usage。检查点绑定 active_message，宿主退出后新消息没有完成检查点时，不把更早轮次的用量当作已包含该输入。成员和协调者的输入占用必须分别选择，不能按整个可见聊天的最后一个模型调用估算。

主聊天逐条保留并显示实际成员来源，恢复时按来源寻找原始用户输入，不能把其他成员或协调者的最近输入当作本轮输入。普通会话的编辑、重试和分叉继续可用。

含成员主讲记录的主会话由多个独立上下文组成。当前单账本编辑、截断、清空和分叉接口不能原子处理这些上下文，因此在改写前明确返回 `session_member_history`，界面不显示对应的单账本操作。用户仍可追加主输入、切换主讲、读取完整历史，或在成员窗口明确恢复。这是当前产品限制，不能称为已实现跨上下文历史改写。

原生成员在发布状态前为所属会话持久声明外部上下文；仅保存编排状态的扩展也应调用 `session.mark_external_state`。完整备份与用于设备传输的 stored capture 在收集文件之前检查声明，返回 `session_external_state` 或对应原生原因。插件停用不移除声明。普通无外部状态会话继续按既有格式备份；多上下文完整便携备份/迁移目前尚未实现，需保留完整 Home。内部回滚保留声明文件，便携解码拒绝包含该文件的包，避免伪装成完整可恢复上下文。
