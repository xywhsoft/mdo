# 原生下载中心

应用更新和商店扩展归档使用原生持久化下载任务。下载窗口提供暂停、继续、重试、取消并删除、进度、速度、预计剩余时间及校验状态。关闭窗口不停止任务；切换目标设备会关闭当前窗口，旧按钮不能操作新设备。

## 自动下载引擎

新任务及用户显式继续的任务，会检测已安装、启用、通过校验和代码授权的 `external-tool:mdo.aria2`，通过它的 `aria2c` 命令导出启动下载。没有可用安装时使用内置引擎；不会从 PATH 随意找程序，也不会自动安装工具或连接用户已有的 aria2 服务。

每条活跃任务按需拥有一个隐藏的 aria2 子进程，通过随机回环端口和随机秘密调用 JSON-RPC。账号授权头仅经内存中的 RPC 传入，不保存会话文件、授权参数或用户 aria2 配置。进程生命周期内固定所用工具目录；结束时暂停、关闭并等待，必要时结束进程树，最后释放目录租约。异常退出通过 `--stop-with-process` 跟随宿主停止。

aria2 最多使用四条连接，具体分段能力由源服务器决定。平台整包接口若使用未知长度的 chunked 响应，可能使用单连接下载；mdo 不向 aria2 强制注入与 HTTP 响应冲突的长度。无论采用哪个引擎，文件就绪前由 mdo 重新核对目录大小和完整 SHA-256，扩展继续执行原有封存检查。

aria2 启动、RPC、进程或可回退的传输错误，会在同一任务中切换一次内置引擎，界面显示当前引擎与回退提示。认证、磁盘、文件完整性等失败直接报告；用户取消不会触发回退。aria2 与内置引擎各自保管临时文件；回退前先停止子进程并清理该任务的 aria2 文件，不把分块文件的物理长度当成连续已下载字节。无法清理时保留失败任务，避免同时写入。

aria2 恢复文件位于 `data/downloads/aria2/<task-id>/`，包括 `payload`、`payload.aria2` 和不含凭据的身份记录。暂停与宿主退出保留文件；成功、取消或清理任务时回收。强制退出后的下载仍需用户点击继续，不会自动重放安装。

## 状态与存储

原生任务是事实来源，记录在 Home 的 `data/downloads/tasks.json`，不保存账号令牌或任意命令。任务身份绑定来源、精确版本/地址、SHA-256 和大小，最多保留 128 条。浏览器存储仅保存展示历史；刷新后以原生快照确认状态，不自动重放安装。

应用包下载使用原位置 `data/update/new.exe`、`new.bin` 或 `new.apk`，旁边的 `.resume.json` 保存文件身份与强 ETag。断线和退出保留部分文件；继续前重读已有字节参与完整 SHA-256 校验。206 必须匹配请求位置、范围、总大小和验证器；200 表示重新下载整文件，先清空旧前缀。416/错误范围只允许有界重试，校验失败的文件删除且不能安装。传输失败最多自动尝试三次，用户可显式重试。

扩展归档保留既有 `data/extension-tasks/<id>/archive.part`、`archive.zip` 和任务元数据，继续使用平台的 offset 分块接口。继续时重新取得账号租约并从实际已接收位置请求；封存仍执行大小、SHA-256、ZIP 与清单检查。安装前不切换目录。原安装操作中断后，下载中心可恢复同一个归档，下载就绪后仍需显式安装或重新提交已检查的依赖计划。

退出后未完成任务显示“已暂停”，由用户继续，不会启动下载或安装。明确“取消并删除”会请求停止当前传输，再清理属于该任务的临时文件。“清除已完成”保留暂停、进行中和待安装的文件；不会把本机读取失败当作已完成。更新包的安装仍使用原有检查与原生确认流程。

同一个目标文件只允许一个活跃写入者。清理旧失败任务时，必须核对旁边的恢复凭据仍属于该任务的地址和 SHA-256，防止误删后来下载到同一路径的新版本。成功或明确取消后再清理恢复凭据，取消与最终校验同时发生时也不会返回可安装的成功结果。

损坏的任务登记文件保留原件并使下载管理器只读，报告不可用，不阻止其他 mdo 功能启动。目的路径限制到受管下载位置或更新包位置；扩展仅引用既有归档任务身份。当前不开放任意 URL/目标文件写入接口。

窗口读取任务失败时，显示醒目提示，保留已有记录并暂时禁用操作；自动刷新成功后恢复。已知错误按错误代码显示中、英、俄说明，原始诊断可展开查看。列表支持桌面滚动和窄屏全屏窗口；关闭窗口不取消传输，进行中的任务继续刷新状态。

## API

- `GET /api/v1/download-tasks`：当前设备的原生下载任务快照；不返回内部路径上下文或账号凭据。
- `POST /api/v1/download-tasks/<id>/<action>`：`pause`、`resume`、`retry`、`cancel`、`forget`。沿用本机来源、写令牌和远程连接权限检查。状态变化或任务仍被占用时返回冲突。

暂停会保留当前生产者及安装计划的所有权；恢复继续原流程。重启后的恢复只重新获取固定的下载资源，不延续无法证明完成的安装步骤，也不替换成新发布版本。

## 验证

`tests/test_native_downloads_runtime.py --host .build/host/xs.exe` 直接编译项目源码，使用回环模拟服务器与小型合成文件，覆盖暂停/恢复、连接中断后的 Range、忽略 Range 的安全重下、进程强制退出后恢复、校验失败、清理旧任务的文件归属、取消清理、扩展归档重启恢复与封存、应用更新策略恢复，以及损坏/超量登记文件的只读处理。没有模型调用或用户 Home 操作。

`--aria2` 使用已有官方 Windows aria2 程序作为获批工具安装到测试 Home，验证真实进程、RPC、暂停时实际进度停止、重启续传、进程崩溃回退、认证/校验失败不回退、取消文件清理、chunked 整包扩展封存、更新包下载、停用工具选择内置引擎和子进程退出。`--serve-ui` 可保持测试窗口供验收，结束时清理测试 Home。

Node 定向回归覆盖窗口控制、暂停文件保留、按设备隔离、归档及更新状态去重、引擎与回退提示，以及三个语言包。内置引擎使用单连接；模型权重大资源、任意外部下载源由后续功能接入，不提高既有应用包/扩展归档大小上限。

平台 `GET /api/v1/mdo/extensions/archive?dependency_protocol=1&version=...` 支持整包下载，新增标准单段 Range／If-Range、206／416 和 Accept-Ranges；旧 offset 分块语义不变。平台源码位于 `D:\GIT\home`。`tests/test_aria2_platform.py` 编译实际发送函数，覆盖整包、范围、后缀、验证器、越界/溢出和旧 offset 响应；上线需要部署对应平台源码，本地提交不代表已部署。

## 2026-11-03 状态与恢复修复

- 原生更新记录按更新服务快照投影为已完成/已失效；瞬时检查失败保留已下载包。
- 扩展完整快照删除已不存在的归档行，单条读取不影响其他任务，清除原生任务不会复活旧行。
- 取消后的清理失败持久化为 `cleanup_pending`，下载中心显示原因并支持单独重试清理；不删除其他任务拥有的文件。
- 损坏/重复记录隔离，先将完整原始索引原子移动到 `tasks.rejected-<utc-us>.json` 再发布健康记录。隔离失败保持只读，避免覆盖证据。超过 128 条健康任务仍拒绝覆盖；暂停、失败、待安装任务不自动丢弃。
- 已取消且清理成功的记录保留 30 天；容量满时优先淘汰最旧的此类记录。隔离文件留给用户诊断，程序不自动删除。
- 验证：下载中心 Node 交互/状态测试 16 项；原生运行时测试通过断点、重启、旧任务文件归属、清理失败与重试、坏记录隔离及修复后新下载。

## 全局网络与大文件来源

下载继承设置 → 网络的全局代理、绕过地址和自定义 CA；模型供应商的单独代理不会影响下载。内置 HTTP SDK 流式落盘，支持 HTTP CONNECT、SOCKS5、系统代理及 PEM；代理解析或证书校验失败不会绕过配置直连。扩展元数据、分块下载及提交共用这一网络策略，授权头不持久化。

aria2 通过内存 RPC 继承 HTTP 代理与凭据。SOCKS5 或自定义 CA 选中内置下载器，并记录 `aria2_network_policy`。官方 WinTLS/AppleTLS 不支持 `--ca-certificate`（[aria2 手册](https://aria2.github.io/manual/en/html/aria2c.html#cmdoption-ca-certificate)），不向系统证书库安装证书、不关闭 TLS 校验；其他平台在单独验证之前也使用相同回退策略。

受信任原生生产者可调用 `MdoTransferDownloadSource`：必须提供公开 HTTPS URL、大小、SHA-256 和 `data/downloads/assets/` 内的目标。身份、跳转域名白名单与收据持久化，可由原生调度器继续；未开放任意 URL 的网页下载接口。仅允许 HTTPS、源域名及最多八个精确声明域名，最多五次跳转，禁止降级和无界跳转；远程账号授权不转发给外部来源。

传输大小上限提升至 1 TiB，64 位计数、偏移及流式 SHA-256；扩展 ZIP 安装的原有限额不变。Windows/Linux 使用现有磁盘空间检查，内置引擎检查剩余字节及 32 MiB 余量，aria2 保守检查完整大小。存储落在选定 Home 的磁盘，可通过 `--home` 选择其他磁盘；本地模型的专用目录选择界面随本地模型扩展实现。macOS 磁盘空间检查和运行验收仍须在目标系统补齐，不能视为已经验证。

测试使用约 200 KiB 的回环文件，验证 HTTPS 信任/拒绝、认证代理、绕过、受控跳转/循环/降级拒绝，以及声明大小超过旧 512 MiB 上限后的校验路径；不生成或下载多 GB 测试文件。真实大模型下载、HF 镜像稳定性及目标平台性能不属于这次小文件验收结论。

## 完成记录与写入失败

更新任务保存目标 build_id，使用本机 build 收据确认已安装；扩展归档安装收据确认后，原生记录也转为 complete。已完成记录、已取消且清理完毕的记录，以及已校验完成的普通文件下载历史，保留 30 天；容量满时淘汰其中最旧的一项。文件本身保留。暂停、失败和待安装扩展/更新记录不因容量策略自动丢弃。

注册任务、暂停/继续及清除历史遇到索引写入失败时回滚对应内存修改；未持久化的继续不会偷偷启动。取消的实际停止和删除行为不撤销，清理仍可重试。完成状态保存失败不会向生产者报告成功。验证增加了索引变成不可写目录的故障注入、128 条正常历史的容量清理、30 天保留及安装收据对齐。
