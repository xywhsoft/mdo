# 对话稳定性持续改进

目标：对话、工具执行和恢复保持顺畅。可恢复问题由程序处理，不把每次重试显示为运行错误；无法继续时只给出准确、可操作的最终提示。每个完成阶段提交 Git。只做有界功能验证，不做压力或高负载测试。

## 实施顺序

1. **模型调用和错误策略**：统一在线、用户配置模型及设置中的测试入口；临时限流、服务暂不可用、尚未产生模型内容的网络故障采用指数退避；遵守 Retry-After；退避可立即取消并服从截止时间。区分每日额度、余额、会员权限、认证、模型配置、上下文和临时故障。避免库与产品层叠加重试、重复执行已经完成的工具。
2. **对话反馈与恢复**：持久化必要的结构化错误分类，用界面语言说明最终失败；减少重复错误卡和临时通知；验证中断、继续、编辑重试、模型切换、排队、重启恢复和流式中断。保留用户输入及已经完成的工作。
3. **真实开发验收**：驱动 mdo 在独立项目中使用 `D:\GIT\xge` 开发简单像素图片编辑器，至少具有画布、画笔/橡皮、颜色选择、缩放与图片保存。实际编译并进行有界功能检查，修复模型、文件工具、命令、权限或界面在过程中暴露的问题。保留开发记录及产物，不借用用户原项目进行破坏性测试。
4. **其他功能回归**：逐项验证账号/续期与额度、项目和会话、设置、附件、工具、子 Agent、Skill、MCP、命令、生态安装、计划任务及移动端关键交互。发现问题先修复，再扩大验证范围。设备不可用时继续本地验证，明确哪些移动端行为仍待真机检查。

## 验证约束

- 首先使用本地可控模型与服务模拟故障，不消耗线上付费服务进行重复故障测试。
- 重试不隐瞒不可恢复状态，也不无限等待。模型内容已经交付后的恢复单独验证，不能简单重放并拼接重复回复。
- 取消、登录切换及关闭应终止等待；不会在后台继续悄悄产生请求。
- 每次记录具体触发条件、用户可见结果、测试范围和提交；不把成功构建当成功能验收。
- 现有工作区未提交修改单独保留，不混入本任务提交。
