# 长任务恢复

目标是让暂时故障留在原任务内恢复。重试仅覆盖明确安全的失败步骤，不重新执行已完成的工具，也不扩大权限或更换账号。

## 配置与等待

设置 → Agent 行为 → 自动恢复重试次数，对应 `settings.agent.recovery_retries`，范围 0–100，默认 10。初次尝试不计入重试次数；0 表示首次失败后直接进入等待。连续失败计数在对应步骤成功后清零。

- 网络、连接、限流、账号续期：先退避重试；用尽后保留运行，通常每五分钟重新检查，不生成最终失败和“继续任务”按钮。供应商更长的 Retry-After 仍受尊重。
- 账号、余额、额度、会员和模型配置：无意义的请求不会重复十次。等待实际条件变化后再尝试；账号侧的普通轮询时间变化不能触发模型重试。
- 内存等资源压力：从十秒起退避，最长十分钟；减少后续工具并发。等待期间仍可停止。
- 明确的调用截止、用户预算/轮数上限、主动停止和账号切换优先。原十五分钟恢复总窗口已经移除，单次网络请求的超时仍保留。
- 有限的模型验证/探针、独立手动压缩不使用无限等待，避免把交互式操作变成长任务。自动压缩继续沿用正在运行的 Agent 任务的恢复策略。

恢复通知沿用对话中的合并状态提示。等待条件改变时不会显示误导性的“倒计时结束立即请求”。恢复后有新输出、工具结果或压缩完成事件时清理提示。

## 账号隔离

续期失败达到阈值后不删除刷新凭据，只进入低频恢复。服务器明确撤销凭据后等待登录；同一账号重新登录可以恢复原任务。用户明确退出或切换到其他账号会取消旧任务绑定，不能用新身份执行旧请求。

配置修复后的失败步骤重新读取目录并创建客户端。之后的新请求也会绕过旧目录对应的缓存客户端。恢复不会重放已经提交的模型回复或工具调用。

## MCP

自动连接、发现和重新连接按服务分别调度。一个服务暂时失败不阻塞其他服务准备，也不让普通 Agent 请求失败。未发现的远程工具不会提前注入完整 Schema；保留已批准连接的身份范围，恢复后同一任务可以继续使用，不能静默换用其他账号的连接。

需要授权、配置修复或持续失败的服务进入公共警告入口。服务恢复后警告自动消失；不自动修改用户的启停设置。实际工具失败仍可作为工具结果交给模型选择其他办法。

## 压缩、结果与存储

复用原有完整工具配对和安全前缀/长轮次分段规则。摘要结构不合格时先按配置纠正；最后一个候选仅缺少标题、且内容长度合规时，可以保留全文补齐结构，并再次通过同一个质量门槛。过短、过长及自定义质量检查仍不接受的摘要不会强行提交。质量重试用尽后等待条件改变，不无限启动收费摘要批次。

压缩提交失败保留已生成的摘要，只重试提交。会话检查点、初始消息、请求构造和有序工具结果分别保留自己的待完成步骤。回复文本已追加但用量写入失败时，只补写用量，不再次追加回复。

显示事件短写、刷新或关闭失败时，保留原尾部位置；下一次先修复未提交尾部，再追加相同事件。只有成功提交才发布事件和消耗事件 ID。普通流式字符仍不逐条落盘。

已执行工具后的结果整理失败不会重新调用工具。可恢复资源释放后，提供保守失败结果和已有收据/文件供模型核对，不能声称副作用从未发生。原生批次线程创建失败仍沿用顺序执行兜底。

## C Agent 与插件

可选生命周期观察器错误继续隔离为警告。控制回调可返回两个新增值：

- `MDO_RESULT_RETRY_SAFE`：明确承诺失败尝试没有修改输入、State、ContextPlan、请求/回复，也没有产生外部副作用。宿主仅重试当前回调，不重新运行前面已成功的回调。
- `MDO_RESULT_RESOURCE`：同一承诺，但采用更长的资源退避。

普通 `MDO_RESULT_ERROR` 仍表示无法证明可安全重放的控制失败；不能靠改返回值隐藏已经发生的文件、进程、网络或 SDK 副作用。主动拒绝和取消也不会被当作暂时故障反复调用。配置角色继续使用现有生命周期，不要求编写恢复框架。

这些通用边界在 XRT 主线实现，通过锁定的整套 xllm/xllm-session/xwork 导出接入 mdo 原生宿主。xwork ABI 为 10，宿主和调用方必须一起重新构建，不能给旧宿主只替换应用脚本。

## 人工交互与不可恢复边界

权限确认默认等待用户，只有明确调用截止、取消或退出才结束等待。ask 原有四小时等待已修复为 64 位常量，超时后的原有回答回传策略保留。

不能自动重试的边界包括：未知副作用收据、无法确定提交结果的日志、真正的损坏数据、无安全契约的必需 C 回调、用户主动停止/退出/换账号、明确预算和截止、进程被系统终止或 C 扩展破坏内存。不能为继续任务而伪造成功、静默丢弃必要上下文或重复执行这些操作。
