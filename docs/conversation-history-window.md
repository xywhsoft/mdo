# 会话历史按完整分组加载

历史阅读和实时流使用同一个正文/执行过程渲染器。公开回复始终显示，思考、
工具和子 Agent 记录放在其原有顺序的折叠块中。

历史接口 `/conversation` 的 `limit` 表示公开回复分组数（1–4）。一个分组包括
回复正文、模型完成元数据，以及前一公开回复之后的执行记录；只有工具调用的
模型轮次不会成为分页边界。用户输入和恢复标记保留在各自的运行边界。
正文流完整聚合，字节和事件预算只决定何时寻找下一分组边界，不截取正文。
工具输出和思考仍为预览，展开/复制使用原有完整事件读取接口。

前端先读取最近一个分组，再根据实际渲染高度补足约 **2.5 个视口**。向上阅读时，
距离已加载内容顶部不足 **1 个视口** 即预加载更早记录，每批新增内容目标为
2.5 个视口。单个长回复可以超出目标高度，仍保持完整。视口增大时自动补齐。
补载保存可见记录的位置、展开状态及实时游标；WebView 取整误差跨批次补偿。
切换会话、搜索、隐藏页面和销毁视图会停止继续补载。失败保留正文，允许点击重试。

保留有界防护：历史单页最多 4 MiB / 4096 个投影事件，单条聚合正文最多 1 MiB，
扫描最多 16 MiB。超出返回明确的 413 错误，不把半个分组作为成功页面返回。
实时增量可以分批发送尚在生成的内容，不改变历史分组规则。恢复控制仍使用其
独立的用户回合读取语义，两者共用日志读取实现，不增加侧文件或改写用户日志。

验证入口：

- `node --test tests/test_history_window.mjs tests/test_conversation_snapshot.mjs`
- `python tests/test_conversation_groups_runtime.py --packed <mdo.exe>`
- 可加 `--replay-journal <ui-events.jsonl>`，只读原文件并在临时 Home 中回放副本。
- `tests/fixtures/timeline-history-window-browser.html` 验证真实布局、缓冲高度和补载锚点。

既有大历史测试的完整正文期望已更新；日常验证使用上述小型离线用例，不运行
压力和高负载测试。
