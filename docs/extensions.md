# 扩展能力：Agent、SubAgent、工具、Skill、MCP 与命令

管理入口：设置 → 扩展能力。资源分别有列表、新建、编辑、导入和导出；自定义资源可启停、删除，默认 Agent 可编辑、恢复默认，内建工具清单只读；MCP 另有测试连接。界面使用原生 HTML/JavaScript，手机端使用同一套页面。工具与主 Agent 的详细约定见 [本地工具与 Agent 配置](local-tools.md)。

0.7.0 的 Agent/SubAgent 使用统一的配置与 C 程序开发接口，支持继承、独立上下文来源、精细委派和只读预览。当前接口以 [角色开发指南](agent-authoring.md) 为准。

## 文件与运行方式

所有持久文件都在当前设备的 `mdo-home` 中；外部文件覆盖打包内置资源。只查看资源列表不会写入资源配置。内置 Skill 等文件资源可停用或保存外部自定义版本，内建工具清单只读，默认 Agent 保持启用；删除外部覆盖后，内置资源会重新出现。

| 类型 | 路径 | 运行方式 |
| --- | --- | --- |
| Agent | `agents/<id>.md` | Markdown/JSON 配置，可结合同 ID C 角色程序 |
| SubAgent | `subagents/<id>.md` | 相同的配置/C 接口，使用隔离账本及托管委派运行器 |
| 自定义工具 | `tools/<id>.c` | TCC 注册，按回调执行和收集结果 |
| Skill | `skills/<id>/SKILL.md` | 元数据发现；指令和附属文件按需读取 |
| MCP | `mcp/<id>.json` | 现有 stdio / Streamable HTTP 连接管理 |
| 命令 | `commands/<id>.c` | TCC 执行编辑器命令，参数使用 xvalue array |

ID 使用 1–64 个小写字母、数字、点、短横线或下划线，不允许 Windows 保留文件名、连续点或路径分隔符。已有 C Agent、SubAgent 继续使用 `modules/agents`、`modules/subagents`。

表单标明必填字段，保存前定位缺少内容、非便携 ID 和常用格式错误，编辑内容会保留。Agent 的提示词可留空使用默认规则，Skill 正文可留空，命令需填写指令并避开内建命令名。MCP 只检查当前连接方式，隐藏字段不阻挡保存；JSON 格式提示不会回显凭据片段。高级源文件和资源引用仍由原生接口验证。

## SubAgent

```yaml
---
name: Reviewer
description: Independently inspect changes and report concrete defects.
model: inherit
reasoning_effort: medium
tools: [read, grep, skill]
read_only: true
allow_delegation: false
---
Inspect the changed code. Report defects with supporting paths and evidence.
```

运行 ID 为 `subagent.reviewer`（文件为 `reviewer.md`）。模型留空或 `inherit` 时继承父任务；工具列表留空时继承父任务可用工具。所有子任务继续受父任务权限、并发和深度上限约束。允许再次委派最多增加一层，不能放大父任务权限。运行中的任务保留启动时的目录快照，新启动的任务使用刷新后的目录。

## Skill

```yaml
---
name: project-review
description: Inspect a repository before editing its code.
metadata:
  author: example
---
Read references/checklist.md when reviewing changes.
```

标准目录包含 `SKILL.md`，可附带 `references/`、`scripts/`、`assets/` 等目录。未知元数据保留；不执行 YAML、别名、钩子或安装脚本。旧版显式 scripts/templates/assets 清单仍限定可读取文件。

模型只增加一个共用工具：`skill`。模型先收到有预算的名称/说明目录；空参数或 `query` 搜索已启用 Skill，`offset`/`limit` 分页，返回总数和下一页位置。`name` 加载正文，`name` 和 `path` 读取列出的文本资源。SKILL.md 在编辑、导入和运行时统一限制为 128 KiB；附属文本每页 48 KiB，可用字节 `cursor` 继续读取，UTF-8 游标自动对齐并返回 EOF。二进制资源使用实际文件路径交给相应工具。打包资源在首次使用时写入按内容寻址的本地缓存，结果返回实际 `base_directory`；脚本仍通过普通工具和权限执行。搜索默认 20 条，最多 50 条。安装 Skill 不会自动执行脚本或授予权限。

聊天输入 `$` 或 `/skill:` 选择技能，填写任务后展开为普通草稿，再确认发送。切换设备或会话后迟到的读取结果不会覆盖当前草稿。

可导入单个 `SKILL.md`、完整文件夹，以及本程序导出的 `.skill.json` 文件包。浏览器小型文件夹导入/导出限定 128 个附属文件和 128 KiB 附属内容；文件包保留二进制资源。大资源或不支持目录选择的手机浏览器，可直接复制到 Home 后刷新，或者导入小型文件包。核心管理源文件最多 128 KiB；没有引入 ZIP 库、远程下载器或依赖安装器。

## MCP

表单提供 stdio（程序、JSON 参数、工作目录、环境变量）和 Streamable HTTP（HTTPS 地址、请求头）。stdio 所需程序必须已经安装在目标设备；Android 通常使用 HTTP MCP。保存不启动程序，测试连接和实际调用才连接。

支持导入常见 `{"mcpServers":{"name":{"command":"npx","args":["..."],"env":{"TOKEN":"..."}}}}` 或带 `url`、`headers` 的配置，也支持本程序的原生 JSON。多服务器导入逐个保存，不覆盖同名文件；失败会明确报告已经保存的数量。旧 SSE 传输不支持。

普通配置中的凭据进入现有本机密钥库，配置只存 `vault:` 引用。表单的环境变量/请求头支持普通 JSON 对象（如 `{"Authorization":"Bearer …"}`）和原生引用数组，也可手动填写 `env:` 和 Home 相对 `file:` 引用。导出不含凭据值，换设备后需要重新配置凭据。源文件模式可调整超时、工具过滤和权限等已有配置项；保存走现有完整校验。

## 命令

```yaml
---
description: Review a file
argument-hint: <path>
---
Review $ARGUMENTS and report concrete defects.
```

输入 `/` 后从菜单选择；带参数命令先填入 `/review `。输入参数并点击发送会展开为草稿，再次确认才提交。无参数模板选择后直接成为普通草稿。命令不运行 shell、不创建独立任务系统，不绕过附件、排队、会话恢复或权限规则。内置 `/stop`、`/new` 等名称不能被自定义资源覆盖。

## 保存与验证

编辑和删除必须带当前源文件 SHA-256 修订值，外部修改会返回冲突，不丢弃编辑草稿。普通更新原子替换文件；Skill 文件夹先准备隐藏目录，成功后整体发布。运行目录发布失败会回滚；无法完成回滚时走既有重启保护。编辑期间不能切换设备，以免将草稿写到错误设备。

资源目录、编辑内容、工具清单与导出读取使用现有的有界安静退避：单次八秒、共同一分钟、最多六次。可恢复读取失败不会中途提示，明确拒绝或重试耗尽后才显示最终结果。切换分类、设备、返回对话或关闭页面取消旧读取，迟到内容不能再打开编辑窗口或下载旧文件；同一编辑意图的新读取替代旧读取。资源的插件归属信息是可选读取，只尝试一次，不拖入整轮退避。保存、删除、启停、导入及目录重新编译的写请求不由这个读取机制重放。

“扩展包”不再是独立的界面或扩展体系。插件统一定义为可以新增、覆盖任意 mdo 应用文件，并可选择加载执行代码的扩展；既可只覆盖文件，也可组合分发已有独立资源。设置保留一个“插件”入口，旧 store 路由转到此入口。

旧组合包的格式、安装收据和存量文件继续保留，详见 [历史扩展中心协议](ecosystem-store.md)。移除旧前端不修改这些数据，也不改变八类已完成的独立商店。新的插件加载和文件管理设计见下节；它不表示新插件页面与运行时已经实现。

验证命令：

```text
python tests/test_extensions_runtime.py
python tests/test_extensions_runtime.py --packed mdo.exe
python tests/test_skill_runtime.py
python tests/test_module_runtime.py
node --test tests/test_extension_formats.mjs tests/test_frontend_i18n.mjs
node --experimental-vm-modules tools/check_web_modules.mjs
```

The Skill manager's **来源、项目与 AI 创建** entry adds project-local editing,
independent enablement, recoverable removal, AI-assisted authoring in a separate

See [Skill format](skill-format.md) for source precedence, supported fields and

## 插件定义、加载与文件管理设计

2026-10-26 设计。范围是产品实际能力及其必要的安装、启停和恢复，不增加追踪系统、诊断面板、能力预检平台、后台调度引擎或新的第三方依赖。

### 定义与实现状态

插件是一份有身份和版本的扩展，可以覆盖 mdo 应用文件，可选执行前端 JS 或原生 C。多个角色、工具、命令及资料可以由同一个插件携带；“扩展包”只是安装文件的称呼，不再有独立的菜单、商店分类或创作入口。Agent、SubAgent、Agent 工具、MCP、Skill、编辑器命令、外部工具、知识库仍可各自独立开发和分发。

这里的“任意覆盖”以应用 VFS `/app/` 为根，不按 web、模块或核心源码设置固定目录白名单。目标使用应用相对路径；不是宿主磁盘绝对路径。项目、会话、账号凭据、插件登记和备份通过专用用户存储访问，不参与应用覆盖解析。受信任 C/JS 代码仍有真实 SDK/进程能力，目录规则不是原生代码沙箱。

现有 `plugin.apply/enable/disable/remove/rollback/list` 已提供不可变修订、VFS 覆盖和可选前端入口；模块 ABI 已有 Register/Stop/Unregister。新设计还需要统一插件清单、专属 C 入口、完整文件映射发布、版本隔离的前端加载及新的管理页。当前“插件”页主要还是旧 C 模块清单。

### 开发目录与清单

作者目录包含 plugin.json、可选 runtime/、覆盖文件和说明许可。下面是拟采用的作者清单；文件大小和 SHA-256 清单由打包器生成，作者不必手写：

```json
{
  "format": "mdo.plugin.v1",
  "id": "example.notes",
  "name": "笔记助手",
  "version": "1.0.0",
  "description": "增加笔记面板和写作角色",
  "author": "Example",
  "license": "MIT",
  "overrides": [
    { "source": "overlay/web/notes.css", "target": "web/notes.css" },
    { "source": "overlay/agents/writer.md", "target": "default-home/agents/writer.md" }
  ],
  "entry": {
    "frontend": "runtime/frontend.js",
    "native": "runtime/plugin.c"
  }
}
```

`overrides` 和两个入口分别可省略：支持纯覆盖、仅执行及两者结合。所有 source/entry 均指向插件自己的文件，target 相对于 `/app/`；不写设备绝对路径，不下载未包含在安装清单内的执行依赖。安装后整目录可随 mdo Home 迁移。平台、最低能力版本、版权和审核资料沿用现有作品机制，不建立第二套账号或发布系统。

大小限制随既有每版本作品配额执行，安装器与平台使用同一清单计量。当前 SDK 的 4 MiB 修订及 JSON/base64 参数上限需要与此对齐，大文件复用已有上传对象/下载任务和流式摘要校验，不能把任意文件扩大成无限制内存 JSON。`plugin.apply` 与商店安装最终须调用同一文件归属、冲突和事务实现，避免本地 SDK 路径绕过商店路径的检查。

“没有专属入口”只表示加载器不额外调用插件入口。覆盖了内置 JS、模块、角色或核心 C 时，这些文件仍可能随 mdo 正常使用而执行；不能把纯覆盖标成无代码或无需信任。

### 文件组织与覆盖规则

持久布局继续使用 `plugins/<id>/revisions/<sha256>/`。修订内有已验证的清单与 files/，发布后只读；`config/plugins.json` 记录所选修订、前一修订及启停意图。作者可编辑的工作副本与已安装修订分开，保存工作副本后再产生新修订。运行产生的插件数据走 `plugin.<id>` 存储命名空间，不写回修订目录。

覆盖通过 VFS 映射，不物理覆盖程序内置文件或用户原文件。目标顺序为有效插件覆盖、现有 Home 应用资源覆盖、程序内置资源；停用后显露下层文件，无需拿旧副本覆盖回去。用户数据存储不走这一优先级。

每个文件有来源路径、应用目标、大小、SHA-256、所属插件及修订。加载器只映射清单列出的文件，不能因为挂载父目录而暴露整个目录中的额外文件。枚举与打开使用相同文件视图，新增目录也能被现有资源管理器发现。

同一路径只能有一个启用插件声明所有权，不提供安装先后顺序或隐藏优先级。未启用的冲突插件可以保留，启用时列出冲突插件和文件，停用冲突方后再继续；不自动替用户停用其他插件。文件/目录前缀冲突、大小写和跨平台路径别名一并检查。路径不得通过 `..`、绝对路径、软链接、junction 等脱离所属修订。

不同插件以 SDK 注册的工具、服务、面板等标识同样必须检查归属，不能仅检查磁盘路径。资源编辑页能显示所属插件；商店来源只读，作者改工作副本后发布新修订，避免编辑器写到被覆盖后不可见的下层文件。

### 加载与生命周期

启动顺序是：最小内置恢复入口 → 恢复未完成的插件事务 → 读取启停清单并校验文件 → 建立完整应用文件视图 → 加载原生入口和资源目录 → 窗口就绪后加载该窗口的前端入口。恢复入口与登记读取不能依赖待挂载的插件文件；保留 `MDO_PLUGINS_DISABLED=1` 启动路径。

前端复用 `activate(sdk)`，返回可选清理函数。入口从带插件 ID 和修订的私有 URL 加载，相对 import、CSS 和附件也自然落到相同修订；只在根脚本附加查询参数不足以隔离它的依赖。每个窗口一份前端实例，后台 C 入口在所属设备宿主中一份。切换控制设备不把本机 UI 插件安装到远端，也不重复启动后台入口。

C 入口复用 `mdoModuleEntry` 以及现有模块 ABI、Application SDK，不再发明第二套工具/服务接口。显式入口才能作为插件原生代码加载，附属 .c 文件不会因为存在于包中就逐一执行；声明为普通资源模块或被覆盖到既有模块目录的文件仍按原资源规则处理，避免同一入口被加载两遍。

Register 成功后才发布其工具、角色、服务和回调；失败清理此次贡献。Stop 停止自身生产者并响应取消，已有调用持有旧代际直到结束，再 Unregister 释放共享状态。停用或更新时不强制释放仍被调用的 C 对象，不强杀线程；不能安全退役的插件显示等待结束或需要重启。JS 清理移除自己注册的贡献，不能用旧实例的清理函数删除新实例的同名贡献。

插件关闭时不能承诺撤销任意文件写入、网络请求或其他外部副作用；加载器负责撤销覆盖、清理受管贡献和安全退役代码。插件注册、启动与停止回调不在全局 VFS/插件互斥锁中执行。

### 生效、更新与恢复

操作先准备只读候选修订，验证摘要、目标冲突及当前修订，再生成完整候选文件映射；使用持久事务与修订条件提交所选版本。新的文件映射应作为一个 VFS 代际发布，编译和目录读取持有同一快照；已打开句柄继续读旧文件。这需要改造当前逐目录提前挂载的行为，不能把现有文件级原子性当作完整插件原子切换。

文件视图、资源目录、C 对象和浏览器脚本不能在一个瞬间全局切换。分别记录用户选择的修订与各运行域实际采用的修订，详情明确给出生效动作，不用一个 enabled 字段伪装全部生效：

| 修改内容 | 生效方式 |
| --- | --- |
| 普通文档、数据和新静态文件 | 提交新的文件视图；已有缓存按相应使用者重新读取 |
| 角色、工具、命令及其他资源目录 | 复用对应资源目录的代际刷新，现有运行保留旧代际 |
| 插件专属 JS/C 入口 | 按上述生命周期退役旧实例并启动新实例；失败不重复自动执行 |
| 已执行的应用 JS/CSS、核心源码覆盖 | 明确提示刷新界面、重载宿主或重启，查询既有重载回执后确认 |

更新保留原启停状态。安装和停用的文件视图变更可恢复；新入口失败可以恢复旧文件视图，但不盲目重复调用旧 activate/Register，更不声称外部副作用被回滚。需要用户刷新或重启时展示 pending 状态；避免一轮轮自动重启、重试插件入口。

历史修订用于明确回滚。卸载先退役入口再移除覆盖和登记，不删除原应用文件、用户项目或插件独立数据；保留私有修订备份。清理数据和历史修订是用户明确选择的独立操作，仍被调用或当前/前一版本引用的文件不能清理。坏清单、丢文件或加载错误收拢到已有统一警告入口，提供禁用、回滚和查看失败信息，不新增监控页面。

### 管理界面与迁移

“插件”保留本机/商店两个选项卡，沿用统一搜索分页、署名版权、无列表内滚动、公共弹窗和全局下载任务。详情提供说明、文件、入口与版本信息；文件页显示树/列表、目标路径、来源、摘要、新增/覆盖和需要的生效操作，源码及差异可只读查看。保存、启用或安装按钮固定在弹窗底部。

本机自定义支持创建目录、添加/替换/移除映射、源码编辑、预览和分享；商店副本只提供启停、更新、卸载和只读文件查看。仅“文件覆盖”或“运行入口”的插件都使用这一套页面。模块开发是插件的一种实现方式，不再出现独立“扩展包”入口。

后台与创作中心收敛为插件一个分类。历史 modules、plugins 和组合包的原始字节与审核摘要保持不变，适配成带原始归属的旧记录；不静默合并 ID、不覆盖本地作者文件、不因迁移自动执行旧代码。旧收据和安装事务在迁移完成前保留读取能力。八类独立扩展不需要为这次收敛修改原包格式。

### 实施次序与验收

1. 完成清单、不可变修订和精确文件映射；验证纯覆盖插件新增/替换、目录枚举、冲突、停用显露原文件和事务中断恢复。
2. 接入前端与 C 入口；验证有/无入口、相对依赖版本一致、启动一次、贡献清理、旧代际在途调用、失败恢复和恢复启动。
3. 重做插件管理页与线上分类，完成自定义 → 投稿 → 审核 → 安装 → 更新 → 下架/卸载链路，验证来源权限和旧记录迁移。
4. 对 Windows、Linux 和 Android 的实际加载进行回归；Android 外部可执行程序仍走完整版 APK，C 源码继续使用既有 TCC 能力，前端覆盖需验证 WebView 刷新。

本轮只完成“扩展包”界面移除（含旧路由处理）与此设计，未实现上述新增机制、迁移或线上发布。界面改动通过 23 项 Node 回归、20 项前端契约检查和 231 模块解析/可达性检查；不以这些结果代替插件运行时的验收。
