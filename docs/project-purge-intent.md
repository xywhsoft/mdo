# 项目清除的便携请求意图

`src/api/project_purge_intent.c` 保存前端将要核对/执行的请求绑定。它不是清除授权，
不会自动执行、取消或重试。执行/取消仍以 [持久结果协议](home-purge-transaction.md)
及服务端最终事实为准。持久意图、HTTP 协调及前端恢复/取消与草稿/队列暂停
已接入；明确清除确认/执行和提交后的导航收敛仍待完成，不将此阶段记作产品
清除操作完成。HTTP 页面代和写入准入见 [旧页面保护](http-write-admission.md)。

## 文件与读取

一个 Home 同时保留一项意图，位于 `data/project-purge-intent.json`，不使用浏览器
localStorage，不生成备份。程序和完整 Home 一同搬移时保留这个文件以及
`data/project-purges` 中的原结果凭据。示例：

```json
{
  "schema_version": 1,
  "intent": {
    "purge_request_id": "dddddddddddddddddddddddddddddddd",
    "project_id": "demo",
    "revision": 1,
    "created_at": 1790790000000000,
    "name": "Demo"
  }
}
```

文件最多 2048 字节，根精确两个字段，意图精确五个字段。ID、版本与创建时间
采用执行接口的同一校验；名称来自服务端已审阅的定义，仅供辨认，最多 256 个
UTF-8 字节。JSON 拒绝重复/额外字段、非法 UTF-8、NUL、未知版本与超限。
空状态只能是文件不存在；损坏、目录或 null 记录均不是“没有请求”。读取核对
路径和打开句柄在读取前后的文件身份、类型和大小，无内置 VFS 回落或自动修补。

`GET/HEAD /api/v1/project-purge-intent` 返回 `{intent: null | {...}, replayed: false}`。
读取不创建 Home。存在时的强 ETag 为 `"mdo-purge-intent-<id>"`，不存在时为
`"mdo-purge-intent-empty"`。所有读取/保存/确认与执行/取消共享意图互斥锁；
服务端意图锁涵盖业务执行及结果捕获，不能在保存或确认移除的间隙换成另一个
绑定。结果查询本身独立，不受意图损坏或当前定义/项目门的限制。

## 保存与重放

`POST /api/v1/projects/{project}/purge-intent` 使用预览返回的原项目强 ETag，正文
精确为 `{purge_request_id, created_at}`，与执行/取消共用绑定解析器。已有同绑定
意图直接返回原名称和 `replayed: true`，不重新读取已删除或重建的项目；另一个
编号、项目、版本或创建时间返回 `409 purge_intent_conflict`，不覆写旧文件。

新意图先核对 ID 未被接受，再取得共享项目租约、读取当前主定义并校验版本/
创建时间，最后通过 Home 原子写入发布。定义缺失返回 404，版本/创建时间变化
返回 412，项目门忙返回 409；这些失败不保存意图。共享租约不能将瞬时预览
升级为排他授权；普通定义更新仍可发生，最终执行必须重新取得独占并检查。
新保存不接受已知请求 ID，即使绑定相同，以免迟到的保存复活已确认移除的意图。

写入后读回精确绑定与原名称。关闭报告错误但实际已发布时，以读回确认结果；
无法核对时保留当前文件及 ID，返回 `purge_intent_unavailable`。客户端丢失保存
响应后应 GET 意图并核对原绑定，不生成新编号。仅保存意图不会接受清除请求、
扫描目标或修改项目/计划缓存。正式执行/取消在有意图时只允许相同绑定；其他
绑定返回冲突。没有意图时保留原 HTTP 调用兼容性，前端应先保存并确认原绑定。

## 确认移除与取消

`DELETE /api/v1/project-purge-intent` 必须提供已保存意图的强 ETag。它表示客户端
已处理原结果，不代表取消请求。服务端只有在读取到相同 ID/项目/版本/创建时间
的 `committed` 或 `aborted` 终态后才移除意图；未知/pending 结果返回
`409 purge_intent_unsettled`，损坏/矛盾结果返回错误且不移除。客户端必须先
停止受影响的本地写入，并按提交事实处理草稿、队列和导航，不能先丢失意图。

取消必须调用 `purge-cancel` 并验证原终态。只删除本地标志或关闭弹窗不能阻止
迟到执行。成功确认后结果凭据仍保留，不复用 ID；迟到保存被已接受记录拒绝，
迟到执行只重放原结果。旧确认的 ETag 不能移除后续新意图。确认响应丢失或进程
在移除后退出，重复 DELETE 在原终态仍有效且没有新意图时返回空与
`replayed: true`，不会创建 Home。

Home 冻结时，GET 与同绑定保存重放仍可核对原记录；新保存及真正移除保持 Home
写入拒绝，需先重启恢复。普通 HTTP 写入的冻结规则不变，导入隔离仍适用于所有
这些 POST/DELETE。意图没有到期或自动执行规则；当前保证测试过的进程中断
恢复，不承诺断电目录元数据持久性。外部同权限程序直接改写文件不在内部互斥
契约内；异常读取保留证据，不自动猜测“空请求”。

## 有界验证与后续接线

2026-10-01 的前端已接恢复/查询、原编号取消及 abort 的明确确认移除。
启动核对之前与已有记录未收敛时暂停当前页面的自动保存、草稿迁移、任务
派发及普通 API 写入，保留未发送内容；既有 Run 停止及读取可用。恢复卡位于
项目设置，通过全局提示直达。超时/损坏/矛盾响应不当作空意图，已提交结果
不提供取消或确认移除；旧页不会因另一页移除意图就丢掉已知未收敛编号。
`tests/test_project_purge_recovery.mjs` 验证这些异步路径；隔离最终打包页覆盖
桌面、320×350、取消后刷新及确认、主定义已经消失的提交结果。

这是当前页恢复门，不会撤销在途 HTTP。另有 [HTTP 写入准入](http-write-admission.md)
拒绝其他旧页面的迟到写入，并在已接纳 HTTP 写入尚未结束时拒绝开始清除。
准备新意图、明确清除确认/执行、受影响操作排空、提交后的本地状态收敛仍待
完成，产品没有实际清除按钮。下述执行顺序继续
作为后续接线要求，不能把恢复/取消面板记作完整清除操作已交付。

`tests/test_project_purge_intent_runtime.py` 在十三个隔离 Home 运行正式 HTTP/
Windows xs/TCC：空读零创建、参数/版本/名称、同绑定重放、两个客户端争用、
断开执行/确认响应后的核对、原定义变化与同名重建、迟到保存/旧确认、冻结与
重启、发布/移除失败及关闭错误、保存/移除后退出、损坏 JSON/类型及矛盾凭据。
故障只注入复制源；项目/引用/工作区字节和目录代按原操作事实检查，不调用模型，
不触碰日常 Home，不做压力或高负载测试。

前端接线必须遵循顺序：审阅清单 → 保存并确认原意图 → 以相同编号执行 → 核对
原提交事实 → 处理本地草稿/队列及导航 → 确认移除。刷新/多页面要先读取意图，
禁止自动创建新编号或自动执行；响应不明时保持原编号并提供查询/取消。UI 还须
验证操作中暂停自动派发/保存，清除后不会因旧内存状态恢复被移除的全局引用，
以及手机弹层、键盘取消、焦点返回和其他项目状态保持。
