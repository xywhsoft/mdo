# 前端操作体验完成审计

本清单以 `app_bak/wwwroot` 的可操作行为为基线，而不是以页面长得相似或单元测试通过为完成标准。`docs/frontend-migration.md` 记录每次实现和验证；这里记录当前还需要什么证据。审计日期：2026-09-25，基线提交 `f9e2c4c`。

## 证据分级

- **打包实测**：从本仓库构建的 `mdo.exe`，使用隔离的便携 Home 和真实 HTTP 页面完成操作，检查界面、API 持久状态和刷新后的结果。涉及模型时使用有界本地测试端点，不依赖公网。
- **模块实测**：真实浏览器加载生产前端模块，但通过测试夹具模拟部分 API 或状态。这能验证焦点、布局和并发隔离，不能代替打包页的端到端操作。
- **运行探针**：真实 xs/TCC 宿主验证 API、持久化和 Agent 状态，不证明前端按钮可用。
- **待验证**：已有实现或部分证据，但尚未完成该行的打包实测。**缺功能**：旧版有可用入口，新版尚无同等入口或底层能力。

## 明确缺口与边界

1. **界面语言：缺功能。** 旧版设置可即时切换中文、英语、俄语；新版默认配置有 `settings.locale`，但 `app/web` 只有极小的 `zh-CN.json`，页面和模块文案仍是中文常量，设置页没有语言选项。需要统一翻译键、三份完整词典、动态切换和便携 Home 持久化。不能只翻译设置页就标记完成。
2. **彻底清除项目：缺底层事务。** 新版只提供只读 `purge-preview` 和取消注册。真正删除须先完成 `docs/project-purge-transaction.md` 的跨进程租约、锚定搬迁、崩溃恢复和共享审计策略；不得把取消注册改名为清除。
3. **附件最终操作：待验证。** 合成图片已在隔离打包 Home 中选入并持久化；图片移除的模块夹具和服务端探针通过，但最终打包页的真实移除、原生系统拖放没有完成。
4. **全量历史搜索：后续增强。** 旧版和新版都只搜索已经载入的消息；当前有记录截断提示。服务端索引不是恢复旧版操作手感的前置条件。
5. **完整 CommonMark：后续增强。** 当前安全 DOM 渲染覆盖常见 Markdown；嵌套规则仍不完整，不把它误记成旧版核心交互已经失效。

设置项还需逐项对照旧版。旧版“阻止系统休眠”、HTTP 代理与自定义 CA、系统提示词有可见设置；新版 `app/web/index.html` 未提供同名入口。它们是否由新架构的其他配置或扩展能力替代，应先核对运行时行为，再确定迁移范围，不能仅凭旧名称缺失就断言底层能力缺失。

## 打包卡片复测

先构建根目录程序，再运行 `python tests/manual_packed_docks_qa.py`，打开打印的本机 URL。在输入框依次发送 `TODO UI`、`ASK UI`、`APPROVAL UI`，分别检查计划、待答卡片和审批卡片；夹具每个标记只发送一次工具调用，其余模型回复为固定文本。完成后在夹具终端按 Enter 停止服务。测试 Home 位于 `.build/mdo-packed-docks-*`，与日常便携 Home 隔离。审批按钮的交互验收应单独记录；只看到按钮不代表允许或拒绝路径已通过。

## 发布收尾条件

1. 逐行完成核心操作链的打包实测；对失效场景保留修复提交和回归步骤。图形工具要求当次确认的删除动作在收到确认前保持待验证。
2. 对明确缺功能项实施或书面确定不属于此次旧版交互迁移，并让产品入口如实反映；不把模块夹具通过写作最终打包验收。
3. 在 Windows 上运行既有有界发布门禁、确定性打包和单文件零旁路写入检查；Linux/macOS 的构建和操作体验另列平台验证，不从 Windows 结果推断跨平台通过。不进行压力或高负载测试。
4. 每完成一个功能或阶段，更新 `docs/frontend-migration.md`、提交 Git，并重建根目录程序。只有上述验收均有证据时，才将长期任务标记为完成。
