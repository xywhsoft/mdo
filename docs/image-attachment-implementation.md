# 图片附件落地约束

旧版输入区支持选择、粘贴和拖入图片，也允许只有图片的消息。新架构应保留这些入口，并让图片作为模型用户消息的 IMAGE part 进入持久账本；只在浏览器里显示预览或把文件路径写进文本都不算完成。

## 已接通的底层

- xrt 的 xwork 新增 `xworkRunCreateWithUserMessage`，在创建异步运行时深拷贝用户消息。消息须由一个 TEXT part 和 1–4 个 IMAGE 字节 part 构成；文本可为空，图片只接受 PNG、JPEG、WebP，单张不超过 8 MiB、总量不超过 16 MiB。显示在事件日志的提示文本必须与 TEXT part 一致。原有纯文本运行入口和 ABI 结构不变。
- xs 的 xwork vendored 副本逐字节跟随上游，并将新符号加入 TCC 导入表。mdo 工作区的 xs/xsw 已从该修订重建。
- 有界 xwork 测试覆盖输入文本不匹配时拒绝，以及调用方释放消息后异步模型回调仍能读到原始图片字节。未运行压力或高负载测试。
- mdo 已有按会话绑定的图片 `POST` 上传和 `GET/HEAD` 原件读取路由。上传独立于 JSON 的 256 KiB 上限，单张最多 8 MiB；按 Content-Type 与文件签名检查 PNG、JPEG、WebP，按会话最多保存 16 张、合计 32 MiB。原件及 JSON 元数据位于便携 Home 的 `sessions/<project>/<session>/attachments/`，读取只接受本会话 32 位十六进制 ID，响应禁止缓存与 MIME 猜测。XS 收包上限已同步调至可容纳 8 MiB 图片。
- 运行请求现可传 `attachments` 数组，最多 4 个本会话附件 ID；服务端重新读取原件，总图片字节最多 16 MiB，并组装一个 TEXT part 加后续 IMAGE parts。xwork 同步深拷贝后才启动异步任务。没有图片能力的模型会返回 `image_model_unsupported`；Ling 3.0 Tiny 默认仍保持纯文本能力。
- 有界 HTTP 探针验证了超过 JSON 上限的图片上传、磁盘持久化、GET/HEAD、格式拒绝与跨会话拒绝；独立图片模型探针验证了纯图、文图消息确实进入模型请求，也覆盖缺失、重复和超量引用。
- 会话草稿与待发队列现保存最多 4 个本会话图片 ID，验证文件存在及总量不超过 16 MiB。新文件 schema 2 保留原 schema 1 纯文本读取兼容；纯图片草稿和队列项可恢复，`sending` 状态保留引用而不自动重发。全局新任务草稿不允许持有尚未绑定会话的图片。
- 运行启动前将附件 ID 暂存在会话事件桥接器中；顶层 `agent_start` 使用持久事件 ID 将引用原子写入 `attachments/events/`。进程重启后 xwork 的 run ID 会复用，因此它不能作为持久身份。旧版 `attachments/runs/` 记录仍可读取；新纯文本运行碰到同号旧记录时写入空引用标记，避免把旧图片误显示在新消息中。没有附件的单文件运行不因此创建 Home。
- 前端现支持选择、粘贴、拖入 PNG/JPEG/WebP，上传到本地会话后显示可移除缩略图；草稿和历史图片可点开原图预览，并支持关闭按钮、背景点击及 Esc。纯图和文图消息的附件 ID 随草稿、待发队列和运行请求传递；刷新后的草稿和历史用户消息从会话附件路由读取原图。当前模型需声明图片能力，Ling 3.0 Tiny 继续保持只读的纯文本默认模型。上传期间禁止发送。
- 分叉仅复制持久边界内保留的顶层用户事件图片，按事件 ID 重建子会话引用，并把原件及元数据复制进子会话。分叉在图片缺失或复制失败时整体失败，回滚新会话目录；子会话随后不依赖源会话图片文件。
- 图片原件现支持按 ID 删除。服务端在同一附件锁下核对会话运行状态、草稿、待发队列、事件 ID 记录和旧版 run ID 记录；仍被引用的图片返回冲突，缺半边文件的删除可重试。前端移除草稿图片时先保存新草稿再请求删除；保存失败会恢复缩略图和草稿附件引用，并禁止在移除完成前发送。移除队列项后尝试删除其图片，由服务端保留共享或历史引用。新增图片引用和运行启动与删除互斥。
- 上传达到会话配额时，会按附件元数据中的创建时间尝试回收超过 24 小时的无引用原件，再重新核对配额。元数据缺失或损坏、新近上传、仍在草稿或历史中使用的图片不会被自动删除；遍历数量有界。运行探针覆盖旧孤儿回收及同样过期但被草稿引用的图片保留。
- 历史截断或清空后，服务端按持久的历史边界事件清理已移除用户消息的 `attachments/events/` 引用记录。重复操作、显式删除图片及配额回收都会重试这项清理，覆盖事件日志已写入但引用文件尚未删除的中断窗口；旧版 run ID 引用仍保守保留。真实图片运行探针覆盖清理和中断修复。

## 接下来贯通 mdo

1. 会话移入回收站时保留可恢复的图片；若日后提供真正删除会话的操作，再清理其目录。旧版 run ID 引用无法在所有历史截断情况下精确映射，仍需兼容期策略。
2. 对图片输入继续做打包页交互验收。隔离 xs/TCC 页面已验证模型切换、文件选择、剪贴板粘贴、混合文件的模拟拖放、刷新草稿、纯图发送、运行中图片排队与随后自动发送，以及取消图片运行后保留未发送草稿。拖放落点提示还通过带文件的合成 DragEvent 验证了虚线边框、内部移动和放下时的状态变化。最终 `mdo.exe` 通过隔离的外部 HTTP/模型配置覆盖，验证内置前端资源的文件选择和剪贴板图片粘贴、双图片草稿、390px 手机宽度，以及带图消息发送、历史缩略图、运行即时停止和取消后的草稿恢复；本地测试模型两次请求都收到图片内容，内置 Ling 默认配置未改。图片移除的真实模块隔离页已覆盖保存失败回滚、保存成功移除、切换会话时不串改新草稿和焦点返回；仍需在最终打包页验证实际移除按钮及操作系统原生拖放。服务端有界探针覆盖错误 MIME/签名、超限、错误会话引用、分叉独立性与回滚、单文件模式及模型消息。只做有界功能与启动测试。

新建任务添加图片时先创建会话，再上传至该会话的便携 Home。模型不支持图片时入口会显示明确错误。文件选择器仅接受 PNG、JPEG、WebP；后端仍独立校验文件签名与容量。
