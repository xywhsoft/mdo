# 图片附件落地约束

旧版输入区支持选择、粘贴和拖入图片，也允许只有图片的消息。新架构应保留这些入口，并让图片作为模型用户消息的 IMAGE part 进入持久账本；只在浏览器里显示预览或把文件路径写进文本都不算完成。

## 已接通的底层

- xrt 的 xwork 新增 `xworkRunCreateWithUserMessage`，在创建异步运行时深拷贝用户消息。消息须由一个 TEXT part 和 1–4 个 IMAGE 字节 part 构成；文本可为空，图片只接受 PNG、JPEG、WebP，单张不超过 8 MiB、总量不超过 16 MiB。显示在事件日志的提示文本必须与 TEXT part 一致。原有纯文本运行入口和 ABI 结构不变。
- xs 的 xwork vendored 副本逐字节跟随上游，并将新符号加入 TCC 导入表。mdo 工作区的 xs/xsw 已从该修订重建。
- 有界 xwork 测试覆盖输入文本不匹配时拒绝，以及调用方释放消息后异步模型回调仍能读到原始图片字节。未运行压力或高负载测试。
- mdo 已有按会话绑定的图片 `POST` 上传和 `GET/HEAD` 原件读取路由。上传独立于 JSON 的 256 KiB 上限，单张最多 8 MiB；按 Content-Type 与文件签名检查 PNG、JPEG、WebP，按会话最多保存 16 张、合计 32 MiB。原件及 JSON 元数据位于便携 Home 的 `sessions/<project>/<session>/attachments/`，读取只接受本会话 32 位十六进制 ID，响应禁止缓存与 MIME 猜测。XS 收包上限已同步调至可容纳 8 MiB 图片。
- 有界 HTTP 探针验证了超过 JSON 上限的图片上传、磁盘持久化、GET/HEAD、格式拒绝与跨会话拒绝。服务端尚未接受附件 ID 作为运行输入；上传能力暂不对前端显示。

## 接下来贯通 mdo

1. 为过期且未被草稿、队列或运行引用的上传加入可恢复的清理规则；会话删除时也清理附件。
2. 运行入口只接受该会话的附件 ID，装配 TEXT/IMAGE parts 后交给 xwork；模型不支持多模态时在服务端明确拒绝，不把图片悄悄降级成文本。
3. 扩展持久队列与草稿，让图片引用随文本一起保存并在刷新后恢复；`sending` 不确定状态仍需人工核对，不能因附件而自动重发。删除队列项或会话时按引用关系清理附件。
4. 前端加入选择、粘贴、拖放、缩略图、移除与上传状态；手机端按钮始终可见且不横向溢出。时间线应从本地附件路由显示历史用户图片，不依赖浏览器临时 URL。
5. 测试覆盖文本加图、纯图、刷新、排队、取消、错误 MIME/签名、超限、错误会话引用、单文件模式和不支持图片的模型。只做有界功能与启动测试。

上传路由和持久引用完成之前，不显示一个无法真正提交图片的附件按钮。
