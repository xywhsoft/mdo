# 简化的 Agent 协作 SDK 实施记录

本轮以完成实际任务、简化配置/C 扩展开发为目标。产品保持 0.7.0；不隐含正式客户端发布或生产部署。每项功能/修复独立提交 master，保留其他任务的工作区改动。

## 已有可用能力

- `state.get/list/put/compare_exchange/remove/transaction/receipt.get`：按项目/namespace 保存，写入需 expected_revision；删除保留修订，避免迟到写入覆盖重建值。同事务一次原子发布，request_id 可用于幂等重试。单值 16 KiB、事务最多 64 次写入、每空间 1024 记录/4 MiB/128 份请求回执，容量满时明确拒绝，不悄悄删除去重信息。
- `lease.acquire/inspect/validate/renew/release`：同一状态中的限时锁，旧持有者通过 fence/token 被拒绝。`lease_guard` 与状态写入在同一锁内验证；单独验证不能保护后续任意 OS 副作用。
- `mailbox.send/get/read/ack/wait`：消息 ID 去重、读取不消费，确认与状态写入可以原子提交。每条正文 8 KiB、收件人 128 条/256 KiB 未读限额。确认后保留去重回执。事件只负责唤醒，消息以持久数据为准。
- `events.read/wait/emit`：有界订阅/通知，取消和调用期限有效。8 KiB 事件、32 KiB 分页，重启/环形缓冲覆盖时明确告知重读真实状态。
- `instance.create/get/list/send/step/cancel/close`：私有原生多轮会话，不占用户会话列表。创建/排队不调用模型，step 处理一条消息并保存。每空间最多 64 个成员，全局最多 8 个成员同时执行。operation.start 可异步调用 step。
- `mdo/lifecycle.h`：插件可介入配置/C 角色上下文、请求、工具、委派和运行结束。结束回调在结果完整后发生，后台子任务完成独立通知；观察者失败不会撤销已完成工作。

成员继承父会话的实时权限。父运行退出后仍保留共享 scope；重新打开父会话继续复用，“询问/完全访问”即时切换。退出先取消并排空成员，随后销毁依赖服务。不确定外部效果不自动重放，审批与用户取消不能被自动续跑绕过。受信任进程内 C 扩展没有进程沙箱。

## 验证方式

真实 TCC/HTTP 隔离 Home 测试：`test_orchestration_sdk_runtime.py` 覆盖原子状态、竞争写入、回执、锁、邮箱、等待及重启；`test_member_sdk_runtime.py` 使用离线模型，覆盖多轮历史、重启、热重载、关闭、权限共享和中途退出不重放；`test_lifecycle_runtime.py`（含 --background）覆盖配置/C 角色、真实子任务完成、回调隔离与代码代际。运行必要回归即可，不为产品增加诊断体系。

## 成员结果与恢复

`instance.result/wait` 按 message_id 返回持久结果，等待不启动模型。关闭后的未执行消息返回取消；重启遗留的运行返回 requires_review。`instance.resume/abandon` 必须带 get 返回的 revision 和 active_message，过时的恢复请求不能启动新执行。resume 复用原生恢复和明确的工具决策；可能产生副作用的未完成工具不会默认重试，调用者可明确 retry（接受可能重复的效果）或 record_uncertain（不执行，记录不确定结果）。abandon 不请求模型，有待决工具时不能用它绕过恢复。

第一轮执行前先 checkpoint，确保第一次模型请求也可以恢复。完成后释放运行 claim，再检查无后台子任务并保存状态与结果。成员的已结束消息结果可跨重启读取；返回文本最多 8 KiB，截断会明确标记。

真实回归验证逐消息结果、通知等待/超时、中途退出后的显式恢复、旧 revision 拒绝、原用户消息只入账一次、结束中断后可继续新消息，以及关闭时未执行消息返回取消。

## 共享任务

`work.create/get/list/claim/complete/release/cancel` 与 `mdo/work.h` 提供扩展可用的简单共享任务列表，不增加内置 todo 工具或独立调度器。依赖只能引用已存在的任务，因此无需维护另一套工作流图；依赖完成后即可领取。领取采用当前 revision，竞争者只能有一个成功。worker/claim_id 可找回当前领取 token；完成/释放须带 token，任务被重新领取或取消后，旧执行者的迟到结果会被拒绝。

结果是最多 16 KiB 的普通 JSON，调用者决定如何检查完成质量；不加入专门的验证、证据和监测体系。完成的结果不可修改，相同结果重试幂等。领取不会自动过期重派，避免一个工作被重复执行；需要重试时明确 release。每执行空间最多 128 项任务，列表按条数和 32 KiB 分页，保留现有 namespace 的总容量限制。

真实回归验证依赖阻塞、8 方竞争只允许一个领取者、旧 token 拒绝、重启后取回领取、幂等结果提交、取消、结果大小及分页稳定性。

## 成员接入

成员的 C 程序、配置角色调用的 C 工具、生命周期回调及 SDK 后台操作共享 Namespace/MemberId。普通 state/mailbox/work 调用省略 namespace 即使用所属协作空间，消息 sender 使用成员身份；无需每次传参。配置模板可用 `{{instance.id}}`、`{{namespace}}`。公开 context 仅追加可选字段，原有项目、会话与工作目录身份保持原语义。

真实配置角色通过工具读到正确空间与成员，发出的邮件具有成员身份；真实 C 角色用公共 mdoWorkCreate 不传 namespace 即在同一空间创建任务，然后调用默认模型循环。后台操作复制这两个字段，并保留调用方代码 catalog，避免丢失成员所属空间。

## 后台子任务修复

真实后台回归发现已解析的推理参数曾借用创建会话时的 Settings 临时字符串，父函数返回后可能失效，子任务因此在模型请求前报不支持推理档位。已改为已解析模型值自身保存字符串，复制到父/子角色时一并复制；不新增任何诊断接口。回归主动覆盖创建函数的栈内存，并要求父任务先结束后子任务仍完成写入和回复。
