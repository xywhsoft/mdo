# 项目清除的 Home 存储事务

`home_purge.h` / `src/storage/home_purge.inc.c` 实现项目数据根的搬迁、回滚和启动
恢复。它是存储原语，没有 HTTP 执行入口；不能绕过项目生命周期门或把只读预览
当作删除授权。项目业务层仍须独占项目、检查 revision/活动对象、协调全局引用，
并在提交后同步计划缓存和导航。上层接入前，不开放产品清除按钮。

## 调用与数据边界

`MdoHomePurgeFiles(ProjectId, Targets, Count, Committed)` 接收调用者独占范围内
重新扫描得到的、调用期间保持不变的候选数组。清单与存储原语共享目标结构和
容量定义。参数必须有序、无重复路径/根身份，包含项目主定义，并限定为项目
八个固定路径或合法计划命名空间。路径来自服务端，计划的业务归属由清单层
验证；存储层不接收用户任意文件名，也不负责业务授权。

单次事务最多 1024 个候选根；遍历最多 8192 个节点、16 层目录，清单最多
512 KiB。文件和目录均通过 Home 的 anchored root 操作。拒绝链接、非法名称、
身份或文件大小变化、重复根及类型不符。所有目标预检结束后才创建事务目录。
纯单文件、没有外部 Home 时拒绝执行且不创建 Home。普通 Home 接口拒绝
`.mdo-purge`、`.mdo-purge-cleanup` 及大小写/尾随点空格别名。

`data/draft.json` 与 `data/workspace-state.json` 现可作为条件目标，由业务层持有
引用保护器并严格解析当前归属后加入同一清单。存储层只接受这两个固定文件名，
不自行判断业务归属；没有项目归属的旧草稿和其他项目的记录必须保留。全局引用
备份不由现有 writer 生成，不猜测历史备份归属，也未放开其路径。配置、缓存、
共享审计、其他项目及用户工作区仍不在清单中。不得在删除后无保护地补写引用。

## 不可变日志协议

外部 Home 的 `.mdo.lock` 始终持有。一个固定的 `.mdo-purge` 事务槽由 Home
互斥锁串行使用，记录目录及 payload 的设备/文件 ID，作为当前存储事务身份；
业务层的请求 ID、结果凭据及可追溯操作记录仍待接入。

1. 创建私有目录、刷新 `owner` 所有者标记，再创建 `payload`。
2. 记录项目、事务目录/payload 身份、排序后的源路径、类型、根身份及文件大小。
   清单写到独占临时文件，刷新后无覆盖改名为 `ready`。
3. 逐个把源搬到 `payload/0000` 等服务端槽位。每次移动前检查原身份和目标
   不存在，移动后检查源已消失、槽位仍是原对象。API 返回句柄关闭错误但实际
   已移动时，以两处身份核对确认结果，不再重复移动。
4. 全部移动后，刷新并发布不可变 `committed` 标记。此时已经提交，不再回滚。
5. 整体把日志退役为 `.mdo-purge-cleanup`，再清理其 payload 和标记。清单保持
   到 payload 全部清完，所有者标记最后删除。中断后退役目录只继续清理。

未逐步覆写“已搬迁计数”；状态由每个根的原位置和槽位共同证明。发布标记使用
同目录临时文件、独占创建、flush 和 no-replace 改名。当前验证**进程中断恢复**；
没有承诺断电后目录元数据持久性，也不把标记 flush 等同于完整断电事务。

## 回滚、恢复与错误结果

提交前错误先完整验证日志、全部槽位及根位置，再按逆序补偿。每项必须恰在
一处，且保持原身份；两处都有、两处都没有、替换目录、损坏标记、陌生日志项
或链接均拒绝恢复，不猜测、不覆盖，不删除冲突数据。

`MdoHomeInit` 挂载并取得整个 Home 的跨进程租约后，在业务管理器初始化前
恢复日志。此时没有业务对象或请求可写，Home 进程租约提供启动阶段的排他性；
运行期业务独占仍必须由调用方取得。清除和旧导入日志同时存在、活动和退役
日志同时存在都会阻止启动。已提交日志必须证明全部源已搬走，才能退役清理。
无 `ready` 的准备中日志只允许空 payload；未知数据仍保留并拒绝恢复。

返回 `true` 表示存储提交并清理完成。返回 `false` 时必须检查 `Committed`：
`false` 为未提交失败，正常补偿后原数据保持；`true` 为已经提交后的错误，不能
重试为一个新删除请求。回滚/清理无法完成或运行中出现待恢复日志时，Home
设置 `RestartRequired`，拒绝普通写入并保留证据。即使提交后清理失败，业务层
仍须处理缓存和结果状态，不能保留可执行的旧计划对象。

## 当前验证

`tests/test_home_purge_runtime.py` 经真实 Windows xs/TCC 使用十一项小型数据根：
所有搬迁节点的失败和进程中断、三处移动后错误、提交失败、准备/临时标记/
提交/退役/标记清理中断及重复启动；回滚失败和提交后清理失败均冻结写入，
重启后按正确方向恢复。另覆盖文件句柄阻止改名、改名成功却报告关闭错误、
无 Home、非法/重复/过期目标、四节点限额、源和 payload 内的 junction、根/
payload/日志身份替换、文件大小变化、歧义位置、错误清单路径、标记损坏、
过早提交及旧导入日志冲突。其他项目、配置、缓存、全局状态和共享记录字节
保持；节点限额通过复制源注入，不生成大量文件或运行高负载测试。

本证据只证明存储协议，不证明业务清除、全局引用协调、计划缓存同步、前端
确认/结果恢复已经接通。Linux/macOS 尚未复验；Windows 门禁结果见前端迁移
记录。外部程序直接修改私有日志或项目桶仍可能造成拒绝恢复，应保留日志与
冲突对象供排查；不能承诺阻止任意同权限外部程序改写 Home。

`tests/test_home_purge_runtime.py` 另把两个条件引用加入十三项小清单，验证成功、
提交前失败、引用移动后进程中断和提交后进程中断；重启及重复重启分别完整恢复
原文件或保持提交结果。业务归属与普通 writer 的协调由独立 HTTP 探针验证，见
[项目引用保护](project-purge-transaction.md#已实现全局引用保护)。这仍不是产品
清除入口、计划缓存同步或持久结果凭据的验收。
