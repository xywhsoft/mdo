# 前端交互迁移记录

目标是保留 `app_bak/wwwroot` 经验证的操作逻辑，逐步迁到 `app/web` 的模块化实现。页面布局可改进；输入、运行、审批、消息操作必须以服务端状态为准。原生 HTML、CSS、JavaScript 保持无包管理器构建，随 `mdo.exe` 一起打包。

## 已落地

| 交互 | 当前实现 | 约束 |
| --- | --- | --- |
| 消息统计 | 会话事件保留模型输入、输出 token；回复显示 token/s 和完整时间提示 | 旧事件 schema 1 可回放，新事件 schema 2 |
| 消息操作 | 复制和分叉放在回复下方 | 分叉通过服务端会话 API，不在浏览器伪造历史 |
| 任务与审批 | 当前会话内嵌后台任务和一次性权限审批 | 按会话和 run 关联，审批决策由服务端执行 |
| 待办计划 | 内置 `mdo.todo` 工具提交完整计划快照；会话内显示可折叠的完成进度，刷新后恢复 | 仅投影主 Agent 成功的工具结果；最多 24 项，每项 1024 UTF-8 字节，总输入最多 12 KiB；快照保存在便携 Home 的会话 `todo.json`，读取缺省计划不创建 Home |
| 询问用户 | 会话绑定的 `ask_user` 工具等待用户回答；聊天区显示选项及自由输入，刷新后读取待答卡片 | 最多 16 个并发询问，每题最多 8 个选项；回答只作用于原会话且只能提交一次；取消、运行超时和进程关闭会清除在线待答；进程中断后的待执行工具由 xwork 会话恢复时安全重试并重新提问 |
| 用量 | 输入 token 估计、最近一次模型输入与上下文窗口比例 | 输入估计是近似值，模型用量取服务端记录 |
| 运行中输入 | 可继续输入、排队、删除待发消息；Ctrl+Enter 中断并优先发送；刷新后恢复队列 | 队列存于会话 `queue.json`；派发前先持久化 `sending`，刷新遇到不确定状态会暂停并提示核对，用户确认后才能重试；新一轮必须等服务端确认上一轮终止 |
| 模型、思考、权限 | 输入区直接选择；空闲会话先恢复上下文并验证配置，再原子更新元数据 | 活跃运行和待恢复调用不能切换；会话 schema 3 兼容旧 schema 1/2 |
| 回复排版 | 用 DOM 节点渲染标题、列表、代码、表格、引用和安全的 HTTP(S) 链接 | 不使用 `innerHTML` 插入模型输出 |
| 点赞、点踩 | 回复下方互斥切换；以成功的 `model_done.event_id` 为键保存到会话 `feedback.json` | 服务端验证事件归属；切换会话或刷新后重新读取；单文件模式无反馈时不创建 Home |
| 斜杠命令 | 输入 `/` 显示可键盘操作的命令菜单；新建、模型选择、分叉、清空、导出、停止和设置复用现有操作 | 清空与分叉仍走原有服务端会话操作和确认流程；未知命令仍可作为普通提示发送 |
| `@` 文件补全 | 输入 `@` 加文件名或路径片段，从当前会话工作区显示候选；方向键、回车、Esc 和点击可操作 | 服务端有界扫描并跳过子符号链接；仅插入相对路径文本，不读取或上传文件内容；无会话时不触发补全 |
| 会话内搜索 | 顶栏搜索按钮或 Ctrl+F 打开浮动搜索框；按文本过滤消息并显示命中数，Esc 关闭 | 只搜索时间线已加载的最近记录；出现记录截断时明确提示早期记录未载入。全量历史检索需独立的服务端索引 |
| 长对话导航 | 向上翻阅时显示“回到底部”，点击回到最新消息；位于底部时自动隐藏 | 依据对话容器的滚动位置判断，实时输出仅在用户保持底部时自动跟随 |
| 输入草稿 | 新任务与各会话分别存入便携 Home；刷新和切换会话恢复输入 | 服务端 revision 防止多窗口静默覆盖；保存失败保留页面输入并显示状态；快速离开使用 keepalive 请求 |

## 尚未迁移

- 图片粘贴、拖放、附件、全量历史检索、消息编辑/重试尚待迁移。旧版图片附件以 Data URL 传递；新架构运行入口目前仅接受文本，需先扩展 xwork 用户消息的多模态输入，不能只增加附件按钮。
- Markdown 渲染覆盖常用块和行内语法，尚未实现完整 CommonMark 嵌套规则。后续可在保持纯 DOM 安全边界的前提下扩展。
