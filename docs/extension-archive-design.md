# 扩展压缩包分发设计（待审阅）

状态：设计草案，尚未开发。本次仅撤回了未发布的 MCP JSON 内嵌目录实现；线上服务及 0.6.0 下载、自动更新保持现状。

## 目标与范围

九类扩展统一使用标准 ZIP 发布：Agent、SubAgent、Agent 工具、MCP、Skill、编辑器命令、外部工具、知识库、插件。每个作品独立分发；本次不增加组合包体系。

发布物是可被普通解压工具打开的真正压缩包。JSON 只记录元数据及配置；文件内容直接作为 ZIP 条目保存。上传、平台保存、下载均传输原始 ZIP 字节，不把 ZIP 或其中的文件 Base64 编码后塞进 JSON。

本机开发仍使用普通目录和文件。打包只发生在导出、分享或发布时；从商店下载安装的副本沿用现有的只读来源和管理规则。

## 统一结构

文件名示例：`example-1.0.0-windows-x86_64.mdo.zip`。扩展名保留 `.zip`，用户可以直接使用常见工具查看和打包。

```text
example-1.0.0-windows-x86_64.mdo.zip
├── manifest.json              # 格式、类别、标识、版本、平台、入口、许可、文件摘要
└── payload/                   # 作者所选目录的根，完整保留相对结构
    ├── mcp.json
    ├── bin/server.exe
    ├── lib/...
    ├── README.md
    └── LICENSE
```

包清单暂定格式名为 `mdo.extension.archive.v1`。`manifest.json` 中记录一个扩展类别、一个作品标识、显示信息、兼容声明及入口路径。文件目录只记录路径、大小、SHA-256 和必要权限，不包含文件内容。`payload/` 内可以保留原项目自己的 `manifest.json`，与外层包清单互不冲突。

根清单大小设独立上限；大文件列表可使用包内独立索引文件。相对目录、隐藏文件、空文件、空目录、二进制和文本文件都需支持，不能沿用旧附件数组的 128 个文件限制。

| 类别 | payload 中的内容 | 安装后交给现有能力 |
| --- | --- | --- |
| Agent / SubAgent | 配置、提示词、可选 C 入口及辅助文件 | 角色注册与现有 SDK |
| Agent 工具 | C 入口、头文件及辅助资源 | Agent 工具运行环境 |
| MCP | 服务配置、程序、依赖及可选解释器 | MCP 连接和 stdio 管理 |
| Skill | SKILL.md、脚本及参考资料 | Skill 发现和调用 |
| 编辑器命令 | C 入口及辅助文件 | 命令注册和 TCC 环境 |
| 外部工具 | 可执行文件、依赖、许可及命令映射 | 工具列表和现有转发器 |
| 知识库 | 索引、文档及相关资料 | 知识库注册和路径提示词 |
| 插件 | 插件描述、覆盖文件及可选加载入口 | 既有插件文件映射与生命周期 |

## MCP 目录如何工作

1. 作者从本机 MCP 条目发起分享，选择完整服务目录，填写作品元数据并查看文件清单。配置、程序和依赖一起打包，保留相对结构。
2. 同一作品可以提供不同平台的归档；客户端按平台和能力选择。解释器若一起分发，应在目录中提供；依赖系统解释器的情况需要显式声明，不假装完整自带运行环境。
3. 自带程序的相对启动路径和工作目录均以 `payload/` 为根；配置可使用 `{$path}` 表示这个目录。只在明确的路径字段展开，用户输入和秘密值不参与隐式替换。
4. 个人凭据、OAuth token、设备连接实例和会话不从 mdo 私有存储导出。公开配置保留参数声明，安装设备单独填写。打包前应让作者确认所选目录的文件清单，避免把目录内的私人文件一起公开。
5. 安装只校验、解压和登记。平台审核、浏览器预览及客户端安装阶段都不运行服务、不执行安装脚本，也不自动执行 npm/pip 下载依赖。
6. stdio 启动沿用明确的程序信任确认。Android 保留完整版预制原生程序的限制；可分发配置、文档和由 APK 内解释器运行的脚本，不能把下载 ELF 当作任意可执行程序启动。

## 客户端、平台和创作中心共用的链路

```text
选择本机目录 → 生成 ZIP → 原始二进制上传 → 校验和私有保存
                                      ↓
                               申请公开、提交审核资料
                                      ↓
                                  管理员审核
                                      ↓
商店目录 → 下载 ZIP → 摘要校验 → 临时解包与完整校验 → 原子安装
```

- 上传控制接口使用小 JSON 创建任务；文件分片使用二进制请求体和偏移，不使用 JSON/Base64。任务支持查询进度、取消、断点恢复；最终按总大小和包摘要封存。
- 平台按 ZIP 原始字节的 SHA-256 保存不可变对象。目录、作者、审核和版本记录与对象分离，禁止作者自报平台提交者身份。
- 创作中心支持 mdo 直接分享和网页选择 `.mdo.zip`。沿用现有的私有稿、公开申请、审核、更新、下架、删除和容量申请流程。
- 审核资料仍可作为单独的私有附件，不因位于审核流程而自动进入公开安装包。现有每版本容量和作品数量规则沿用。
- 后台、创作中心和客户端详情先读小元数据，再按需读取文件列表、文本预览或原始文件。大包详情不能依赖把整包放进接口响应；文本预览需要有大小上限。
- 包的读取和校验应采用目录索引、流式读取与逐文件哈希，避免把所有文件解压到一个巨大的 xvalue/JSON 对象。平台不得为审核执行作者的程序。
- 下载、扩展安装及更新共用现有全局下载任务入口，保留当前统一列表、分页、弹窗和底栏范式。

## 安装、更新和文件管理

- 使用不可变版本目录，例如 `data/extensions/<kind>/<work-id>/<archive-sha256>/payload/`，注册时核对平台返回的作品归属和版本。
- MCP 连接固定绑定整个归档修订，程序或依赖变动也会改变修订。不能只按 mcp.json 的哈希区分版本。
- 安装先在任务临时目录完成校验，成功后原子切换登记。失败或取消清理本次任务文件，保留原版本。
- 更新保留设备参数和凭据。正在运行的进程继续引用原修订，明确重连时使用新修订；启动确认与实际文件摘要绑定。
- 卸载只清理本扩展拥有、且没有连接或进程继续引用的文件；设备连接、凭据与用户私有数据的处理沿用现有显式选项，不被服务器下架动作远程删除。
- 本机路径由当前 Home 和包目录计算，不在归档或设备绑定中固化作者机器的绝对路径，保持绿色迁移能力。

## 归档校验

统一支持标准 ZIP 的 Store 和 Deflate，初版不支持加密归档、分卷归档和嵌套归档自动展开。利用现有压缩、文件和摘要接口提供共用实现，不要求用户额外安装 zip/unzip、Python 或其他工具。

平台和客户端共享同一套限制及路径规则，包括路径穿越、绝对路径、驱动器路径、Windows 保留名称、文件/目录前缀冲突、Unicode 文件名冲突、重名、权限及条目类型。客户端还要按目标文件系统独占创建、复核真实落盘路径，不能仅靠 ASCII 小写比较。

发布归档不允许符号链接、硬链接或特殊文件落盘。打包器可以将指向所选目录内部的链接展开为真实内容，越出目录的链接列为打包错误；应检测环路并将展开后的文件计入限制。

压缩包大小沿用账户容量；解压后的总量、单文件大小、文件数及目录深度分别限制。初始建议为解压总量 512 MiB、单文件 128 MiB、最多 50,000 个条目；这些是待审阅参数，需用实际 MCP 依赖目录验证后定稿。逐文件校验声明大小、CRC、SHA-256 和权限，不允许额外未登记条目、截断数据或超限解压。

## 旧格式过渡和实施顺序

当前其他扩展也存在 JSON 文件内嵌或自定义二进制封装，不能仅给 MCP 的 JSON 外面再套一层 ZIP。新增统一归档层和类型适配器，逐类替换发布、审核、下载及安装链路；应用本地配置格式不随发布格式强行改变。

1. 先完成共用 ZIP 规范、读取/写入、目录清单和校验接口设计，审阅通过后实现。
2. 用 MCP 跑通本机目录发布、二进制上传、审核、商店下载、解压、实际启动、更新与卸载。
3. 将其余八类扩展接入同一归档层，撤掉重复的内嵌文件分发路径。
4. 新版只展示、发布和安装 ZIP 作品。旧作品原件及审核记录保留；旧客户端所需只读兼容通道与新通道分开。旧作品转为 ZIP 会得到新的包摘要，须有明确转换记录及审核，不能覆盖原版本对象或伪造原摘要。
5. 客户端能力协商、平台接口、创作中心和后台同时验收后，再安排线上发布和客户端更新。本设计未分配新版本号或发布构建号。

## 验收目标（尚未执行）

- 标准 ZIP 工具互操作；单个大二进制、多层依赖、超过 1024 个文件、隐藏/空文件及空目录可以完整往返。
- 压缩包传输过程中和磁盘上均为真实 ZIP，所有 JSON 响应只含元数据；审核和安装得到相同的文件及摘要。
- 路径、Unicode 冲突、链接、重复条目、压缩炸弹、截断、错误摘要和目录外引用均被拒绝。
- Windows 和 Linux 的自带 MCP 程序完成启动、协议通信、停止、更新和引用回收；测试不依赖真实模型供应商。
- Android 验证现有平台限制及脚本路径，不通过降低系统安全限制运行下载的原生程序。
- 其他八类的分享、审核、安装、信任确认、更新及卸载不回归；安装失败、取消和重启恢复不损坏原版本及用户数据。
- 大包的客户端详情、创作中心和后台都能正常打开，凭据不进入任何归档、元数据、审核展示或日志。
